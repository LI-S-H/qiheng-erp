## 分析任务中断恢复（待设计和验证）

- 当前独立 AnalysisAgent 未配置检查点，任务与 Python 沙箱在本次调用结束时关闭，暂不支持中断后继续执行。
- 后续接入主智能体时，需基于项目实际使用的 Spring AI Alibaba 版本验证父智能体按需调用子智能体后，子任务检查点、身份上下文、任务标识及结果交接的恢复行为；不能假设配置 RedisSaver 后自动恢复。
- 需要覆盖模型调用前后、工具调用前后和 Python 执行中断，以及服务重启、沙箱仍在或已丢失等情况。沙箱已丢失时，应验证重新创建环境、重新准备已授权数据与处理未确认执行结果的方式。
- 需要区分图状态恢复与沙箱文件、运行中进程、已保存结果的生命周期，确认重复执行和结果交接的处理方式；本条为待设计事项，不代表恢复能力已经实现。

## 异常退出的沙箱保留与回收（待设计和验证）

- 真实测试中，强制终止 Java 进程后，其 Python 沙箱容器仍存在且运行；测试随后清理了该测试容器。
- 正常任务继续先保存结果再关闭沙箱；异常失联的沙箱建议先保留，初始保护期暂定可配置的 1 小时，从最后一次有效任务活跃记录失效后计时，而不是仅按上次 Python 执行时间判断。
- 后续应在进程外记录任务、沙箱、所属实例和活跃状态，并验证依赖是否支持可靠标记、识别和重连已有沙箱；不能仅按容器名称批量删除。
- 回收前重新确认任务未被其他实例接管；状态无法确认时先保留并记录，避免误删运行或恢复中的任务。多实例、网络分区、接管与回收竞争都需要测试。
- 保留容器只保留恢复的可能性；当前分析图检查点、任务与沙箱重连均未实现，Python 普通变量也不会跨执行进程保留。保护期结束回收后，未回传的沙箱文件会丢失。
