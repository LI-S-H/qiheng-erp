# AI 助手待排查问题

## 分析任务中断后的重新发起

- 分析智能体已接入主智能体；每次工具调用创建独立分析任务，正常结束时关闭沙箱。不恢复旧分析线程、Python 进程或旧沙箱。
- 用户再次发送消息后，主智能体对检查点中未完成的工具调用补充 `INTERRUPTED` 结果，结合新消息决定是否重新调用分析工具，不保证自动重跑。
- 待验证：真实进程中断后再次调用的端到端行为，以及旧任务未完成交接时，已保存的分析文件是否能通过任务 ID 发现；尚未回传的沙箱文件无法按已保存结果使用。

## 异常退出的沙箱回收（已实现，边界待验证）

- 当前按单实例实现：实际创建的容器逐个登记 Redis，分析过程更新活动时间；本进程运行中的任务由内存集合保护。
- 任务正常结束先关闭沙箱，再确认容器删除；失败保留登记。定时任务默认每五分钟清理超过一小时未活动且不在本进程运行列表中的已登记容器。
- 已验证新进程视角读取 Redis 登记并清理真实容器；尚未覆盖容器创建成功、登记 Redis 前进程崩溃的窗口。当前依赖未确认可设置可靠容器标签，不能按名称批量删除。
- 方案不支持多实例共享沙箱登记：各实例的内存运行列表互不相通，部署多实例前需重新设计跨实例保护。分析中断后由主智能体根据后续输入重新调用，不恢复旧沙箱。
