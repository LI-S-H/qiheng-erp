# 后端开发规范

本规范适用于 `erp-server/`。Java、Spring Boot 及各模块依赖以根 POM 和模块 POM 为准；模块职责见[总体架构](architecture/overview.md)，精简入口见[后端开发](development/backend.md)。

## 业务与分层

- Controller 接收请求、进行参数与权限校验并调用业务服务；Service 负责业务规则、状态、事务和协作；Mapper 负责数据库访问。具体目录和依赖以现有模块代码为准。
- 跨模块处理复用现有服务与接口，采购、销售、退货和仓储不得通过绕过服务直接改库存、状态或金额。
- 订单、出入库和退货的状态流转、并发、幂等、审计字段和处理数量应参考对应服务及状态枚举；修改后核对调用方和测试。
- 编码、金额与数量沿用现有服务及[数据库约定](database/database-design-conventions.md)，已发生交易使用对应业务快照，不以当前主数据替代历史事实。

## 数据与接口

- 表、字段、默认值和索引见[数据库结构](database/schema/README.md)，业务关联见[数据关系](database/relations.md)。结构导出没有声明物理外键，业务必须处理关联完整性。
- 对外接口、错误处理、分页和权限同时核对当前 Controller、DTO、[OpenAPI](api/erp-openapi.yaml)及前端调用。BIGINT 标识按现有接口字符串约定传输。
- 写入按业务边界使用事务、权限与审计；涉及 Redis、消息队列和数据库的跨系统操作，不能假定它们是同一数据库事务。
- 数据库变更同时考虑空库初始化、现有库升级、数据兼容与备份；演示数据不能代替业务接口校验。

## AI 与敏感信息

现有 AI 代码包含经过权限、范围、SQL 守卫和只读执行器约束的取数路径，并非所有读取都通过业务 Service。业务写入应继续走授权的业务流程和必要确认；具体能力与验证边界见 [AI 架构](architecture/ai.md)。

测试及部署使用隔离环境，不记录真实凭据或个人数据；初始化中的测试账号仅用于演示。

## 验证

根据影响范围运行 Maven 测试、接口契约检查及隔离环境集成测试。只编译或跳过测试不表示业务通过；记录执行版本、依赖和失败项目。测试入口见[测试资料](testing/README.md)。
