# 演示数据生成器 v2

本目录用固定随机种子生成一套可用于演示采购、销售、库存、退货和供应商评分的业务数据。生成结果不依赖当前数据库中的旧交易数据，只沿用商品/分类映射与主数据 ID 段。

输出中的 `product.reference_purchase_price` 和 `reference_sale_price` 按分写入（`bigint`），与交易金额同一口径；2026-11-22 之前生成的旧包是元口径，不能混用。

## 运行

在 `erp-server` 同级项目根目录执行：

```powershell
cd docs/database/demo-data/generator
python generate_demo_data.py
```

输出到 `out/`：

| 文件 | 说明 |
|---|---|
| `demo-data-v2.sql` | 完整演示数据，导入空库即可 |
| `master-data-v2.sql` | 仅主数据，便于单独检查 |
| `verify-data-v2.sql` | 86 项业务规则检查，第二列为 0 表示通过 |
| `stats-v2.txt` | 数据规模与分布统计 |

## 输入

| 文件 | 来源 | 用途 |
|---|---|---|
| `categories.tsv` | 当前库 `product_category` 导出 | 126 个分类（22 个上级、104 个下级），保留原分类层级 |
| `products.tsv` | 当前库 `product` 导出 | 保留 1560 个商品 ID、编码和分类映射 |

商品名称、品牌、规格、参考价、安全库存全部重新生成；供应商、客户、仓库也重新生成，名称按真实业务形态构造，不再使用"演示区域仓 01""华源供应链 001 号"之类的编号名。

## 数据设计

### 主数据

- 仓库 5 个：上海浦东中心仓、广州白云分拨仓、北京顺义北仓、成都双流西仓、武汉江夏南仓，按区域权重分配商品，期末库存量不等。
- 供应商 200 家：按品类专长分组，分优质（20%）、普通（60%）、尾部（20%）三档；尾部供应商交期长、准时率低、次品率高。
- 客户 200 家：连锁超市、便利店、餐饮、电商、社区团购、酒店，信用额度分 5 万至 100 万。
- 商品 1560 个：品牌 × 品名 × 规格组合，规格与品类匹配（如牛奶 250ml×12 盒、大米 5kg/袋），参考价按品类区间分散，毛利率 8%–65%，安全库存按品类分档。

### 供货关系

- 约 72% 商品单源，20% 双源，8% 三源；446 个商品有第二供应商。
- 备选供应商分低成本型（价格低 6%–14%、交期长、质量低）和优质型（价格高 4%–14%、交期短）。
- 约 45% 的第二源无采购历史，评分状态保持 `NOT_READY`，用于演示样本不足。
- 报价按分存储，报价有效期部分已过期，起订量分 1–200 件多档。

### 交易

- 时间窗口 2025-11-01 至 2026-11-21，按月份季节系数生成旺淡季（2 月低谷，3/6/9/11/12 月旺季）。
- 采购单约 6000 张：状态覆盖 `DRAFT`、`SUBMITTED`、`APPROVED`、`PARTIAL_INBOUND`、`INBOUND_DONE`、`CANCELLED`；约 50% 为多行明细；约 8%–15% 的已完成单实际到货晚于承诺日，形成交付分梯度。
- 销售单约 6700 张：按客户购物篮生成，约 50% 为多行明细；状态覆盖 `DRAFT`、`SUBMITTED`、`APPROVED`、`PARTIAL_OUTBOUND`、`OUTBOUND_DONE`、`CANCELLED`。
- 价格按普通客户、大客户、促销三档折扣生成，销售单价普遍低于参考售价。
- 退货单约 360 张：采购退货和销售退货各占一半，状态覆盖草稿、待审核、已审核、部分执行、已完成、已取消；已执行的退货生成对应出入库单和库存流水。

### 库存

- 期初库存通过每仓一张 `ADJUST_IN` 盘点入库单建账。
- 按月需求驱动补货，采购到货时间早于出库时间，库存不出现负数。
- 约 11% 商品期末零库存、5% 低于安全库存、20% 高于两个月销量；约 490 个商品跨仓存放，并生成成对的调拨出/入库单。
- 期末 `warehouse_stock.locked_qty` 等于未完成销售单锁定量与未执行采购退货锁定量之和。

### 评分

- 先造采购、入库、质检事实，再按系统公式计算：
  - 交付分 `max(0, 10000 × (1 - 罚额 / 应交金额))`，逾期系数 25%/50%/75%/100%。
  - 质量分 `合格金额 / (合格金额 + 不合格金额) × 10000`。
  - 价格分 `min(10000, 参考采购价（分） × 10000 / 报价（分）)`。
  - 推荐分 = 价格分×0.3 + 交付分×0.3 + 质量分×0.3 + 服务分×0.1。
  - 综合分按同一权重汇总供应商级价格分、交付分、质量分、服务分。
- 任一维度缺失时评分状态为 `NOT_READY`，约 43 家供应商保持样本不足。

## 验证方法

1. 建隔离库，依次导入 `docs/database/init/01-schema.sql`、`02-system-demo.sql`、`out/demo-data-v2.sql`。
2. 执行 `out/verify-data-v2.sql`，86 项检查应全部为 0。
3. 可选：将后端连接到隔离库，执行真实的提交、审核、入库确认、出库确认流程。

2026-11-22 已在隔离库 `erp_demo_v2` 完成导入并通过 86 项检查；后端冒烟验证通过采购单提交/审核/入库确认、销售单提交/审核/出库确认、退货提交和库存余额复核。

## 注意

- 金额口径统一按分：商品参考价、交易单价和金额都写 `bigint` 分，数量统一 ×100。
- 固定随机种子为 `20261122`，同一份输入重复生成结果一致。
- 生成器不会清理目标库已有数据；导入前必须确认目标是空库或已按需清空，避免主键和单号冲突。
