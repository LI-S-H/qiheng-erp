# Docker 部署

仓库当前的自动部署实现位于 `deploy/docker/`，基础服务和应用由独立 Compose 项目管理。完整的脚本参数、镜像准备、初始化及故障处理以 [Docker 部署原说明](../../deploy/docker/README.md)和 `deploy.sh` 为准；运行前根据目标环境审查配置，不在共享文档记录真实地址或凭据。

## 首次部署顺序

1. 准备目标机器、Docker、Compose、仓库读取权限和镜像来源，核对部署目录及受控的私有配置。
2. 使用部署脚本 `init` 初始化配置；确认私有配置完整，再运行 `check-source`、`pull-images` 和 `infra-up`。当前脚本通过配置的 GitCode 仓库获取发布版本；不要将访问令牌放进仓库地址或命令参数。
3. 准备经过核对且适合目标环境的数据库 SQL。[空测试库初始化文件](../database/init/README.md)已在隔离环境验证，但包含仅供测试的账号，生产环境须另行设计账号数据。`import-db` 用于空业务库；既有库升级另行制定方案。
4. 使用 `deploy` 构建并启动应用，检查状态和日志，再执行隔离环境适用的业务验收；健康检查不能替代业务测试。
5. 需要自动发布时，先确认发布源、权限、备份和回退方式，再配置定时调用。普通应用发布不自动执行数据库迁移。

## 数据与运维

- AI 业务技能从外部目录加载，不打包在 JAR 中。当前服务器运行镜像工作目录为 `/app`，默认技能路径为 `/app/skills`；现有 Dockerfile 和 Compose 未提供该目录的技能文件或挂载，也未显式传入 `ERP_AI_SKILLS_DIR`。启用 AI 时可通过 Compose 覆盖配置向容器提供可读取的外部技能目录；若使用非默认路径，还需在容器环境中设置 `ERP_AI_SKILLS_DIR`。核对文件权限及加载日志，具体机制见 [AI 架构](../architecture/ai.md#业务技能加载与扩展)。该部署路径尚需在目标环境验证。

- MySQL、Redis、MQ 及 AI 文件使用相应持久化卷；在计划窗口内执行备份、恢复演练和版本记录。容器或镜像回退不会回退数据库。
- 使用脚本提供的 `status`、`logs`、`pause`、`resume`、`retry`、`rollback` 管理发布；先核实现有服务状态，不通过删除持久化卷解决启动问题。
- Docker Socket 用于当前 AI 沙箱管理，赋予后端较高宿主机权限；仅在经过授权和风险评估的环境启用，具体以部署原说明及实际配置为准。
- 排查或分享日志时先清除令牌、密码、联系方式和业务数据，不粘贴完整私有配置。
