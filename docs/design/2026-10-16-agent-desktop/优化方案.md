# 云仓 ERP 桌面工作区优化方案

日期：2026-10-16。交付范围：当前前端审阅、统一布局与视觉提案、可点击交互原型、实施顺序与后端边界。用户已选择浅色、克制、适合长期办公的方向。

## 结论

建议采用 **稳定的浅色导航 + 中央业务工作区 + 按需展开的右侧画布**。业务表格保留 ERP 的操作效率；AI 借鉴桌面智能体的对话、澄清和产物并排模式。优先改布局、密度和信息层级，再优化字体资源与细节，最后扩展真正的 AI 执行能力。

本方案以独立原型呈现，尚未应用到生产页面。现有 `docs/frontend-style-guide.md` 规定深色应用壳，正式实施浅色壳前需先同步这份规范。保留云仓名称、Logo、蓝色主色、既有业务状态机、字段契约和权限裁剪。

**演示入口**：运行本目录 `node serve.cjs`，打开 <http://127.0.0.1:5188/docs/design/2026-10-16-agent-desktop/>。默认工作台；侧栏可进入智能助手、采购、库存、方案画布和设计规范。所有数字为示例，原型不请求业务接口、不修改数据库。

## 推荐布局

### 统一应用壳

- 侧栏默认 232px：品牌、页面导航、最近会话、底部账号。只有 AI 页面展示会话分组；一级业务导航位置保持稳定。
- 顶栏 56px：面包屑、页面定位、按需画布开关、待处理事项与账号。顶栏不再重复一个大标题。
- 业务区水平内边距 24–32px，垂直 24px。工作台阅读宽度受控，数据表使用剩余宽度。
- AI 正文列约 620–760px；消息 15px/1.8，输入框与阅读列对齐，固定在当前会话底部，保留换行与提交提示。
- 右侧计划画布默认 360–400px，可收起。只在需要核对计划/依据时占位；业务表格不常驻挤压一栏。

| 视口 | 导航 | 中央内容 | 右侧画布 |
| --- | --- | --- | --- |
| ≥1440px | 232px | 弹性填充；AI 有阅读上限 | 用户打开时并排 360px |
| 1280–1439px | 默认 232px，可收起 | 表格优先宽度；降低辅助信息密度 | 仅空间足够时并排，否则抽屉 |
| 768–1279px | 可收起/抽屉 | 单主工作区 | 抽屉，不压缩表格 |
| <768px | 带文字的菜单入口 | 单列、筛选可折叠 | 全宽抽屉，标题与关闭动作固定 |

断点以内容最小宽度为最终依据，不机械套用数字。原型采用 <1280px 计划抽屉，可直接体验。

### 工作台

先展示四项关键指标的单条摘要，然后是今日待办与库存风险。待办优先级由现有后端口径决定，前端不重新发明风险分数。经营趋势、商品排行、供应商履约保留为次级分析区；不要因为首屏简化就删掉信息。

待办仍按 `todoId` 定位详情，再进入对应业务页。通知数字表示待处理事项，不等同未读；打开通知不清零。

### 采购 / 销售 / 仓储列表

标题与说明 → 紧凑摘要 → 2–4 个高频筛选 + 更多筛选 → 表格工具栏 / 数据 / 分页。每个筛选有明确字段；展开更多后保留已生效条件及清除入口。新增仍放表格工具栏，遵循现有规范。

采购保留单号、往来方、仓库、状态、金额、预计到货、操作为第一层；创建人和精细更新时间可放列设置或详情。列显隐只改变展示，不能删接口字段。状态文案与正式枚举保持映射，不把只读状态改成任意下拉。

宽表允许**容器内**横滚，固定单号和操作列。只读详情可使用右侧详情区；长单据、长表单和复杂编辑继续使用宽对话框/独立页，以实际内容决定，避免窄抽屉容纳完整订单编辑。

摘要必须继续标“本页”或使用真正全量聚合接口，不能把当前页派生统计改名成“全部”。库存列表维持无精确总数分页的既有能力。

### AI：从问题到可核对计划

原型路径：工作台 / 库存 → 制定分析计划 → 输入目标 → 确认时间和仓库 → 生成计划 → 右画布查看步骤 / 依据 → 导出 Markdown。

状态文案区分：准备就绪、等待补充、规划中、计划已生成、失败可重试。`PLAN_READY` 展示“计划已生成”，不展示“分析已完成”。SQL 查询和 Python 分析在画布里写为拟执行步骤。

**用户确认的对话细节**：用户消息靠右并带气泡，AI 回复靠左。用户气泡采用低饱和蓝色浅底、深色正文，最大宽度为消息区的 75% 且不超过约 560px；短句不拉满，长文本与连续字符均自动换行。头像和角色标识跟随各自方向，避免用户与 AI 的消息混为同一条阅读流。时间等辅助信息保持可读，在窄屏上不通过缩小字体来塞内容。澄清表单与计划属于 AI 消息，继续放在左侧。

当前已有会话、历史、草稿恢复与进度 SSE，应完整保留。右画布负责结构化计划，会话正文负责问题与解释，减少同一段计划两处全文重复。

### 产品 / 系统 / 登录

- 产品：编码、名称、分类与状态优先；品牌/条码进入更多筛选；分类标签统一中性，保留多选及操作权限。
- 系统：角色名称、状态与作用范围清楚；批量动作只在选中后出现；权限页保持可追溯的业务权限码。
- 登录：保留现有品牌和输入结构；浅色壳与登录自然衔接；生产环境是否展示演示账号由环境约束明确决定。
- 各模块均需空、加载、错误、无权限状态；后台刷新保留已有内容并标旧数据，不能显示假零值。

## 字体与视觉规范提案

保留 HarmonyOS Sans SC，系统回退沿用当前链路。正文 400、控件 500、标题 600。现有 Semibold 文件只对应真实 600；是否新增 700 需核对真实字体，避免一个文件被声明成多个不匹配字重。数值使用 `tabular-nums`，不为“科技感”全站使用等宽字体。

| 元素 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 页面标题 | 24 / 32px | 600 |
| 分区标题 | 16 / 24px | 600 |
| 业务正文、输入、表格 | 14 / 22px | 400 |
| AI 阅读正文 | 15 / 27px | 400 |
| 导航、按钮 | 13–14 / 20px | 500 |
| 辅助说明、时间 | 12 / 18px，重要字段不缩小 | 400 |
| 关键数字 | 26–28 / 34px | 600 |

| Token | 建议值 | 用法 |
| --- | --- | --- |
| 主工作底色 | `#F7F8FA` | 单一浅色底 |
| 内容表面 | `#FFFFFF` | 表格/画布/输入 |
| 浅导航 | `#F3F4F6` | 稳定、低对比边界 |
| 正文 | `#20242C` | 核心内容 |
| 次要文字 | `#626873` | 说明，不以低透明度替代 |
| 主色 | `#315DCE` | 主操作、链接、选中 |
| 主色浅底 | `#EDF2FF` | 当前导航、轻量选中 |
| 结构边框 | `#E3E6EB` | 非交互分隔；输入轮廓另保证可辨识 |
| 成功 | `#236849` / `#EDF7F1` | 文字 + 状态名称 |
| 提醒 | `#875514` / `#FFF5E5` | 待关注，不整页橙色 |
| 风险 | `#B33E45` / `#FFF0F1` | 阻塞、高风险、危险动作 |

间距采用 4/8/12/16/24/32；输入 36px，触摸目标至少 44px；表格标准行高 52px、紧凑 44px。按钮/输入圆角 6–8px，主容器 10–12px。分隔优先于阴影；去掉每块卡片顶部彩线和无语义彩点。

动效 140–180ms，仅用于展开、切换和反馈，尊重 `prefers-reduced-motion`。Tab 焦点必须可见，抽屉打开后聚焦其中、Esc 关闭并返回触发点，遮罩禁止点击穿透。对比度需依据最终 token 和实际文字状态测试，截图不能证明完整 WCAG 合规。

## 后端是否需要改

**第一阶段统一布局、字体、配色与交互层级，原则上无需改后端。** 真正执行分析、产物持久化等属于后续能力，不能借视觉改造默认扩建。

| 提议 | 当前依据 | 后端结论 |
| --- | --- | --- |
| 浅色壳、字体、密度、固定表格列、响应式抽屉 | 现有页面和公共组件 | 不需要，前端与规范同步 |
| 工作台重排、待办/通知入口 | 现有 overview、inventory-status、todoId、access 权限模型 | 通常复用；若新增统计口径/时间范围才扩聚合接口 |
| 原型中的采购“较昨日减少”、预计今日到货笔数、最近动态 | 固定示例，当前 overview 未直接提供这些完整口径 | **需要额外聚合/事件来源或相关接口评估**；首版建议直接使用现有四项 DashboardMetric 和现有待办 count，去掉没有来源的对比与动态，不由前端猜算 |
| 折叠更多筛选、明确参数、列显隐 | 已有业务 list API | 不需要；新筛选字段必须先确认现有参数，缺失时扩 OpenAPI |
| 命令菜单只跳页面 | 现有路由与菜单权限 | 不需要；按当前用户权限裁剪 |
| 全局跨实体搜索 | 不能用模糊 keyword 代替明确字段 | 如要建设需单独搜索设计、权限与可检索字段契约；本轮不实现 |
| AI 会话、澄清、计划画布 | `/ai/assistant/*`、`/ai/graph/stream`、`/ai/graph/resume/stream` | 复用现有接口；UI 不改变 `checkpointId` 等恢复语义 |
| 从业务页把单号/范围预填为文本 | 现有 query 接收文本 | 前端可做；只带已授权的最小上下文，不传整个表/敏感数据 |
| 可靠的结构化业务上下文与附件 | 当前请求主要为 conversationId/query 或 thread/checkpoint/answer | 新增实体引用/附件前需后端校验归属、权限、版本与大小 |
| 本地导出计划 Markdown | 当前 Plan 结构 | 前端可做；本轮演示已实现本地导出 |
| 真正执行 SQL/Python、完整报告/结果画布 | 当前 Plan 为 SQL_QUERY/PYTHON_ANALYSIS 描述，停在 PLAN_READY | **需要后端扩展**：只读数据访问、权限裁剪、执行隔离、超时取消、运行状态、结果 schema、来源与时间 |
| 保存报告、历史版本、跨设备产物 | 当前会话消息可存计划，不等于完整产物库 | **需要评估新增持久化模型/API**，区分会话与产物生命周期 |
| 定时经营任务 | API 适配层主动抛“经营任务暂未开放”，路由重定向 | **需要后端调度与执行闭环**；OpenAPI 有路径不代表功能已经开放 |
| AI 生成采购草稿/审核写操作 | 当前仅需求规划 | **需要独立后端方案**：人审确认、幂等、事务、权限、审计，不能由聊天直接绕过正式业务接口 |
| 跨设备保存导航/列宽/密度偏好 | 当前本地即可展示 | 单设备 localStorage 可做；跨设备时再加用户偏好接口 |
| 工作空间切换 | 原型弹窗仅说明位置，未接组织列表 | 若真正建设多组织切换，需后端组织授权、数据隔离与会话范围设计；不算纯样式改动 |

以上扩展是建议边界，不是本次已修改项。本轮没有修改后端、数据库或 OpenAPI。

原型首页指标用于展示层级，不是一套新增统计接口的默认承诺。其“本月销售额”可对接现有销售指标；采购待审核/待入库的数量应按现有待办实际可见数据映射。首版不具备完整口径时改用现有“本月销售额 / 本月毛利额 / 待处理订单 / 库存风险 SKU”，保留统一布局即可。
