# 云仓 ERP 外观风格探索

日期：2026-10-18。阶段：设计方案比较，尚未应用到业务前端。

> 本页及 REDESIGN.md 均为历史探索。用户明确指定 10 月 16 日演示的简约风格后，已停止图像发散，最新交付请查看 [简约网页预览](../2026-10-18-minimal/README.md)。

## 目标与边界

以简约、简洁、美观、适合长时间处理业务为目标。保留现有菜单、页面信息、统计口径、筛选条件、表格字段、按钮文案、权限和业务流程；仅探索应用壳、配色、排版、间距、边框、圆角、图标与状态样式。不得为了让画面干净而删字段、藏操作或添加新的统计卡片。

## 视觉方向

三种概念使用相同采购页截图作为图像参考，保持原有信息架构。差异集中在外观，不能用删减业务内容制造差异。

| 方向 | 工作区 / 侧栏 / 主色 | 感受与取舍 |
| --- | --- | --- |
| 清爽浅色（推荐） | #F5F7FA / #F7F8FA / #2F6BFF | 整体明亮，低视觉负担，最符合简洁美观与日常办公目标 |
| 石墨专业 | #F4F5F6 / #20252B / #0F62FE | 保留深侧栏的定位感，白顶栏减轻压迫，适合希望延续现有后台气质的情况 |
| 柔和青灰 | #F5F6F4 / #F1F4F2 / #23746D | 浅色中性底与低饱和青色，气质温和；如选用需单独区分主操作色与成功状态色 |

## 建议统一的外观规则

概念图按聊天中展示的顺序：

1. [清爽浅色](concept-light.png)
2. [石墨专业](concept-graphite.png)
3. [柔和青灰](concept-sage.png)

三张图由内置 Image Gen 分别生成，实际画布为 1487 × 1058，接近要求的 1440 × 1024 比例。它们是原采购订单截图的外观变体，不是已经实现的页面。生成要求包含本文件的业务边界、各方向配色、完整九列表格和原始历史数据保持约束。

- 保留现有 HarmonyOS Sans SC 字体。正文与表格约 14px，标题约 24px，主要使用 400、500、600 三档字重；编号和金额使用等宽数字。
- 主色集中用于主按钮、当前导航和焦点；绿色、黄色、红色仅表达业务状态，状态标签同时保留文字。
- 移除汇总卡片中无必要的四色顶线和圆点，以文字、数值、间距与细分隔建立层次。
- 采用 4–8px 的克制圆角，普通容器使用细边框，浮层才使用轻阴影；避免大圆角、强渐变和装饰性大卡片。
- 查询控件保持现有字段、顺序和行为，统一高度与标签基线。按钮保留现有位置和文案，通过填充、边框、文字区分层级。
- 表格保留全部列与横向滚动；优先改善列内排版、行分隔、表头对比度和状态标签，不通过缩小字号或隐藏列适配。
- 工作台、库存、采购、销售、系统权限和 AI 助手共用基础 token；具体内容和操作流程不随换肤变化。

## 概念图的使用限制

图像生成用于判断风格，不能作为字段、数字和文字的准确性证明。若概念图出现汉字、金额或控件细节误差，以原截图、文字快照和现有业务组件为准。实际落地时仅修改样式和必要的样式类，不依据生成图重建业务内容。

本阶段没有修改 `erp-web/`、接口契约或现行前端规范，因此不涉及业务构建与契约回归。用户选定方向后，开始前端编辑前需执行并阅读 `npm run preflight:frontend -- shared`；若修改具体模块，还需包含相应 scope，并在完成后执行项目要求的契约、构建和浏览器检查。
