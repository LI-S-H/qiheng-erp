## 设计判断

问题不只在颜色，而在页面由多层相似卡片拼接、统计区空间使用低效、表格主次信息与对齐不清楚、状态标签过小、按钮缺少统一层级。保持业务内容不等于保持原有布局。允许重新组织容器、移动现有操作和调整信息的视觉顺序；菜单分组、字段含义、查询行为、统计口径、权限与状态流转保持原样。

建议以“精密工作表”为主要方向，采用连续白色工作区、紧凑指标带、扁平筛选工具栏、按业务类型对齐的表格和可辨识的图形状态。另提供“业务工作台”和“清晰协作台”作对照，区别在组件结构和工作区组织，不以更换蓝/绿/紫区分。

实际生成图为 1448 × 1086（4:3）。独立视觉审查确认组件重设计成立。概念图仍存在已知误差：仅画出 7 行却沿用每页 10 条页脚，局部汉字或编码可能失真；第一张页面内查询按钮为实心蓝色，而下方组件区为描边；第一张待审核与部分入库颜色也不完全符合本文的推荐状态表。正式实现应统一采用本文件的组件规则和原内容快照，不能直接照图重建数据或混用两种按钮规范。本轮未执行真实交互与业务回归验收。

## 全站组件修改清单

以下规则以推荐方向为基线。数值是设计目标，实际落地需结合现有组件及真实浏览器测量。

| 元素 | 当前问题 | 完整修改方案 |
| --- | --- | --- |
| 应用导航 | 深色壳体占据较强视觉比重，一级二级同样偏重 | 浅中性侧栏、统一细线图标、常规字重；二级通过缩进和树线关联；选中项使用紧凑矩形底和小标记；保留全部菜单、分组与权限 |
| 顶部区域 | 模块、页面标题与正文标题重复争夺注意 | 顶栏采用轻量面包屑，页面主体保留唯一视觉主标题；角色和通知入口保持可见，不减少功能 |
| 页面标题与操作 | 业务说明和后续动作关联不清 | 标题、说明形成一组；现有新增按钮可移至标题右侧；不增加快捷操作 |
| 指标汇总 | 四个独立大卡、彩色顶线和圆点，空间使用低效 | 变为一条非交互指标带，标签与数值成组、细分隔线区分；保留标签、值和口径，不做可点击筛选标签 |
| 筛选容器 | 独立大卡与列表脱节，额外占用高度 | 推荐采用列表前的扁平查询工具栏；其他对照可采用连续筛选带或与表格合一的工作容器；所有已有筛选可见 |
| 输入框 | 普通描边框重复排列，层级与状态不统一 | 34–36px 高，6px 圆角，轻填充；标签持续可见；focus 有清楚描边，错误紧邻字段，禁用态可辨认；保留原校验和输入格式 |
| 下拉与远程选择 | 箭头、触发器和输入框缺少共同语言 | 触发器与输入框统一高度、内边距、圆角；选项使用一致行高、选中标记、悬停和键盘焦点；保留现有搜索、清空与取值行为 |
| 主按钮 | 多处实心按钮竞争视觉权重 | 以新增、保存、确认等为主要填充样式；推荐方向使用炭黑主按钮，查询使用轻量蓝色样式；图标辅助识别，文案保持原样 |
| 次按钮 | 描边和阴影过多 | 采用轻描边或低对比填充；重置/取消优先轻量文字或 ghost；busy、disabled 与焦点有统一外观 |
| 行操作 | 文字颜色混用，部分被右边界裁切 | 处理与查看保持文字可见，统一紧凑 ghost/文字按钮；操作列有明确最小宽度；必要时横向滚动，不用缩小字体挤入 |
| 表头 | 内容与正文对齐关系不清、视觉偏重 | 表头与对应列同轴，弱化背景、使用中等字重；保留所有列，不新增排序和选择功能 |
| 表格单元格 | 各类信息普遍居中或加粗，供应商编码标签抢注意 | 业务文本左对齐、金额右对齐；供应商名称为主、编码为次；时间拆成日期/时分秒两行但不丢数据；编号等宽、正文常规字重 |
| 表格行 | 色块、边框与标签同时强调，密度不稳定 | 推荐仅使用细横分隔、无斑马纹；明确 hover 与键盘焦点；双行记录约 56px，复杂记录按内容增长；不裁切状态副说明 |
| 状态组件 | 小号描边胶囊、文字和说明难以扫描 | 推荐使用 16px 阶段图形 + 13–14px 状态名，透明底；副说明保持原样。对照提供语义文字和 3px 圆角矩形填充标签；三者不能混用为一套默认样式 |
| 分页 | 信息、条数选择和翻页缺少统一节奏 | 与表格底部对齐，明确当前页；每页条数、页码、上一页、下一页、总数沿用原业务；切换时保留 busy 与禁用反馈 |
| 详情与表单 | 大量相似框体容易割裂阅读 | 同一表单以标题、间距、分组分隔组织，少用卡片嵌套；只读信息采用标签/值排版；必填、错误、来源说明保持 |
| 弹窗与确认层 | 需与新组件家族一致 | 标题区、可滚动正文与底部操作区清楚分层；正文保留全部字段，按钮沿用主次层级；危险操作明确，保留确认及底层 inert 行为 |
| 空态与加载 | 容易成为与表格无关的装饰 | 紧凑空态、贴合行列的骨架和轻量加载层；保留查询、重置、刷新、保存等原反馈，不新增业务引导 |
| 图标与排版 | 图标尺度、字重与信息等级缺少共同节奏 | 使用项目现有 Lucide 图标家族；保留 HarmonyOS Sans SC；正文 14px、标题约 24px；400/500/600 字重，按信息层级分配 |

## 推荐状态体系

| 原状态 | 图形/外观 | 说明 |
| --- | --- | --- |
| 草稿 | 空心圆 + 中性文字 | 未进入处理流；副说明仍是待提交 |
| 待审核 | 时钟/点状环 + 琥珀色 | 等待审核，不渲染成失败 |
| 待入库 | 包裹轮廓 + 蓝色文字 | 等待入库，与审核区分 |
| 部分入库 | 半填充圆 + 蓝色文字 | 只表明部分完成，不生成百分比 |
| 已入库 | 勾选圆 + 绿色文字 | 流程完成 |
| 已取消 | 划线圆 + 中性文字 | 流程终止，与错误/危险区分 |

图形必须与原文配合，不只靠颜色区分。不改变状态枚举、流程判断或允许执行的操作。库存的正常、低库存、零库存仍表达原有库存语义，不因统一外观把风险隐藏。

## 各类业务页面如何使用

- 采购、销售、出入库、客户、供应商、产品等列表共用导航、标题、指标、筛选、表格与分页规则；按字段数量换行，不把业务条件收进新弹层。
- 库存页面收敛整行绿色装饰；低库存/零库存仍保留明确的语义标签、数量与必要的局部风险强调，不改变原有风险判断及“查看风险库存”入口。
- 分类与部门树保留层级、展开、勾选和级联规则，以缩进与轻量连接关系显示；图标和行样式统一。
- 工作台保留全部指标、趋势和待办，仅重做指标展示、图表视觉、列表层级、边框和排版；不更改统计值与口径。
- AI 助手沿用同一字体、按钮、表单和浮层规则；保留现有对话区、计划、进度、输入底座及交互，不将业务工作区改成营销页。

## 落地与验收

先应用到共享基础组件，再按库存、采购、表单/详情、工作台和 AI 业务验证。不能用全局 `!important` 覆盖堆砌或整页重写破坏现有请求与状态逻辑。项目已有未提交修改，必须保留。

真正开始前端编辑前，在 `erp-web` 执行与改动覆盖范围一致的预检并阅读完整输出。公共样式和组件必须包含 `shared`，若业务页同时调整则包含相应 scope；涉及全站时使用 `all`。预检后向用户明确报告 scope，再调用编辑工具。外观方案与现行前端风格规范冲突的部分，应在预检后先更新设计规范，禁止一边实施一边保持相互矛盾的规范。

验收至少覆盖：导航、标题、指标带、筛选、表格、状态、按钮、行操作、分页九类中七类的可见结构或组件形态变化；转灰度后仍能区分新旧；字段和操作守恒；长文本、宽表、横向滚动、弹窗、禁用、加载、键盘焦点和窄视口。按项目规定执行契约检查、构建和对应浏览器验证。
