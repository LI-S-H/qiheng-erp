# 智能经营助手真实页面风格落地

入口：[本机实际助手](http://127.0.0.1:9071/ai/assistant)。本轮已启动前端9071与现有配置的本地后端8081；登录沿用原账号，所有请求仍走原接口。工作台仍只更新[独立设计预览](../2026-10-19-workspace-preview/preview.html)。

## 范围

`MainLayout` 仅将 `/ai/assistant` 加入已确认的浅色应用壳，新增页面标记隔离助手样式；目前迁移共19条路由。`ai-pilot.css` 统一会话栏、消息、计划、澄清、输入及手机浮层。正文14px，计划和输入13px，说明12px或较小辅助字号；复用现有共享按钮、Dialog、Tooltip、加载组件和现有布局断点。

新建会话按钮增加书写图标和克制的交互细节；用户提问跳转轨继续位于对话区左侧中部，保留真实提问轮次、预览、键盘操作、滚动高亮和850ms定位提示。输入区与消息滚动区相邻，贴合底部。

没有修改 AI API、消息适配、store、SSE解析、业务字段、权限、暂停锚点或模型请求参数，也未加入执行分析、报告或调度入口。原工作区已有的AI业务重构不属于本次外观改造增量。

## 局部加载及根因

当前AI请求本来已经设置 `skipPageLoading`。切换闪空的直接原因是：store切换时清空旧消息，页面又立即清空计划并关闭计划栏。

现在仅在读取会话时复用 `ListLoadingOverlay`，对话区域和展开的计划区域分别显示同项目加载样式，120ms进入、220ms退出。应用壳、侧栏、输入实例保持；计划开合由用户控制，切换不自动收缩。

同账号切换期间的旧消息与计划只作为不可操作的显示快照；成功时先显示新内容、等待DOM更新后滚到末尾；失败清除快照并显示原重读入口；账号变化立即清除快照。原请求版本、账号校验、取消和草稿逻辑保持。

消息刻度点击仅滚动，不请求接口、不显示加载层。SSE规划期间保持原实时进度可见，不以读取遮罩盖住；加载更早消息仍保留原位置补偿。跨页面路由切换继续使用原全页过渡。
