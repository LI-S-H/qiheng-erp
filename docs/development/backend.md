# 后端开发规范

后端位于 `erp-server/`，根 `pom.xml` 管理 Java 21、Spring Boot 与 Maven 多模块。`erp-admin` 为启动入口；业务模块包括系统、商品、仓储、采购、销售、退货和工作台，AI 与公共、安全能力分别位于对应模块。模块依赖以各 `pom.xml` 为准。

## 修改业务时

1. 先阅读对应 Controller、请求/响应类型、Service、Mapper、实体和相关测试；核对 [接口契约](api.md)与实际数据库结构。
2. 接口层负责身份和参数边界；业务规则、状态变更、事务、并发与幂等在对应服务链路核对。跨模块流程使用项目现有业务服务及接口，不绕过权限和状态校验。
3. 金额、数量、状态和编码沿用现有类型及校验方式，修改时同时检查前后端、数据库、库存流水和历史数据兼容性。
4. 业务写入继续使用现有权限、审计和事务机制；不要将测试账号、生产数据或凭据写进源码、文档及日志。
5. 变更接口、配置或数据库时同步修改对应契约和文档，并根据影响运行测试。

## AI 边界

业务动作必须走现有受控业务流程及确认机制。当前代码也存在独立只读 SQL 分析路径；旧规范中“AI 不直接查询数据库”的表述不能用于描述这一实现。涉及该路径的变更要检查只读账号、SQL 校验、权限、数据范围和审计，具体限制以实现和安全评审为准，不把本说明当成安全验收。

## 验证

在 `erp-server/` 执行 `mvn test` 可运行 Maven 测试阶段；实际覆盖和外部依赖以测试代码及运行结果为准。涉及真实 HTTP 或状态写入时，使用[隔离环境集成测试](../testing/integration/README.md)。详细分层约定见 [后端开发规范](../backend-development-guide.md)，模块依赖以 POM 为准。
