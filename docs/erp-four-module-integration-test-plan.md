# 采购、销售、仓储、退货四模块集成测试计划

## 1. 目标与范围

本计划验证采购、销售、仓储和退货模块的跨模块数据流、状态机、库存事实、退货处理进度回写和接口契约。测试以真实后端实现为准，不以页面 Mock 数据替代服务端校验。

覆盖范围：

- 采购订单审核、采购入库确认、库存与采购累计入库回写。
- 销售订单审核锁库、销售出库确认、库存与销售累计出库回写。
- 采购退货审核预占、采购退货出库确认、库存与采购退货进度回写。
- 销售退货审核、销售退货入库确认、库存与销售退货进度回写。
- 权限、乐观锁、幂等、并发竞争、精度、金额快照与文档契约。

不在本计划范围：退款、换货订单、财务结算、批次/序列号和跨仓调拨。

## 2. 当前契约基线

### 2.1 统一退货入口与权限

| 能力 | 接口/动作 | 后端权限 | 核心断言 |
| --- | --- | --- | --- |
| 列表、详情、来源订单和来源明细 | `GET /returns*` | `return:query` | 采购与销售均使用统一查询权限，按 `returnType` 区分方向 |
| 创建采购退货草稿 | `POST /returns` | `purchase:create` | 请求必须带 `returnType=PURCHASE_RETURN` |
| 创建销售退货草稿 | `POST /returns` | `sales:create` | 请求必须带 `returnType=SALES_RETURN` |
| 编辑、删除、提交、审核、取消 | `/returns/{id}` 及动作接口 | `purchase:manage` 或 `sales:manage` | 权限由既有退货单方向决定 |

### 2.2 来源明细数量字段

| 方向 | `sourceFulfilledQty` | `stockAvailableQty` | `occupiedQty` | 可否继续申请的唯一判断 |
| --- | --- | --- | --- | --- |
| 采购退货 | 原采购明细累计已入库量 | 当前仓库 `stockQty - lockedQty` | 同来源有效采购退货占用量 | `availableReturnQty = max(0, min(sourceFulfilledQty - occupiedQty, stockAvailableQty))` |
| 销售退货 | 原销售明细累计已出库量 | 当前服务端跳过库存查询，固定返回 `0` | 同来源有效销售退货占用量 | `availableReturnQty = max(0, sourceFulfilledQty - occupiedQty)` |

`availableReturnQty = 0` 表示该来源明细不可再申请退货，前端必须禁止新增该明细或将申请数量限制为 0。采购退货的 `stockAvailableQty = 0` 会使可退量为 0；销售退货的该字段当前是未适用的服务端占位值，不能用它判断可退资格。

### 2.3 状态机与仓储工作单

| 退货状态 | 允许的核心动作 | 仓储结果 |
| --- | --- | --- |
| `DRAFT` | 编辑、提交、删除、取消 | 不生成工作单、不占用退货数量 |
| `SUBMITTED` | 编辑、审核、取消 | 已按申请数量占用来源可退量 |
| `APPROVED` | 取消（尚未处理） | 采购生成 `PURCHASE_RETURN` 待确认出库单；销售生成 `SALES_RETURN` 待确认入库单 |
| `PARTIAL_EXECUTED` | 查看 | 已确认部分数量，剩余审核量继续通过工作单处理 |
| `COMPLETED` / `CANCELLED` | 查看 | 终态，不再直接编辑或处理 |

金额是申请金额快照：创建或编辑时按申请数量和来源单价计算；审核及仓储确认只更新审核/处理数量，不重算金额。

## 3. 测试环境与数据准备

| 项目 | 方案 | 通过条件 |
| --- | --- | --- |
| 数据库 | 独立 MySQL 测试库，按基础表、采购、销售、仓储、退货 SQL 顺序初始化 | 每轮测试使用独立库或可回滚事务，不复用开发数据 |
| Redis | 独立 DB/容器 | 不污染开发会话与缓存 |
| 服务 | 启动 `erp-admin`，启用 purchase、sales、warehouse、return 模块 | 健康检查通过，四模块 Bean 和路由可用 |
| 身份 | 管理员、仅查询、仅创建、仅管理四类测试账号 | 每个接口均能覆盖 200、403 与必要的 401 |
| 产品与仓库 | 同一仓库下准备整数精度和两位小数精度产品 | 覆盖精度、可用库存和锁定库存边界 |
| 来源订单 | 一张已部分履约和一张已完全履约的采购/销售订单 | 覆盖部分确认、全量确认和来源资格筛选 |

所有数量断言统一用数据库存储值（×100 整数）和 API 展示值（最多两位小数）双重比对；所有金额断言使用金额字符串与存储值双重比对。

## 4. 端到端用例矩阵

### 4.1 采购入库主链

| 编号 | 场景 | 操作 | 关键断言 |
| --- | --- | --- | --- |
| PI-01 | 审核生成待确认入库单 | 创建、提交、审核采购订单 | 生成一张 `PURCHASE_IN/PENDING_CONFIRM`；库存与已入库数量均不变 |
| PI-02 | 部分入库 | 确认小于剩余数量 | 入库单确认；库存增加本次数量；采购明细 `inboundQty` 增加本次数量；来源订单进入部分入库 |
| PI-03 | 完全入库 | 再确认剩余数量 | 采购明细累计量等于订购量；订单进入完成；产生且仅产生对应库存流水 |
| PI-04 | 重复确认与超量 | 重复提交确认、确认量超过剩余 | 前者幂等不重复记账，后者整体失败且库存/回写/流水不变 |

### 4.2 销售出库主链

| 编号 | 场景 | 操作 | 关键断言 |
| --- | --- | --- | --- |
| SO-01 | 审核锁库并生成待确认出库单 | 创建、提交、审核销售订单 | `lockedQty` 增加审核数量；生成一张 `SALES_OUT/PENDING_CONFIRM`；实际库存不变 |
| SO-02 | 部分出库 | 确认小于剩余数量 | `stockQty` 与 `lockedQty` 同时减少本次数量；销售明细 `outboundQty` 回写；订单进入部分出库 |
| SO-03 | 完全出库 | 确认剩余数量 | 锁定全部释放；累计已出库等于审核数量；库存流水只记一次 |
| SO-04 | 锁库竞争与不足 | 两张销售单竞争同一可用库存 | 仅一方可锁定成功；失败方返回业务错误且不产生工作单 |

### 4.3 采购退货链

前置：来源采购明细已实际入库，且仓库存在足够可用库存。

| 编号 | 场景 | 操作 | 关键断言 |
| --- | --- | --- | --- |
| PR-01 | 来源资格与数量口径 | 查询来源订单、来源明细 | 仅返回 `inboundQty > 0` 的来源；明细接口仍返回 `availableReturnQty=0` 的已履约行，但前端不得允许选择；`availableReturnQty` 等于采购公式，`stockAvailableQty=0` 时不能申请 |
| PR-02 | 草稿、提交与编辑 | 创建草稿，提交后编辑 | 草稿不占用；提交按申请量占用；`SUBMITTED` 可全量编辑并保持该状态，重新校验可退量与金额快照 |
| PR-03 | 审核预占与工作单 | 审核部分通过 | 占用从申请量切换为审核量；`lockedQty` 增加未处理审核量；生成 `PURCHASE_RETURN/PENDING_CONFIRM` 出库单；全零审核失败 |
| PR-04 | 部分出库 | 确认部分审核量 | 退货单进入 `PARTIAL_EXECUTED`；`processedQty`、库存、锁定量和库存流水仅按本次确认量推进；来源采购订单的累计已入库量保持不变，剩余可退量由有效退货单占用量派生；剩余量不重复预占 |
| PR-05 | 完成与重复确认 | 确认剩余、重放确认请求 | 退货单完成；库存与锁定量各减少审核总量；库存流水和退货处理进度不重复 |
| PR-06 | 审核后取消 | `APPROVED` 且未处理时取消 | 待确认出库单取消；未处理锁定量释放；库存和来源累计履约量不变 |
| PR-07 | 并发竞争 | 两张退货单竞争同一来源或同一可用库存 | 只允许一方提交/审核成功；另一方失败且所有表保持原子一致 |

### 4.4 销售退货链

前置：来源销售明细已实际出库。

| 编号 | 场景 | 操作 | 关键断言 |
| --- | --- | --- | --- |
| SR-01 | 来源资格与数量口径 | 查询来源订单、来源明细 | 仅返回 `outboundQty > 0` 的来源；明细接口仍返回 `availableReturnQty=0` 的已履约行，但前端不得允许选择；`stockAvailableQty` 当前返回 0，`availableReturnQty > 0` 时仍可申请，等于销售公式 |
| SR-02 | 草稿、提交与编辑 | 创建、提交、编辑 | 草稿不占用；提交占用申请量；`SUBMITTED` 编辑后重新校验来源可退量并保持状态 |
| SR-03 | 审核与入库单生成 | 审核部分通过 | 占用从申请量切换为审核量；不锁库存；生成 `SALES_RETURN/PENDING_CONFIRM` 入库单；全零审核失败 |
| SR-04 | 部分入库 | 确认部分审核量 | 退货单进入 `PARTIAL_EXECUTED`；`processedQty`、库存和库存流水仅按本次确认量推进；来源销售订单的累计已出库量保持不变，剩余可退量由有效退货单占用量派生 |
| SR-05 | 完成与重复确认 | 确认剩余、重放确认请求 | 退货单完成；库存流水和退货处理进度不重复 |
| SR-06 | 审核后取消 | `APPROVED` 且未处理时取消 | 待确认入库单取消；库存不变；来源销售累计履约量不变 |
| SR-07 | 并发竞争 | 两张退货单竞争同一销售来源明细 | 仅一方能占满可退量；另一方失败且不生成入库单 |

## 5. 横向质量用例

| 类别 | 必测内容 | 通过条件 |
| --- | --- | --- |
| 权限 | 未登录、无 `return:query`、无 `purchase:create`/`sales:create`、无对应 `*:manage` | 401/403 符合契约，数据无变更 |
| 乐观锁 | 用过期 `version` 编辑、提交、审核、取消 | 返回 409，明细、状态和库存不变 |
| 幂等与重复操作 | 对确认接口重复调用；对取消接口重复调用 | 重复确认不得重复产生工作单、流水、退货处理进度或锁定量变化；重复取消返回“当前状态不允许取消”，且不产生任何数据变更 |
| 数量精度 | 整数产品提交 0.01；两位精度产品提交第三位小数 | 后端拒绝；无数据写入 |
| 金额快照 | 申请数量、审核数量、处理数量不同 | 总金额和明细金额始终等于创建/编辑后的申请数量乘原单价 |
| 原子性 | 在库存扣减、退货单处理进度回写、流水写入任一步注入失败 | 所有相关表回滚到操作前状态 |
| 文档契约 | OpenAPI、DTO、前端 adapter、Mock、数据库说明和 SQL 种子 | 字段名、必填项、枚举/非空规则、数量与金额语义一致 |

## 6. 自动化分层与交付门槛

| 层级 | 推荐实现 | 覆盖重点 | 合入门槛 |
| --- | --- | --- | --- |
| 静态契约 | `npm run check:openapi` | OpenAPI 引用、SQL/文档/前端退货请求一致性 | 必须通过 |
| 前端构建与契约烟测 | `npm run build`、采购/销售退货 contract smoke | 适配层请求路径、参数、请求体、只读字段 | 必须通过 |
| 服务单元测试 | JUnit 5 + Mockito | 可退量公式、金额快照、权限分支、状态迁移 | 必须新增并通过 |
| 模块集成测试 | Spring Boot Test + Testcontainers MySQL/Redis | 事务、Mapper、端口回写、库存锁定 | 必须新增并通过 |
| API 端到端测试 | RestAssured/WebTestClient | 第 4、5 节数据流、响应码和数据库断言 | 发布前必须通过 |
| 浏览器验收 | Playwright | 登录、权限入口、来源选择、0 可退量禁选、提交与二次确认 | 发布前必须通过 |
| 并发回归 | 并行 API 请求 + barrier | 来源可退量和库存锁竞争、幂等 | 发布前必须通过 |

建议首批自动化类按模块放置在 `erp-server/erp-{purchase,sales,warehouse,return}/src/test`，共享端到端编排放置在 `erp-admin/src/test`。每个用例使用独立测试数据，严禁依赖开发库中的固定单号或已存在库存。

## 7. 执行顺序与验收输出

1. 初始化独立 MySQL/Redis，执行 schema 与种子一致性校验。
2. 执行 PI-01 至 PI-04、SO-01 至 SO-04，建立入库、出库与库存基线。
3. 执行 PR-01 至 PR-07、SR-01 至 SR-07，并在每一步比对退货单、工作单、库存余额、锁定量、来源累计履约量（保持不变）和库存流水。
4. 执行横向质量用例及并发回归。
5. 运行静态契约、前端构建、后端模块测试和浏览器验收。

每次执行须输出：测试数据标识、接口请求与响应、关键表操作前后快照、库存流水 ID、失败用例的异常与事务回滚证据。任何一项库存余额、锁定量、来源累计履约量（应保持不变）、退货处理量或流水条数不符合预期，即判定本轮失败。
