# 前端开发规范

## 1. 文档定位

本文档只约束启衡 ERP 的前端开发，包括页面、组件、前端 API 适配层、交互状态和前端测试。后端代码规范应单独成文，不得混入本文档。

每次新增或修改前端代码前，必须先阅读：

1. `docs/frontend-development-guide.md`
2. `docs/frontend-style-guide.md`
3. 当前业务模块在 `docs/database/` 下的数据库设计
4. `docs/api/erp-openapi.yaml` 中对应接口
5. 需要复用风格的现有页面和组件

编码 Agent 必须在编辑文件前执行对应范围的预检命令，并在过程消息中报告已完成的 scope：

```powershell
cd erp-web
npm run preflight:frontend -- product
```

同时修改多个模块时传入多个 scope；修改公共组件、全局样式、路由或通用 API 时包含 `shared`，影响范围不明确时使用 `all`。不得先修改代码再补跑预检。Git 提交钩子会校验预检凭证的当前提交、有效期、覆盖范围和必读文档哈希。

若页面、数据库设计和 OpenAPI 不一致，先修正契约再写页面，不得用 Mock 数据掩盖字段来源问题。

## 2. 数据库驱动原则

- 页面字段必须能追溯到数据库字段、明确的关联查询、聚合查询或前端固定字典。
- 不得要求后端返回数据库没有来源、又能由前端稳定计算的展示字段。
- `BIGINT` ID 在 JSON 中必须按字符串传输，前端不得转换为 `Number`，避免超过 JavaScript 安全整数范围。
- 数据库枚举、状态、金额和数量进入页面模型前，必须在 API 适配层完成类型转换和合法值校验。
- 固定字典名称由前端按编码映射；会随业务数据变化的名称可由后端通过一次关联查询返回。
- 设计表单前必须逐字段确认“用户输入、后端生成、登录上下文、审计自动填充、业务推导”五类来源；非用户输入字段不得渲染为可编辑控件，也不得进入提交 DTO。系统生成字段需要展示时使用只读值并说明来源。
- 产品编码、仓库编码、供应商编码、客户编码和业务单号等唯一业务编码默认由后端统一生成，并由唯一索引兜底；只有需要映射外部系统编码、客户约定编码或既有线下标签体系等明确业务场景时，才能在说明重复、变更和兼容风险并经用户确认后开放人工填写。

## 3. 查询接口规范

### 3.1 字段必须明确

- 一个筛选控件必须对应一个明确的查询参数和数据库字段或关联字段。
- 多个查询参数同时存在时默认按 AND 组合，接口文档必须写明匹配方式。
- 禁止为了减少筛选框使用含义不明的 `keyword`，同时匹配编码、名称、品牌、部门等多个数据库列。
- 只有数据库已设计全文检索或业务明确需要“全局搜索”时，才允许使用 `keyword`，并必须在 OpenAPI 中列出匹配列、分词规则和组合方式。
- 编码、名称、条码等字段应分别使用 `productCode`、`productName`、`barcode` 等参数，不能让后端猜测用户输入意图。
- 前端发送请求前必须去除文本首尾空格；空字符串、`all` 和未选择值不得发送到后端。

### 3.2 层级筛选

- 分类和部门接口返回扁平数据，前端按 `parentId` 构建树、缩进和路径。
- 下拉框可显示前端生成的 `办公用品 / 办公纸品` 路径，但请求只发送稳定的 `categoryId`。
- 产品按分类查询时，选中父分类表示查询该分类及全部后代分类下的产品。
- 后端根据最新分类关系解析后代 ID 并完成查询；前端不得发送分类路径字符串，也不得把当前缓存计算出的全部后代 ID 作为最终查询条件。
- 产品列表可以通过关联查询返回当前分类名称，但不得返回拼接后的分类层级路径。

## 4. API 适配层规范

- 页面组件不得直接假设运行时响应类型与 TypeScript 声明一致。
- API 模块负责把响应 DTO 转换为页面模型，例如把 `"1"` 转换为状态数字 `1`，把 decimal 字符串转换为有限数值。
- 非法状态、非法数值和非字符串 `BIGINT` ID 应尽早抛出契约错误，不能静默产生错误页面数据。
- 下拉选项必须保留业务字段原始类型；状态值保持 `0 | 1`，不能因组件内部处理变成 `"0" | "1"`。
- 页面提交 DTO 必须与 OpenAPI 一致，前端专用的 `all`、路径名称、选中标签等字段不得进入请求。
- Sa-Token 请求头名称使用登录响应返回的 `tokenName`，不得写死。

## 5. 后端返回边界

- 后端应返回业务数据和必要的关联展示字段，不应组装前端展示结构。
- 部门、产品分类等层级数据返回扁平数组，不返回 `children`、`parentName` 或层级路径。
- 允许后端返回一次查询可稳定获得的关联字段，例如用户部门名称、产品当前分类名称。
- 允许后端返回数据库可执行的聚合字段，例如角色用户数、分类直接关联产品数。
- 前端计算的数量只能用于展示和快速预校验，停用、删除等最终判断由后端基于最新数据完成。

## 6. 表单与组件

- 必填字段必须同时具备红色星号、提交校验和邻近错误提示。
- 文本提交前执行 `trim`，并校验非空、长度和格式；金额、数量校验有限值和业务范围。
- 输入框、文本域和下拉框必须使用统一焦点辉光，不得在弹窗中出现更粗或更亮的焦点环。
- 同一页面同一时刻只能打开一个下拉弹层；打开新下拉必须关闭旧弹层。弹窗内下拉层级必须高于业务弹窗、低于二次确认层；长选项列表使用细滚动条且不得被弹窗内容遮挡。
- 金额输入使用货币前缀明确单位，人民币显示 `￥`，提交值仍为纯数值。
- 弹窗高度受 `100dvh` 约束，长表单必须可滚动，标题和底部操作始终可访问。
- 长表单或长详情的独立滚动正文必须使用共享 `DialogScrollArea`；该组件会在真实内容层为滚动条预留空间，禁止在业务页面通过给 `ScrollArea` 外壳添加 `pr-*` 来规避遮挡。
- 二次确认出现时，底层编辑弹窗必须进入 `inert` 状态，遮罩必须阻止点击穿透。
- 写操作必须使用提交锁；唯一键冲突使用 `409 Conflict` 并回填具体字段。
- 会触发库存、金额或来源单据回写的业务状态不能使用普通下拉任意修改；必须按后端状态机提供明确动作按钮、二次确认和独立事务接口。已产生业务事实的终态记录不得直接改回草稿，应通过冲销或反向业务单据纠正。

## 7. 查询、分页与加载

- 查询使用短防抖并通过请求序号忽略过期响应。
- 防抖等待期也必须立即显示查询中状态和数据区加载层。
- 分页和每页条数切换使用短防抖，点击后立即锁定分页容器并显示加载反馈。
- 刷新按钮与查询、分页使用同一套短防抖和数据区加载层；点击刷新后必须立即显示遮罩并禁用刷新按钮，不能等请求发出后才反馈。
- 重置筛选会重新查询列表，必须与查询按钮使用同一套短防抖和数据区加载层；点击后先清空筛选控件，再立即显示遮罩并禁用重复操作。
- 加载期间保留旧数据作为上下文，但禁止重复触发查询、分页和数据操作。
- 表格使用固定布局和显式 `colgroup`，翻页或筛选后列宽不得漂移。

## 8. 测试与文档同步

- 修改查询字段时必须同时更新类型、API、Mock、页面、OpenAPI 和浏览器测试。
- 测试必须验证每个筛选控件只影响对应字段，并验证多个条件按 AND 组合。
- 层级筛选必须覆盖父级、子级和无结果场景。
- 响应转换必须覆盖字符串状态、decimal 字符串和非法值。
- 完成后至少运行 OpenAPI 契约检查、生产构建、对应页面 smoke 和全量交付测试。
- 新发现的规范缺口同步补充本文档，并在 `BUGFIX_LOG.md` 记录根因和验证结果。

## 9. 历史问题清单

以下问题均已在本项目出现，后续开发必须逐项规避：

1. 登录响应包含 `tokenName`，但请求头曾写死为 `satoken`。
2. 部门和产品分类曾要求后端预组装树结构或层级路径。
3. 权限页面曾要求后端返回数据库不存在的 `moduleName`。
4. 状态下拉值曾被转换为字符串，导致数字状态筛选失效。
5. 请求曾把前端占位值 `all` 发送给后端。
6. 表格未固定列宽，翻页后列距随内容变化。
7. 已有校验但缺少必填星号和字段附近的错误提示。
8. 编辑用户未修改密码时曾发送空密码字段。
9. 查询防抖等待期和分页切换曾没有加载反馈，用户容易重复点击。
10. 写操作、批量操作和确认操作曾缺少提交锁。
11. 长弹窗曾被视口截断，产品档案滚动区曾被压缩为 0 高度。
12. 警告弹窗曾允许点击底层编辑表单，确认区按钮曾贴近底边。
13. 前端曾计算并展示精确下级、员工或产品影响数量，可能与后端最新数据不一致。
14. 部门和产品分类的编辑停用入口曾绕过与批量停用相同的级联规则。
15. 删除保护曾主要依赖前端按钮或列表快照，后端缺少最终 `409 Conflict` 校验。
16. 产品表曾考虑冗余分类名称，存在分类改名后的双写风险。
17. 产品档案 Mock 数据曾发生中文编码损坏。
18. 产品、用户和权限查询曾使用一个 `keyword` 同时匹配多个数据库字段，接口无法表达明确查询意图。
19. 产品分类筛选曾只匹配当前分类，没有包含父分类的全部后代分类。
20. 页面曾只依赖 TypeScript 类型，没有在 API 边界转换后端字符串状态和 decimal 字符串。
21. 产品表单曾允许用户填写本应由后端生成且不可修改的产品编码。
22. 多个下拉组件曾同时保持展开，弹层互相覆盖并造成误选。
23. 分页每页条数触发框宽度不足，中文选项显示不完整。
24. 金额输入缺少货币前缀，下拉长列表滚动条视觉过重。
25. 弹窗内下拉与弹窗内容使用相同层级，选项曾被白色表单遮挡并呈现穿透效果。
26. 数据库允许产品暂不分类，但业务文档曾误写为启用产品必须归属分类，导致页面、接口和库表约束互相矛盾。
27. 库存健康和锁定占用曾混用一个“库存状态”字段，导致同一库存的低库存与锁定事实互相覆盖；正交派生维度必须拆分展示和筛选。
28. 出入库记录页曾被误设为纯只读追溯页，遗漏库存调整新增、草稿编辑、确认和取消入口；同时不能把状态改成任意下拉，必须区分来源单据自动生成与手工调整，并使用受控状态流转。
29. 出入库数量输入曾统一使用 `0.0001` 步长，导致箱、瓶等离散单位通过数字箭头产生四位小数；数量步长和校验必须来自产品数量精度，接口传真实值，后端统一做 100 倍整数持久化转换。
30. 出入库手工入口曾只允许库存调整，无法补救遗漏登记的采购、销售和退货业务；补录必须与来源生成凭证明确区分，并强制记录原业务单号、原因和当前登录负责人。

## 10. 开发检查清单

编写代码前确认：

- 已阅读本文档、视觉规范、模块数据库设计和对应 OpenAPI。
- 每个页面字段都有明确数据来源。
- 已区分用户输入字段和系统生成字段，提交 DTO 不包含只读展示字段。
- 每个筛选框都有独立参数和可执行查询条件。
- 层级数据的前后端职责已经划分清楚。
- 响应 DTO 与页面模型之间有必要的类型转换。

提交代码前确认：

- 类型、API、Mock、页面、OpenAPI、数据库说明和测试保持一致。
- 没有发送 `all`、空字符串或前端展示字段。
- 没有要求后端拼接树、路径或其他前端可计算内容。
- 查询、分页、写操作和弹窗均有正确的加载或提交锁。
- 构建、契约检查和浏览器回归全部通过。
