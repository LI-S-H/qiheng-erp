# 启衡 ERP 前端界面风格规范

## 1. 设计目标

界面统一采用简洁、克制、适合长时间使用的企业后台风格。页面首先保证层级清楚、表格可读和操作确定，不使用营销页式装饰、强渐变或大量独立卡片。

## 2. 应用壳

- 左侧导航与顶部状态栏使用同一组深色中性 token，背景、边框、文字和 hover 状态必须一致
- 左侧导航宽度固定，一级菜单和二级菜单使用统一字号、字重、圆角和缩进
- 当前菜单使用低饱和深色背景与左侧品牌色短线，不使用整块高亮蓝色
- 顶栏左侧显示当前模块和页面标题，右侧仅保留通知与用户菜单
- 路由切换使用约 `220ms` 的轻量加载遮罩与淡入过渡，遮罩期间不暴露旧页面内容，菜单高亮和页面内容必须同步

### 2.1 通知铃铛弹层

- 铃铛触发按钮沿用顶栏 `36px` 方形点击区和中性文字色，hover 使用侧栏统一的低对比背景；存在待处理事项时显示数字徽标，不再使用无业务含义的固定圆点。
- 数字徽标紧贴铃铛右上角，`1-99` 显示实际值，超过 `99` 显示 `99+`，待处理数量为 `0` 时隐藏。只有高优先级事项可以使用风险色，普通待办使用品牌色或中性色，避免顶栏长期处于红色报警状态。
- 弹层从铃铛右下方展开并右对齐，桌面端宽度约 `380px`，最大高度使用 `min(560px, calc(100dvh - 5rem))`；较小视口下宽度不超过 `calc(100vw - 1rem)`，不得溢出视口。
- 内容使用单一容器和分隔线组织紧凑列表，不把每条通知做成独立大卡片。标题单行省略，影响说明最多两行；完整证据和处理过程前往工作台或业务页面查看。
- 业务标签、优先级、数量、时间和操作按钮保持明确层级；普通信息使用中性色，只有真正的高风险事项使用红色，避免用多种高饱和颜色制造噪声。
- 首次加载使用紧凑骨架屏，后台刷新保留旧列表并显示轻量刷新状态；空态只显示“当前没有待处理事项”，不使用营销插画或庆祝动画。
- 通知弹层和用户菜单必须互斥，点击外部或按 `Esc` 可关闭；触发按钮、列表项和底部入口均需支持键盘焦点和可读的 `aria-label`。

## 3. 字体与颜色

- 全站使用 `Microsoft YaHei`、`PingFang SC`、`Noto Sans SC`、`system-ui` 中文系统字体栈
- 页面业务正文、筛选标签、输入内容和表格主文字统一使用 shadcn `text-sm`，即 `14px`；所有 shadcn 文字按钮统一为 `13px`；页面标题约 `24px`，一级与二级菜单为 `15px`
- 导航文字使用中等以上字重，非激活菜单也要保证足够对比度，不能依赖低透明度制造层级
- 主色只用于主操作、当前导航和关键链接；普通信息使用中性灰
- 启用状态使用浅绿底深绿字，停用状态使用浅灰底灰字，危险操作使用浅红或红色文字
- 输入框和下拉框获得焦点时仅使用低透明度、带模糊半径的品牌色辉光，不使用清晰的高亮双描边

## 4. 列表页结构

列表页按以下顺序组织：

1. 页面标题与一句说明
2. 单条摘要栏，内部等分展示 4 项核心指标
3. 紧凑筛选区
4. 单一数据容器，内部包含工具栏、表格和分页或树形摘要

摘要指标不拆成四张独立卡片，避免页面碎片化。新增按钮放在表格工具栏，不放在页面标题右侧。

筛选输入统一使用共享 `Input`，筛选下拉统一使用 shadcn `Popover + Command` 组合的 `AnchoredSelect`，弹层固定从触发框正下方展开且与触发框等宽。同一页面同一时刻只能展开一个下拉弹层，打开新下拉时必须立即关闭旧弹层。宽内容区允许单行排列；中等宽度改为两列网格并让操作按钮单独右对齐；移动端改为单列。

筛选选项值必须保留接口字段类型，例如状态使用数字 `0 | 1`，不能转换成字符串；“全部”只用于前端显示，发送请求时应省略对应参数。多个有效筛选条件按 AND 组合。

筛选控件按数据库字段拆分，不得用一个含义不明的关键词输入同时查询编码、名称、品牌等多个字段；层级选择显示路径可由前端计算，但请求只发送稳定 ID。

## 5. 弹窗与滚动

- 所有 `Dialog` 和 `AlertDialog` 内容高度不得超过 `100dvh - 2rem`
- 内容超过视口时，弹窗容器必须提供纵向滚动，且滚动条始终可达
- 长表单和长详情的正文滚动统一使用 `DialogScrollArea`，滚动条与表单控件之间必须保留安全间距，不得由业务页面重复维护右侧补白
- 权限码等长列表可以在弹窗内部使用独立 `ScrollArea`，但不能通过 `overflow: hidden` 截断外层内容
- 弹窗在较小桌面视口下也必须能访问标题、表单内容和底部操作按钮

## 6. 按钮与标签

- 主操作使用品牌蓝实底按钮
- 所有文字按钮使用 `13px` 和常规字重；通过高度、留白、颜色和边框表达层级，不通过放大或加粗文字制造强调

## 表单与请求规范

- 前端表单模型可以用 `null` 表示“尚未选择”，提交 DTO 必须与 OpenAPI 一致，不允许把必填字段的空值发送到接口
- 文本提交前先 `trim`，再执行必填、长度和格式校验；多选字段需要去重并校验至少一项
- 建模表单前先确认字段归属：后端生成、登录上下文带入、审计自动填充或业务规则推导的字段不得让用户编辑；需要展示时使用只读值和来源说明，并从提交 DTO 中移除
- 金额输入框在控件内显示明确货币前缀（人民币使用 `￥`），前缀不得遮挡输入值或参与提交
- 唯一键冲突使用 `409 Conflict`，并将“登录账号已存在”“角色编码已存在”等消息回填到具体字段
- 权限码使用小写字母、数字和冒号分段，前端与 OpenAPI 统一校验；必填项在标签后显示红色 `*`，错误信息紧邻控件
- 查询入口使用短防抖避免连续请求；保存、启停、删除和批量操作必须使用提交锁，接口完成前禁止重复触发
- 查询按钮使用短防抖，列表请求通过序号忽略过期响应；点击查询后必须立即进入可见的“查询中”状态，防抖等待期也要显示旋转图标和数据区加载层，禁止让用户面对无反馈延迟
- 查询加载层保留旧数据作为上下文，使用轻量遮罩阻止重复操作；请求或本地筛选完成后自动移除，查询按钮和重置按钮在此期间保持禁用
- 上一页、下一页、页码和每页条数切换统一使用短防抖；点击后立即复用数据区加载层，并把分页容器标记为忙碌和暂时不可交互，避免用户因无反馈重复点击
- 工具栏刷新按钮统一使用短防抖；点击后立即复用数据区加载层并禁用刷新按钮，防抖等待期和请求期间都必须保持可见反馈
- 筛选区重置按钮统一使用短防抖重新查询；点击后立即清空筛选控件、显示数据区加载层并禁用重复操作
- 保存、确认和批量操作在请求完成前保持禁用状态
- 所有存在父子层级或业务关联的停用操作都必须二次确认；前端只展示通用风险说明，不计算精确影响数量，后端基于最新数据完成最终校验和事务级联
- 编辑表单内修改状态和列表批量启停必须遵守同一套级联、确认和后端校验规则，禁止通过编辑入口绕过风险确认
- 列表返回的下级、员工数、产品数等数据只能用于页面展示和快速预校验，不能作为是否允许操作的最终依据
- 删除前端只做预校验，后端必须再次检查下级和业务关联；存在关联时返回 `409 Conflict`，不能仅依赖按钮禁用或 Toast
- 编辑弹窗内触发二次确认时，确认层必须使用更高层级的可交互遮罩，底层弹窗进入 `inert` 状态；禁止仅做视觉覆盖却允许点击或聚焦底层控件
- 确认弹窗的正文区和操作区必须分层，按钮区不得使用贴近容器边缘的负外边距，上下内边距不低于 18px
- 次要批量操作使用 `outline`
- 行内“编辑”“角色”“权限配置”“新增下级”使用 `ghost`，通过文字颜色区分，不叠加多种彩色底框
- 删除等危险操作使用红色文字或浅红背景，不使用大面积实红按钮
- 角色和权限摘要使用浅蓝底、蓝色文字和轻边框
- 表格状态标签保持低视觉权重，宽度随内容变化
- 工具栏按钮保留 shadcn 原生 hover 色阶和轻阴影变化；批量操作使用 `Tooltip` 说明用途，禁用时提示需要先选择数据

## 7. 表格与分页

- 表头使用浅灰背景和较弱文字色，正文行高约 `48px-52px`
- 文本列左对齐，状态、数量、角色等短字段居中
- 操作列只保留高频动作，批量动作集中在工具栏
- 数据表使用 `table-layout: fixed` 和显式 `colgroup`；分页、筛选或树节点展开后不得按当前内容重新计算列宽
- 表格展示字段必须能追溯到数据库字段、关联表或可执行的聚合查询；固定字典的中文名称由前端根据数据库编码映射，不要求后端返回无数据源的冗余字段
- 分页底栏与部门树摘要栏统一为 `52px` 高，使用 `12px` 辅助文字
- 带总数分页左侧展示总条数和 shadcn `Select` 每页条数选择，中间使用 shadcn `Pagination` 放置上一页、页码和下一页，右侧展示总页数；当前页数字不使用明显边框或背景
- 无总数分页左侧展示本页条数和每页条数选择，中间只放上一页、当前页和下一页，右侧提示不统计总数；仓库、库存余额等不需要精确总条数的页面优先使用该模式
- 数据容器应允许横向滚动，不能通过压缩列宽造成内容重叠

## 8. 部门树规则

- `/system/depts` 接口返回扁平数组，前端按 `parentId` 构建树和层级路径
- 展开控件使用纯 `chevron`，无边框、无底色，并为无子节点行保留同宽占位
- 无父节点显示“无上级部门”
- 勾选父级时同步勾选全部下级，取消父级时同步取消全部下级
- 停用父级时级联停用全部下级；上级停用时不能单独启用下级
- 存在下级部门或员工归属时禁止删除部门，后端必须重复校验
- 停用确认只需说明下级部门会同步停用、员工账号不会自动停用以及停用部门不能继续作为新增或调整员工归属，不展示精确员工或下级数量
- 通过编辑弹窗把部门改为停用时，也必须先显示同样的级联影响确认，确认后再提交

## 9. 产品分类树规则

- `/product/categories` 返回扁平数组和每个分类直接关联的 `productCount`，不返回 `children`、上级名称或层级路径
- 前端按 `parentId` 构建树、计算路径并完成名称和状态筛选，避免后端拼接展示字符串
- 勾选父级时同步勾选全部下级；停用父级时级联停用全部下级和这些分类下的关联产品，上级停用时不能单独启用下级
- 停用确认只需说明下级分类和关联产品会同步停用，不展示精确数量；通过编辑弹窗把分类改为停用时，也必须先显示同样的级联影响确认
- 同一上级下分类名称不能重复；编辑时不能把上级设置为自身或自身下级
- 存在下级分类或关联产品时禁止删除分类，前端预校验，后端必须重复校验并返回 `409 Conflict`

## 10. 智能体对话输入区

- 智能体对话必须把消息滚动区与输入区拆成两个相邻布局行；消息只在上方区域滚动，输入区使用不透明底座和细分隔线贴合容器底部。
- 禁止通过绝对定位、底部留空和重阴影把输入框做成悬浮卡片，避免消息内容出现在输入框下方；聚焦态只使用轻量边框与焦点辉光，不做上移变换。
- 输入、发送、加载锁和键盘提示封装为模块组件；`Enter` 发送、`Shift+Enter` 换行，发送期间输入框和按钮必须禁用。

## 11. 交付验证

每个系统权限页面至少通过以下检查：

- `npm.cmd run build`
- 对应 `smoke:system-*` 浏览器端到端测试
- 产品分类页面执行 `npm.cmd run smoke:product-categories`
- 产品档案页面执行 `npm.cmd run smoke:product-products`
- `npm.cmd run check:openapi` 接口文档引用和关键契约检查
- 1440 x 900 桌面视口截图复核
- 1115 x 838 中等桌面视口筛选布局复核
- 低高度视口长弹窗滚动测试
