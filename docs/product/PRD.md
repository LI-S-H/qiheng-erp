## 2. 产品定位

启衡 ERP 的通知铃铛是登录用户在任意业务页面快速发现“当前需要我处理或关注什么”的轻量入口。它聚合采购、销售、仓储、库存和系统异常等跨模块事项，但不替代工作台和具体业务页面。

核心价值：

- 让采购、销售、仓库、管理者和系统管理员及时发现与自己有关的阻塞事项和风险。
- 用一个轻量弹层提供业务摘要和明确去向，减少用户逐个进入模块检查状态的成本。
- 复用工作台待办口径和权限裁剪，避免铃铛与工作台产生两套互相冲突的数据。

当前阶段不建设独立消息中心，不维护用户级已读/未读历史，不新增消息表，不提供站外推送。

## 4. 功能范围

### 4.1 包含

- 顶栏铃铛展示待处理数量徽标，数量超过 99 时显示 `99+`，数量为 0 时不显示徽标。
- 点击铃铛打开右对齐弹层，展示当前用户可见且状态为 `PENDING` 的前 8 条待办。
- 待办覆盖采购、销售、仓储、库存、复核风险和系统异常等可扩展业务类型。
- 每条待办展示业务标签、优先级、标题、待处理数量、简短影响说明和明确动作。
- `completionMode=AUTO` 的事项点击“去处理”后跳转接口提供的内部业务路由，由业务状态变化自动完成。
- `completionMode=TRACKED` 的系统异常点击“查看详情”后进入工作台异常详情，不在铃铛中直接完成。
- 弹层底部提供“进入工作台查看全部”，用于查看完整待办和证据。
- 支持加载、空数据、接口失败、重试和缓存数据过期状态。
- 用户菜单和通知弹层互斥，同一时刻只允许打开一个顶栏浮层。

### 4.2 不包含

- 不建设独立消息中心页面或消息历史列表。
- 不设计已读、未读、全部已读、删除、归档和免打扰。
- 不在铃铛内审核采购单、审核销售单、确认出入库、删除或作废业务数据。
- 不提供全文搜索、复杂筛选、批量处理、负责人转派和超时升级。
- 不提供 WebSocket、SSE、邮件、短信、企业微信等实时或站外推送。
- 不展示经营趋势、商品排行、供应商履约等工作台分析内容。

## 6. 功能说明

### 6.1 待处理数量徽标

- 用户目标：无需打开弹层即可判断是否存在待处理事项。
- 数据来源：`GET /dashboard/notifications` 返回的 `pendingCount`。
- 页面表现：`1` 至 `99` 显示实际数字，超过 99 显示 `99+`，为 0 时隐藏。
- 业务口径：徽标表示待处理业务事项数量，不表示未读消息数量；打开弹层不会清零。
- 无障碍文案：铃铛需要提供“通知，当前有 N 项待处理”一类可读标签。

### 6.2 通知弹层

- 用户目标：快速了解发生了什么、影响什么以及下一步去哪里处理。
- 前置条件：用户已登录并进入主布局。
- 页面表现：弹层右对齐铃铛，头部展示“待办与预警”、待处理数量和刷新状态，中部展示最多 8 条紧凑列表，底部展示“进入工作台查看全部”。
- 排序规则：后端先按 `sortWeight` 升序，再按 `priority`、处理模式和发生时间排序；前端仅做相同规则的兜底排序。
- 操作步骤：点击铃铛打开弹层；阅读摘要；点击“去处理”或“查看详情”；路由跳转成功后关闭弹层。
- 成功结果：用户到达与待办匹配且有权限访问的页面。
- 失败处理：接口失败时保留已有缓存数据并提示刷新失败；没有缓存时展示错误说明和“重新加载”。

### 6.3 数据刷新

- 主布局首次加载后请求一次通知摘要。
- 用户打开铃铛时，如果从未加载或缓存已超过 60 秒，则刷新数据；缓存未过期时直接展示，避免每次点击都阻塞弹层。
- 页面从后台恢复到前台且缓存已超过 60 秒时允许刷新一次。
- 当前阶段不持续轮询；用户完成业务后，下一次满足刷新条件时由后端最新状态更新数量和列表。
- 刷新过程中保留旧数据并显示轻量刷新状态，禁止弹层内容闪空。

### 6.4 待办处理边界

- `AUTO`：显示“去处理”，跳转 `route` 对应业务页面；业务状态完成后待办自动消失或数量变化。
- `TRACKED`：显示“查看详情”，跳转工作台查看异常证据；不在铃铛显示“完成处理”。
- 铃铛内不存在提交 DTO，所有字段均为服务端返回的只读展示字段。

## 7. 字段和信息展示

| UI 标签 | API/schema 字段 | 类型 | 来源 | 可编辑 | 空值展示 | 规则 |
| --- | --- | --- | --- | --- | --- | --- |
| 刷新时间 | `refreshedAt` | string | 后端生成 | 否 | `-` | 表示本次通知摘要生成时间 |
| 待处理数量 | `pendingCount` | integer | 后端按权限聚合 | 否 | `0` | 徽标最大显示为 `99+`，不是未读数 |
| 高优先级数量 | `highPriorityCount` | integer | 后端按权限聚合 | 否 | `0` | 用于头部风险提示，不单独制造第二个徽标 |
| 是否还有更多 | `hasMore` | boolean | 后端计算 | 否 | `false` | 为 `true` 时底部文案提示进入工作台查看全部 |
| 待办标识 | `items[].todoId` | string | 后端稳定标识 | 否 | 不允许为空 | 前端不得转换为数值 |
| 业务标签 | `items[].businessLabel` | string | 后端按事件源返回 | 否 | `其他` | 优先使用后端标签，避免新增类型必须发版 |
| 标题 | `items[].title` | string | 后端聚合 | 否 | 不允许为空 | 一行展示，表达具体待办 |
| 影响说明 | `items[].description` | string | 后端聚合 | 否 | `暂无说明` | 最多展示两行，不能只写技术错误码 |
| 数量 | `items[].count` | integer | 后端聚合 | 否 | `0` | 表示该聚合待办包含的业务事项数 |
| 优先级 | `items[].priority` | enum | 后端计算 | 否 | `LOW` | `HIGH`、`MEDIUM`、`LOW` |
| 完成模式 | `items[].completionMode` | enum | 后端规则 | 否 | 不允许为空 | 决定“去处理”或“查看详情”动作 |
| 发生时间 | `items[].occurredAt` | string/null | 事件或异常记录 | 否 | 不展示 | 聚合状态类待办允许为空 |
| 业务路由 | `items[].route` | string | 后端返回内部路由 | 否 | `/dashboard` | 仅允许站内受控路由，前端仍执行权限守卫 |

## 8. 操作和状态流转

| 当前状态/模式 | 用户可执行操作 | 前置校验 | 二次确认 | 成功后状态 | 禁止操作 |
| --- | --- | --- | --- | --- | --- |
| `PENDING + AUTO` | 去处理 | 路由存在且用户有页面权限 | 否 | 由业务页面完成后自动更新 | 在铃铛直接审核或确认 |
| `PENDING + TRACKED` | 查看详情 | 当前用户有异常查看权限 | 否 | 由异常中心或后台任务更新 | 在铃铛手动完成异常 |
| 已完成或已忽略 | 不进入当前弹层 | 后端过滤 | 否 | 保持原状态 | 作为“未读消息”重新展示 |

## 9. 权限和数据范围

| 角色/权限范围 | 可见数据范围 | 可执行操作 | 禁止操作 |
| --- | --- | --- | --- |
| 普通业务用户 | 仅当前用户有查询/处理权限的模块待办 | 跳转有权限的业务页面 | 查看无权模块数量和摘要 |
| 主管/管理者 | 当前角色、部门或业务范围内待办 | 跳转复核或处理 | 绕过具体业务接口权限 |
| 系统管理员/异常处理人 | 被授权或被指派的系统异常摘要 | 进入工作台查看异常证据 | 向普通员工广播系统异常 |

权限裁剪必须由后端完成。前端菜单隐藏和路由守卫只作为体验与第二层保护，不能作为数据保密依据。

## 10. 异常、空态和边界

- 空数据：显示“当前没有待处理事项”，不显示徽标，不展示营销式插画。
- 加载中：首次加载使用紧凑骨架屏；后台刷新保留已有列表。
- 接口失败：有缓存时展示缓存并提示刷新失败；无缓存时展示重试入口。
- 无权限：接口返回空数组和 0，不泄露无权模块名称、数量或业务摘要。
- 路由失效：提示“该事项暂时无法打开”，保留弹层，不跳转 404。
- 长文本：标题单行省略，影响说明最多两行，完整证据前往工作台查看。
- 大数量：徽标显示 `99+`；弹层始终最多 8 条，不能通过无限滚动扩容。
- 重复事项：同一业务类型按后端聚合，不为同类单据生成大量重复行。

## 14. 跨模块接口收敛规则

以下规则适用于采购、销售、仓库和 AI 模块；产品模块与系统模块接口保持现状。

- 供应商和客户选择器复用各自分页查询接口进行远程搜索，不再维护全量 `options` 接口。
- 采购订单和销售订单列表只返回单头字段；查看、编辑、提交和审核前按订单 ID 获取包含 `items` 的详情，避免分页列表重复传输全部明细。
- 采购和销售列表上的状态数量由当前页 `records` 派生，不要求后端额外返回与当前页重复的 `summary`。
- 入库单和出库单是可创建、编辑、提交、确认的工作单；`/warehouse/stock-bills` 只返回已确认、已产生库存变化的只读库存流水。
- 单张工作单详情和动作统一使用 `/warehouse/work-bills/{workBillId}`；不得复用库存流水路径进行编辑、提交、确认或取消。
- 新建仓库工作单必须按方向调用 `/warehouse/inbound-bills` 或 `/warehouse/outbound-bills`，不再使用统一兼容创建接口。
- AI 定时任务保存产品、仓库和接收角色的稳定 ID，名称仅用于展示；输出形态只保留任务报告和对话卡片，不建立重复的通知输出体系。
- AI 工作框只有在调用采购单、入库单或出库单等对应业务接口成功后，才能显示“草稿已创建”或单据编号；没有持久化接口的操作只能标注为“本次预览”，不得伪装为已暂存或已保存。

## 15. 跨模块界面体验优化

### 15.1 目标与实施原则

- 目标用户仍为当前各模块已有角色；不新增角色、权限、字段、状态或接口。
- 优化重点是降低筛选、识别状态、定位关键列和选择下一步操作的成本，同时保持适合长时间办公的克制企业后台风格。
- 严格按 `shared → auth → dashboard → system → product → warehouse → purchase → sales → ai` 串行实施；当前模块完成构建、对应 smoke、浏览器 QA 和代码审查后，才能进入下一模块。
- `shared` 只承载无业务语义的动效规则、表格滚动反馈和通用行操作外壳；状态映射、权限判断、查询参数和业务 handler 必须保留在各模块。
- 普通动效以 `180ms-240ms` 的状态反馈为主，不使用纯装饰性连续动画；系统设置为减少动态效果时，功能和焦点顺序保持不变，动画立即完成或关闭。

### 15.2 模块范围矩阵

| 模块 | 本次优化 | 明确不改 | 主要验收 |
| --- | --- | --- | --- |
| `shared` | 动效 token、`prefers-reduced-motion`、共享汇总条、共享筛选面板、溢出内容提示、表格横向滚动边缘提示、通用行操作菜单 | 不承载业务状态、权限和请求 | 全量交付测试通过；共享组件具备语义结构、键盘焦点和响应式能力；普通/减弱动画均可用 |
| `auth/login` | 开发环境边界、显示密码、Caps Lock、错误和提交反馈、轻量入场动效 | 不改变登录接口和 token 处理 | 开发/生产文案正确；键盘可用；重复提交被阻止；重定向正确 |
| `dashboard` | 指标层级、趋势切换、待办下钻与刷新反馈 | 不在工作台复制采购、销售或仓储写操作 | 7/15/30 天切换无闪跳；待办只导航或展示证据；刷新状态明确 |
| `system/users` | 紧凑筛选、有效条件提示、行操作收纳 | 不改变查询参数、权限和批量操作规则 | 筛选与参数一一对应；权限、禁用态、确认和提交锁保持不变 |
| `product/products` | 桌面紧凑单行表格、行操作收纳 | 不改变产品字段、状态和接口；不提供无必要的列显示菜单 | 1440px 无固定列和横向滚动；操作不换行；加载和空态不漂移 |
| `warehouse/stock-bills` | 入/出库宽表、关键列与操作可见性、明细展开动效 | 不改变作业单状态机和确认规则 | 入库、出库双路由均通过；展开/收起无相邻行回跳；操作确认保持不变 |

### 15.3 通用交互与可访问性规则

- 行内只直接展示最高频且不会造成歧义的主操作；低频操作进入“更多操作”菜单。菜单只是入口收纳，不改变原有 `v-if`、disabled、loading、二次确认和业务 handler。
- 危险操作继续使用明确文案和二次确认，不因收纳进菜单而降低风险提示。
- 宽表必须在自身容器内横向滚动；只有仍可向对应方向滚动时才显示边缘提示。sticky 表头和后续固定列必须使用不透明背景及正确层级。
- 仅真实存在宽表横向浏览需求的页面提供列显示偏好。偏好仅保存在前端本地，使用带模块和版本的稳定 key；菜单只展示可显隐字段，不展示无操作价值的“固定关键列”。
- 加载、空数据、错误、成功和只读状态都必须有可见反馈；截图用于视觉证据，点击、loading、disabled、焦点和动画必须使用浏览器 DOM 或 computed-style 断言验证。

### 15.4 验收门禁

| 编号 | 验收点 | 通过标准 |
| --- | --- | --- |
| UIX-01 | 模块隔离 | 一次只修改并验收一个模块；共享能力先完成，业务模块只复用 |
| UIX-02 | 契约稳定 | `check:openapi` 通过；无新增或变更 API、DTO、数据库字段和状态枚举 |
| UIX-03 | 构建与回归 | 每模块 `build` 和对应 smoke 通过；shared 与最终阶段运行 `test:delivery` |
| UIX-04 | 桌面布局 | `1440×900` 与 `1280×720` 下无意外页面级横向溢出、遮挡或操作不可达 |
| UIX-05 | 动效 | 普通模式状态变化自然且无布局跳动；`prefers-reduced-motion: reduce` 下动画关闭或近零，功能保持正常 |
| UIX-06 | 键盘和焦点 | 筛选、菜单、表格操作、弹窗和登录主路径可通过键盘到达，焦点样式可见 |
| UIX-07 | 业务安全 | 权限、状态条件、提交锁、二次确认和写操作结果与优化前保持一致 |
| UIX-08 | 工作区保护 | 不修改或覆盖用户已有的 `erp-web/.env.development` 变更 |

### 15.5 待确认问题

当前没有阻塞首批模块实施的问题。供货产品入口在当前环境暂未复现跳转失败，进入该模块时需要结合用户实际入口继续取证；若全部真实入口均正常，则只补回归测试并如实记录，不做猜测性修改。若后续希望增加 AI 流式停止、服务端列偏好同步或跨设备个性化，需要先补充 API 与持久化契约，不纳入本轮视觉和交互优化。

### 15.6 2026-07-14 交互修复批次

- 部门管理和产品分类复用同一树表收起能力。收起过程中从点击前、动画中间帧、结束、折叠行移除到稳定窗口，页面与表格的横向宽度、滚动位置及可视单元格横坐标均不得跳变。
- 入库单和出库单复用同一明细收起能力，并按与树表相同的全过程标准验收；不得用隐藏水平溢出的方式掩盖布局变化。
- 普通动效应平滑完成；`prefers-reduced-motion: reduce` 下应快速稳定，且两种模式均不得出现横向平移。
- 固定列边缘层次由公共表格容器统一管理，仅在对应方向仍可滚动时显示；无滚动空间时不显示多余阴影，hover 不得引起布局位移。
- 产品档案和销售订单以 `1440×900` 扣除侧栏后的内容区为桌面基线，表格应满足 `scrollWidth <= clientWidth`，操作不换行、不重叠；较窄视口允许自然降级为表格内部横向滚动，不通过压缩字体或隐藏关键字段伪造适配。
- 产品档案移除固定列和列显示能力，包括入口、偏好读写与废弃本地键；长文本省略时仍需提供 Tooltip、详情或可访问名称。
- 入库单、出库单保留宽表横向滚动并提供模块内聚的列显示能力。两类页面复用列定义逻辑，但存储键按页面类型隔离并带版本；展开控制、单号、状态、关键数量和操作列始终可见。
- 筛选区优化优先覆盖本批触达页面，统一标签、间距、控件高度、查询/重置主次、焦点和响应式折行；不得改变查询字段与查询参数的一一对应关系。

本批仍按模块串行推进：每个模块的契约检查、构建、目标 smoke、普通/减弱动效、截图与 DOM 证据、独立审查全部通过后，才能进入下一模块。

### 15.7 2026-07-14 全局一致性补充

- 所有业务列表页复用共享汇总条和筛选面板，统一卡片层级、标签、控件高度、焦点样式、响应式折行及“重置 → 查询”的操作顺序；页面仅维护业务字段、查询参数和事件。
- 左侧导航展开子项在默认、悬停、聚焦和当前页状态下必须保持与深色背景足够的文字对比度。
- 产品档案、销售订单和采购订单在桌面基线下均不使用固定列；无实际横向浏览需求的页面不提供列显示入口。
- 入库单、出库单保留宽表字段选择能力，菜单仅列出真实可选字段，显示当前选择数量，支持恢复默认，并保持入库与出库偏好隔离。

- 列表筛选字段统一使用共享的 `compact / standard / wide` 三档展示宽度，由页面按字段内容声明；共享组件只负责尺寸 token、舒适间距、自动折行和移动端单列，不识别业务字段，也不允许业务页面用等分网格把短字段拉伸为大输入框。
