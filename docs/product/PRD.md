## 2. 产品定位

启衡 ERP 的通知铃铛是登录用户在任意业务页面快速发现“当前需要我处理或关注什么”的轻量入口。它聚合采购、销售、仓储、库存和系统异常等跨模块事项，但不替代工作台和具体业务页面。

核心价值：

- 让采购、销售、仓库、管理者和系统管理员及时发现与自己有关的阻塞事项和风险。
- 用一个轻量弹层提供业务摘要和明确去向，减少用户逐个进入模块检查状态的成本。
- 复用工作台待办口径和权限裁剪，避免铃铛与工作台产生两套互相冲突的数据。

当前阶段不建设独立消息中心，不维护用户级已读/未读历史，不新增消息表，不提供站外推送。

## 4. 功能范围

### 4.1 包含

- 顶栏铃铛展示待处理数量徽标，数量超过 99 时显示 `99+`，数量为 0 时不显示徽标。
- 点击铃铛打开右对齐弹层，展示当前用户可见且状态为 `PENDING` 的前 8 条待办。
- 待办覆盖采购、销售、仓储、库存、复核风险和系统异常等可扩展业务类型。
- 每条待办展示业务标签、优先级、标题、待处理数量、简短影响说明和明确动作。
- `completionMode=AUTO` 的事项点击“去处理”后跳转接口提供的内部业务路由，由业务状态变化自动完成。
- `completionMode=TRACKED` 的系统异常点击“查看详情”后进入工作台异常详情，不在铃铛中直接完成。
- 弹层底部提供“进入工作台查看全部”，用于查看完整待办和证据。
- 支持加载、空数据、接口失败、重试和缓存数据过期状态。
- 用户菜单和通知弹层互斥，同一时刻只允许打开一个顶栏浮层。

### 4.2 不包含

- 不建设独立消息中心页面或消息历史列表。
- 不设计已读、未读、全部已读、删除、归档和免打扰。
- 不在铃铛内审核采购单、审核销售单、确认出入库、删除或作废业务数据。
- 不提供全文搜索、复杂筛选、批量处理、负责人转派和超时升级。
- 不提供 WebSocket、SSE、邮件、短信、企业微信等实时或站外推送。
- 不展示经营趋势、商品排行、供应商履约等工作台分析内容。

## 6. 功能说明

### 6.1 待处理数量徽标

- 用户目标：无需打开弹层即可判断是否存在待处理事项。
- 数据来源：`GET /dashboard/overview` 响应中的 `pendingCount`,与工作台首屏共用同一份聚合。
- 页面表现:`1` 至 `99` 显示实际数字,超过 99 显示 `99+`,为 0 时隐藏;overview 数据未就绪时整个铃铛图标不渲染。
- 业务口径:徽标表示待处理业务事项数量,不代表未读消息数量;打开弹层不会清零。
- 无障碍文案:铃铛需要提供"通知,当前有 N 项待处理"一类可读标签;只要工作台概览已加载，铃铛始终保留。`access.todos.state === 'DENIED'` 仅表示当前角色没有可见待办，弹层展示空态，不再作为独立授权或隐藏图标的条件。

### 6.2 通知弹层

- 用户目标:快速了解发生了什么、影响什么以及下一步去哪里处理。
- 前置条件:用户具备 `dashboard:overview:query`、已登录并进入主布局，且 overview 已加载完成。
- 页面表现:弹层右对齐铃铛,头部展示"待办与预警"和待处理数量,中部展示最多 8 条紧凑列表,底部展示"前往工作台查看完整依据"按钮。
- 数据来源:铃铛条目直接复用 `overview.todos`,前端取每条的 7 个基础字段(`todoId / businessType / businessLabel / title / description / count / priority`)渲染;不调用独立通知接口。
- 排序规则:复用工作台返回的 `sortWeight` 升序;前端只做兜底排序,不引入额外权重。
- 操作步骤:点击铃铛打开弹层;阅读摘要;点击任一条目;前端关闭弹层并 `router.push({ path: '/dashboard', query: { todoId } })`。
- 成功结果:工作台 mount 时读取 `route.query.todoId`,命中 `todos` 后打开同一条详情弹窗。
- 失败处理:overview 加载失败时铃铛不渲染、工作台显示错误态与 toast 提示,不单独设计铃铛错误态。

### 6.3 数据刷新

- 主布局挂载时通过 Pinia `dashboardOverviewStore.refresh()` 拉取一次 overview,顶栏和工作台共用。
- store 内部按 60 秒节流:同一会话内反复打开铃铛、切回标签页不会重复请求;进入工作台 mount、用户主动点刷新按钮、错误态重试三种场景使用 `refresh(force=true)` 绕过节流。
- overview 加载完成前铃铛图标整体不渲染(`v-if="store.overview"`),避免出现"图标在但无数据"的中间态。
- 停留期间 store 不主动刷新,等用户主动或路由切换触发 mount。
- 登录、退出和会话失效必须清除 overview 与节流时间；旧会话请求的成功、失败和结束回调不得覆盖新账号的数据或加载状态，旧会话 401 不得注销新账号。
- 布局和主页同时加载时等待同一请求。后台刷新失败保留上次数据并提示“刷新失败，当前显示上次数据”，不能将失败当作待办数为零；首次失败仍进入工作台错误态。

### 6.4 待办处理边界

- 铃铛内不存在提交 DTO,所有字段均为服务端返回的只读展示字段。
- 铃铛条目点击统一进入 `/dashboard?todoId={todoId}`,工作台详情弹窗打开后再按 `completionMode` 决定动作。
- 工作台详情中的 `AUTO` 待办提供"前往完成"按钮,跳转由前端受控的 `TODO_NAVIGATION` 映射维护;`TRACKED` 仅展示证据,不提供完成按钮。

## 7. 字段和信息展示

| UI 标签 | API/schema 字段 | 类型 | 来源 | 可编辑 | 空值展示 | 规则 |
| --- | --- | --- | --- | --- | --- | --- |
| 刷新时间 | `refreshedAt` | string | 后端生成 | 否 | `-` | 表示本次 overview 聚合时间,顶栏和工作台共用 |
| 待处理数量 | `pendingCount` | integer | 后端按权限聚合 | 否 | `0` | 徽标最大显示为 `99+`,不是未读数;overview 数据未就绪时铃铛图标整体不渲染 |
| 待办标识 | `todos[].todoId` | string | 后端稳定标识 | 否 | 不允许为空 | 铃铛点击时原样写入 `/dashboard?todoId={todoId}`,不得改为业务页面路由 |
| 业务标签 | `todos[].businessLabel` | string | 后端按事件源返回 | 否 | `其他` | 优先使用后端标签,避免新增类型必须发版 |
| 标题 | `todos[].title` | string | 后端聚合 | 否 | 不允许为空 | 一行展示,表达具体待办 |
| 影响说明 | `todos[].description` | string | 后端聚合 | 否 | `暂无说明` | 最多展示两行,不能只写技术错误码 |
| 数量 | `todos[].count` | integer | 后端聚合 | 否 | `0` | 表示该聚合待办包含的业务事项数 |
| 优先级 | `todos[].priority` | enum | 后端计算 | 否 | `LOW` | `HIGH`、`MEDIUM`、`LOW` |
| 完成模式 | `todos[].completionMode` | enum | 后端规则 | 否 | 不允许为空 | 仅在工作台详情中决定"前往完成"或"仅查看"动作 |
| 详情定位 | `todos[].todoId` | string | 后端稳定标识 | 否 | 不允许为空 | 铃铛和工作台详情共用同一定位字段 |

## 8. 操作和状态流转

| 当前状态/模式 | 用户可执行操作 | 前置校验 | 二次确认 | 成功后状态 | 禁止操作 |
| --- | --- | --- | --- | --- | --- |
| `PENDING + AUTO`(铃铛内) | 查看工作台待办详情 | 具备 `dashboard:overview:query` 及目标业务页面权限 | 否 | 跳转 `/dashboard?todoId={todoId}`,工作台打开同一条详情 | 在铃铛直接审核或确认 |
| `PENDING + TRACKED`(铃铛内) | 查看工作台待办详情 | 具备 `dashboard:overview:query` 及系统异常查看权限 | 否 | 由异常中心或后台任务更新 | 在铃铛手动完成异常 |
| `PENDING + AUTO`(工作台详情) | 前往完成 | 路由存在且用户有页面权限 | 否 | 由业务页面完成后自动更新 | 在详情弹窗内直接审核 |
| `PENDING + TRACKED`(工作台详情) | 查看证据 | 当前用户有异常查看权限 | 否 | 由异常中心或后台任务更新 | 在详情弹窗内手动完成异常 |
| 已完成或已忽略 | 不进入当前弹层 | 后端过滤 | 否 | 保持原状态 | 作为“未读消息”重新展示 |

## 9. 权限和数据范围

| 角色/权限范围 | 可见数据范围 | 可执行操作 | 禁止操作 |
| --- | --- | --- | --- |
| 普通业务用户 | 仅当前用户有查询/处理权限的模块待办 | 跳转有权限的业务页面 | 查看无权模块数量和摘要 |
| 主管/管理者 | 当前角色、部门或业务范围内待办 | 跳转复核或处理 | 绕过具体业务接口权限 |
| 系统管理员/异常处理人 | 被授权或被指派的系统异常摘要 | 进入工作台查看异常证据 | 向普通员工广播系统异常 |

权限裁剪必须由后端完成。前端菜单隐藏和路由守卫只作为体验与第二层保护，不能作为数据保密依据。

`dashboard:overview:query` 是工作台主入口权限,顶栏铃铛复用 `GET /dashboard/overview` 的待办摘要;系统异常类待办额外需要 `dashboard:exception:query` 才能展示。具体待办内容仍按业务权限在该接口内裁剪。

## 10. 异常、空态和边界

- 空数据：显示“当前没有待处理事项”，不显示徽标，不展示营销式插画。
- 加载中：首次加载使用紧凑骨架屏；后台刷新保留已有列表。
- 接口失败：有缓存时展示缓存并提示刷新失败；无缓存时展示重试入口。
- 无权限：接口返回空数组和 0，不泄露无权模块名称、数量或业务摘要。
- 路由失效：提示“该事项暂时无法打开”，保留弹层，不跳转 404。
- 长文本：标题单行省略，影响说明最多两行，完整证据前往工作台查看。
- 大数量：徽标显示 `99+`；弹层始终最多 8 条，不能通过无限滚动扩容。
- 重复事项：同一业务类型按后端聚合，不为同类单据生成大量重复行。

| 编号 | 验收点 | 验收方式 | 通过标准 |
| --- | --- | --- | --- |

| NTF-05 | 业务跳转 | 浏览器真实点击 | `AUTO` 待办进入正确业务页面并关闭弹层 |
| NTF-06 | 异常边界 | 浏览器真实点击 | `TRACKED` 只查看详情，不出现完成处理按钮 |
| NTF-07 | 非未读语义 | 交互验证 | 打开或关闭弹层不会清零待处理数量 |
| NTF-08 | 数据刷新 | 请求时间与 UI 状态验证 | 缓存未过期直接展示，过期后刷新且旧数据不闪空 |
| NTF-09 | 加载/错误/空态 | Mock 三种响应 | 状态均可见且错误态可重试 |
| NTF-10 | 响应式和键盘 | 1440×900、较小桌面视口和键盘验证 | 弹层不出视口，Esc 可关闭，焦点可达 |

## 14. 跨模块接口收敛规则

以下规则适用于采购、销售、仓库和 AI 模块；产品模块与系统模块接口保持现状。

- 供应商和客户选择器复用各自分页查询接口进行远程搜索，不再维护全量 `options` 接口。
- 采购订单和销售订单列表只返回单头字段；查看、编辑、提交和审核前按订单 ID 获取包含 `items` 的详情，避免分页列表重复传输全部明细。
- 采购和销售列表上的状态数量由当前页 `records` 派生，不要求后端额外返回与当前页重复的 `summary`。
- 入库单和出库单是可创建、编辑、提交、确认的工作单；`/warehouse/stock-bills` 只返回已确认、已产生库存变化的只读库存流水。
- 入库单详情和动作使用 `/warehouse/inbound-bills/{inboundBillId}`，出库单详情和动作使用 `/warehouse/outbound-bills/{outboundBillId}`；不得复用库存流水路径进行编辑、提交、确认或取消。
- 新建仓库工作单必须按方向调用 `/warehouse/inbound-bills` 或 `/warehouse/outbound-bills`，不再使用统一兼容创建接口。
- 人工补录的采购入库、销售退货入库在 `DRAFT` 可修改来源对象和来源单号；来源单号与新增态一致，仅支持搜索选择已有来源单据。调整入库、调整出库在 `DRAFT` 可修改来源仓库，但调整单号保持不变；系统生成单和 `PENDING_CONFIRM` 必须锁定来源。来源变更只更新追溯信息，不改变产品明细和库存。
- 系统生成的采购入库单在列表可选列和详情中只读展示采购订单预计到货日期快照；销售退货、调整入库和手工补录显示为空，任何入库新增或编辑表单都不得提交该字段。
- AI 定时任务保存产品、仓库和接收角色的稳定 ID，名称仅用于展示；输出形态只保留任务报告和对话卡片，不建立重复的通知输出体系。
- AI 工作框只有在调用采购单、入库单或出库单等对应业务接口成功后，才能显示“草稿已创建”或单据编号；没有持久化接口的操作只能标注为“本次预览”，不得伪装为已暂存或已保存。

### 14.1 采购订单取消规则

- `DRAFT`、`SUBMITTED` 采购订单可取消；`APPROVED` 采购订单仅在全部关联采购入库工作单尚未确认、采购明细累计入库数量均为 0 时可取消。`PARTIAL_INBOUND`、`INBOUND_DONE` 及存在任一已确认入库工作单的订单必须拒绝取消。
- 前端在“更多操作”中为未履约的已审核订单仅提供“取消采购单”，不提供编辑或审核；二次确认须明确说明将作废待确认入库工作单，且不会产生库存变动。操作成功后以接口返回后的刷新结果为准。
- 后端在同一事务内核验入库事实、作废关联的 `DRAFT`/`PENDING_CONFIRM` 入库工作单并将订单更新为 `CANCELLED`；取消与入库确认使用订单维度串行锁及乐观锁，确认竞态或版本冲突返回 `409`。
- 已取消订单重复取消按幂等成功处理，不重复作废工作单；前端不自行修改库存或累计入库数量。

验收场景：已审核且未入库的订单可从行操作确认取消，关联待确认入库工作单同步作废且库存/库存流水不变；部分或全部入库订单不显示取消入口，直接调用接口返回冲突；重复取消不会重复产生副作用。

## 15. 跨模块界面体验优化

### 15.1 目标与实施原则

- 目标用户仍为当前各模块已有角色；不新增角色、权限、字段、状态或接口。
- 优化重点是降低筛选、识别状态、定位关键列和选择下一步操作的成本，同时保持适合长时间办公的克制企业后台风格。
- 严格按 `shared → auth → dashboard → system → product → warehouse → purchase → sales → ai` 串行实施；当前模块完成构建、对应 smoke、浏览器 QA 和代码审查后，才能进入下一模块。
- `shared` 只承载无业务语义的动效规则、表格滚动反馈和通用行操作外壳；状态映射、权限判断、查询参数和业务 handler 必须保留在各模块。

## 16. 采购退回

### 16.1 产品目标与范围

采购人员通过“采购业务 / 采购退回”登记已实际入库商品的退供应商申请，采购管理人员完成提交、审核或取消，仓库在审核通过后通过来源生成的采购退货出库单执行实际出库。

本期包含退回单列表、新增草稿、编辑草稿、详情、提交、审核通过、取消和删除草稿；不在采购退回页面直接扣减库存，不新增退款、结算或换货订单，不允许在部分出库后放弃剩余数量。

### 16.2 页面、角色与权限

| 页面/区域 | 入口 | 角色目标 | 权限 |

### 16.4 状态与动作

| 状态 | 页面文案 | 可见动作 | 结果与限制 |
| --- | --- | --- | --- |
| `DRAFT` | 草稿 | 编辑、提交、删除、取消 | 提交前校验日期、明细和剩余可退数量；删除仅逻辑删除主表并物理删除明细 |
| `SUBMITTED` | 待审核 | 编辑、审核通过、取消 | 拥有对应 `*:manage` 权限时可完整编辑并保持待审核；审核数量不得超过申请数量；不通过可取消并写入 `status_reason` |
| `APPROVED` | 待退货出库 | 查看、取消 | 审核通过生成 `PURCHASE_RETURN_ORDER` 来源的待确认出库单；仅全部已处理数量为 0 时可取消 |
| `PARTIAL_EXECUTED` | 退货出库中 | 查看 | 不允许取消或放弃剩余数量，仓库必须继续处理 |
| `COMPLETED` | 已完成 | 查看 | 终态，只读 |

## 工作台访问状态与空态规范

- 经营趋势继续使用现有 `trendPermissions` 契约和页面表现，本规范不改变趋势图、时间范围或曲线展示。
- 顶部指标和业务待办、订单流转、销售商品排行、供应商履约、库存预警统一由 `access` 返回 `ALLOWED`、`EMPTY`、`DENIED` 状态；前端不得以 `0` 或空数组推断权限。
- `DENIED` 保留卡片或面板位置，显示“暂不可查看 / 当前角色暂不支持查看此模块”，不显示数值、金额、环比、技术权限码或详情入口。后端指标字段必须返回 `null`，不得把无权限业务数据钳制为 `0`。
- `EMPTY` 表示用户已获准查看但其可见范围暂无数据；真实业务值为 `0` 的指标仍按数值展示，不能判为 `EMPTY`。
- `ALLOWED` 表示接口已返回当前账号可查看口径的数据，不表示全局完整业务范围；比较口径不可用时，环比字段可以返回 `null`。
- 指标 `comparisonState` 区分 `AVAILABLE`（显示环比）、`NO_BASELINE`（暂无可比基线）与 `UNAVAILABLE`（对比数据暂不可用）。无指标权限时为 `null`；Redis月基线读取失败尝试数据库回算，只有回算失败才标记不可用，本期真实值保留。昨日状态快照无法用今天状态回算，读取失败标记不可用，正常缺快照标记无基线。
- 待办只返回数量大于 0 的项目，按后端 `sortWeight` 递增连续排列，不为固定待办类型保留空槽。

## 采购评分快照与库存安全库存（2026-10-07）

- 采购人员在新增和编辑订单时看到的是当前供货产品推荐分，仅供选择参考，不进入提交DTO；未选择产品或供货评分未就绪显示 `—`，不假填零。
- 审核人在采购审核的同一事务中冻结各明细的当前推荐分；审核后显示“审核时推荐分”，不随供货产品评分变化。没有有效评分保持 `null`，有效零分保留 `0`，评分不可用不阻止正常采购审核。历史订单空快照不猜测回填。

| 主动停止 | 取消请求，不伪装为成功；回读历史，不保存半截助手回答 |
| 切换会话或离开页面 | 取消旧流，旧请求不得污染新会话 |
| 模型未启用 | 发送返回 503 并提示能力不可用，ERP 其他页面仍可使用 |

会话创建、改名、删除和历史分页保留原有归属校验、确认和竞态保护。JSON 使用 /ai/assistant/messages；SSE 使用 /ai/assistant/messages/stream，fetch POST 携带登录返回的动态认证头。

定时经营任务、业务快捷分析和工作框暂不开放入口；图表组件保留，后续接入可信业务数据。最新基础需求替代本文旧 UI 优化章节中“不提供流式停止”的阶段限制。
