# 项目开发规范

- 开发时先核对当前代码、业务流程、数据库结构及接口契约，模块分工见[总体架构](architecture/overview.md)。
- 遵循 [后端](development/backend.md)、[前端](development/frontend.md)、[数据库](development/database.md)和[接口](development/api.md)规范，涉及公共组件与样式时同步查阅原前端规范和样式文件。
- 涉及权限、业务状态、金额数量、事务和并发时，以服务端规则为准，不能用前端显示或直接修改数据库绕过业务处理。
- AI 的只读查询须遵循现有权限范围和 SQL 守卫，业务写入须经过受控业务流程；具体实现见 [AI 架构](architecture/ai.md)。
- 使用隔离环境测试，不提交真实密码、令牌、私钥、个人信息或未脱敏业务数据。提供者明确授权的虚构测试数据应标明用途，不得作为生产账号。
- 按影响运行构建和测试，记录未验证范围；更改表结构、接口、配置时同步更新文档。

## 前端开发强制前置流程

- 修改前按影响范围执行 `npm run preflight:frontend -- <scope>`，范围和前置条件见[前端开发规范](development/frontend.md)。
- 使用项目提供的提交前检查，禁止使用 `--no-verify` 绕过检查；遇到失败应定位原因并记录尚未通过的项目。
