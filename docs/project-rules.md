# 项目开发规范

本文档定义启衡 ERP 项目的全局开发规范，所有开发者（包括 AI Agent）必须遵守。

## 1. 项目计划优先

所有代码实现、模块设计、接口设计、权限设计、AI Tool 设计、定时任务设计和业务流程设计，都以项目计划文件为主要依据：

```text
docs/erp-project-plan.md
```

必须遵守：

- 严格按照项目计划中的技术选型、模块结构、业务流程进行开发。
- 不得擅自引入计划之外的技术栈、框架或架构模式。
- 不得擅自把模块化单体改成微服务。
- 不得让 AI Tool 绕过业务 Service、权限校验或数据权限过滤。
- 不得让大模型直接执行任意 SQL 或绕过受控 Tool 查询业务数据。

## 2. 开发优先级

```text
阶段 1：基础框架
阶段 2：Sa-Token 权限
阶段 3：ERP 核心业务
阶段 4：RAG 知识库
阶段 5：自然语言业务查询
阶段 6：Python 分析
阶段 7：AI 业务闭环
```

不得跳过基础权限、核心业务和审计设计，直接实现后续 AI 能力。

## 3. 计划不一致时的处理

发现实际需求与项目计划不一致时，必须先暂停修改，向用户说明：

1. 当前不一致点
2. 影响哪些模块或流程
3. 可选方案及优缺点
4. 推荐方案

用户确认后再修改项目计划文件，然后按新计划实现。不得擅自修改计划或实现与计划不一致的功能。

## 4. 权限与 AI 安全

- 普通接口和 AI Tool 使用同一套权限体系。
- AI Tool 调用时必须携带当前登录用户上下文。
- AI Tool 必须执行权限校验和数据权限过滤。
- 涉及敏感字段时必须脱敏或字段权限判断。
- AI Tool 调用必须记录审计日志。
- PythonTool 分析结果只作为建议，不得直接修改业务数据。
- 采购单生成、库存调整等业务动作必须由用户确认后执行。

## 6. 通用行为要求

- 先阅读项目计划和规范，再进行开发。
- 先确认模块边界，再修改代码。
- 优先选择简单、稳定、符合计划的实现方式。
- 不做与当前任务无关的重构。
- 不擅自删除用户已有内容。
- 遇到架构偏离、计划冲突或权限风险时，先说明，再等待用户决定。
- 优先遵循现有架构、命名和目录结构，做最小必要修改。
- 先定位根因再修复；完成后报告修改内容、验证结果和剩余风险。
