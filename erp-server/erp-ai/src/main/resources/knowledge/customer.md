# 客户业务口径

> 适用范围：客户档案与客户信用额度。
> 关联文档：客户在下单与停用上的约束见 `sales.md`、`return.md`；数量放大与 `deleted` 清单见 `shared.md`。

## 一、速查（先看这几条）

1. `credit_limit` 是 **×100 整数存储的金额**（单位元），与数量字段同口径但含义不同，别当成数量用。
2. **额度只是档案字段**：当前代码在下单路径**不校验、不占用、不扣减**信用额度（只在客户新增/编辑/查询里出现）。要判断"是否超额度"必须自己按销售订单金额现算，并说明这是推导值。
3. `status` 是 `1` 启用 / `0` 禁用（**数字，不是英文枚举**）；逻辑删除另有 `deleted`。
4. **客户只与销售侧关联**——采购侧没有客户概念；客户与产品的唯一连接点是销售订单明细。
5. 客户停用后**不能新增销售单据**；既有订单的退货不受此限制。

## 二、对象与字段

### 2.1 客户档案 `customer`

| 字段 | 说明 |
|---|---|
| `customer_code` | 客户编码，唯一 |
| `customer_name` | 客户名称，必填 |
| `contact_name` / `contact_phone` | 联系人与联系电话，必填 |
| `address` | 地址，必填 |
| `credit_limit` | 客户信用额度，`BIGINT`，**×100 整数存储**（金额，单位元） |
| `status` | `1` 启用 / `0` 禁用（`TINYINT`） |
| `remark` | 备注 |
| `deleted` | 逻辑删除 |

### 2.2 引用关系

| 表 | 引用字段 | 语义 |
|---|---|---|
| `sales_order` | `customer_id` / `customer_code` / `customer_name` | 后两个是**下单快照** |
| `return_order` | `party_id` / `party_code` / `party_name`（`return_type = SALES_RETURN`） | 销售退货的客户由原订单带出，**不能在退货单里单独更换** |

## 三、状态与启停保护

- **停用（`status = 0`）后不能新增销售单据**；既有订单的退货不受限制。
- **停用被未完成退货阻挡**：存在 `status NOT IN ('COMPLETED','CANCELLED')` 的销售退货单时不能停用（见 `return.md`）。
- 建单时客户必填、必须存在且**启用**；提交与审核时**重新校验启用状态**（草稿期间主数据可能已变，见 `sales.md`）。

## 四、关键口径

### 4.1 额度口径

- `credit_limit` 与其它数量字段**同为 ×100 整数口径**，但它是**金额**不是数量——还原时除以 100 得元。
- `credit_limit` 是**客户级单一阈值**，与安全库存一样不按仓库、销售员或产品拆分。
- 与销售额比较时，销售额取 `sales_order.total_amount`（分），两者口径一致（都是 ×100），但**含义不同**：一个是累计成交金额，一个是信用额度上限。

### 4.2 时间归期

客户本身没有时间维度指标；按客户统计销售额时，归期用 `sales_order.approved_at`（见 `sales.md` §5.1），不要用客户记录的 `create_time`。

## 五、业务定义

### 5.1 信用额度

**系统里的信用额度只是一个档案数值**，没有"已用额度""可用额度"字段，也没有下单拦截。若业务上要算：

```
已用额度（分） = 该客户在统计窗口内、状态属于 APPROVED / PARTIAL_OUTBOUND / OUTBOUND_DONE 的销售订单 total_amount 合计
可用额度（分） = credit_limit − 已用额度（分）
```

这只是**按当前口径推导的参考值**，不是系统事实：未计入未出库的取消单、退货冲减、跨期口径都可能不同。要用它下结论时，必须在 `instruction` 或报告里写清推导口径与局限。

## 六、常见错误

1. 把 `credit_limit` 当数量或当"元"直接展示 → 它是 ×100 的金额，要除以 100。
2. 以为下单会被信用额度拦截 → 代码没有这个校验。
3. 以为系统里有"已用额度"字段 → 没有，只能按销售订单现算并说明口径。
4. 用 `status` 的英文枚举去过滤 → 它是 `1`/`0` 数字。
5. 漏 `deleted = 0` → `customer` 里存在逻辑删除数据。
6. 在采购分析里加客户维度 → 采购侧没有客户概念。
7. 用客户主数据当前名称覆盖历史单据快照 → 单据上的 `customer_name` 是创建时快照。

## 七、写 `instruction` 时的提醒

1. 客户范围要写明「只统计启用、未删除的客户」；用业务说法表达，列名不要写进 `instruction`。
2. 涉及额度就标单位（`credit_limit` 是分口径整数，展示换算为元）。
3. 要"客户欠款/额度使用"这类指标时，明确写出推导口径（哪些订单状态算入、按哪个时间归期、是否含退货），不要只写指标名。
4. 客户与产品的连接只经由销售订单，跨模块统计要说明走的是销售侧路径。
