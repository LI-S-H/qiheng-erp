# 产品业务口径

> 适用范围：产品档案、产品分类、数量精度、安全库存、单位与启停保护。
> 关联文档：库存三口径与库存健康见 `warehouse.md`；供货关系与最小起订量见 `supplier.md`；数量放大与快照通用规则见 `shared.md`。

## 一、速查（先看这几条）

1. **安全库存在 `product.safety_stock_qty`（产品级，不在库存表）**，×100 整数，与 `warehouse_stock.stock_qty` 同口径可直接比。
2. **不存在 `min_stock_qty` 字段**。`product.safety_stock_qty` 是安全库存（产品级阈值），`supplier_product.min_order_qty` 是最小起订量（供应商 × 产品级），别搞混。
3. `quantity_precision`（0-2）决定数量允许的小数位；**明细上的精度是下单时快照，产品后来改精度不回写历史单据**。
4. **参考采购价 / 参考销售价是 `DECIMAL(18,2)` 单位元，不放大**，与"分"口径的金额字段不同，不能直接比。
5. `status` 是 `1` 启用 / `0` 禁用（**数字，不是英文枚举**）；逻辑删除另有 `deleted`。
6. **单位是自由文本，没有单位表、没有换算机制**——不同单位不能汇总数量。
7. 产品编码 `P` + 6 位序号，后端生成、**创建后不可修改**。

## 二、对象与字段

### 2.1 产品档案 `product`

| 字段 | 说明 |
|---|---|
| `product_code` | 产品编码（`P` + 6 位序号），后端生成，**创建后不可修改**，唯一 |
| `product_name` | 产品名称，必填 |
| `category_id` | 分类 id，**可空**（暂不分类）；**无物理外键** |
| `brand_name` | 品牌。**MVP 不设品牌表**，直接放产品表 |
| `unit_name` | 单位名称，默认 `件`。**自由文本，不是受控主数据** |
| `quantity_precision` | **数量小数位，0-2**。离散单位通常 0，kg/L 等可拆分单位按业务设 |
| `specification` | 规格型号。**MVP 不设规格表** |
| `barcode` | 条码，可空，唯一 |
| `reference_purchase_price` | 参考采购价，`DECIMAL(18,2)`，**单位元，不放大** |
| `reference_sale_price` | 参考销售价，同上 |
| `safety_stock_qty` | 安全库存数量，`BIGINT`，**×100 整数存储**（12.50 存 1250） |
| `status` | `1` 启用 / `0` 禁用（`TINYINT`，**不是英文枚举**） |
| `deleted` | 逻辑删除，独立于 `status` |

**参考价只是参考**：真实成交价以采购/销售订单明细为准。参考采购价有**独立接口维护**，编辑接口不接收该字段；变更会触发所有供应该产品的供货关系评分重算。

### 2.2 产品分类 `product_category`

- 分类是层级结构，父级停用会**级联停用全部下级分类**，并把该分类及全部下级分类**直接关联的未删除产品统一设为停用**。
- **启用分类不会自动重新启用产品**；但启用产品的分类必须处于启用状态。

## 三、状态与启停保护

**停用前必须没有未完成业务引用**，"未完成"的状态集合：

| 单据 | 未完成状态 |
|---|---|
| 销售单 | `DRAFT` / `SUBMITTED` / `APPROVED` / `PARTIAL_OUTBOUND` |
| 采购单 | `DRAFT` / `SUBMITTED` / `APPROVED` / `PARTIAL_INBOUND` |
| 退货单 | `DRAFT` / `SUBMITTED` / `APPROVED` / `PARTIAL_EXECUTED` |
| 入库单 / 出库单 | `PENDING_CONFIRM` |
| 库存 | `locked_qty > 0`（有锁定库存） |

**停用后不能新增销售单据**（"产品已停用，不能下单"）。

**删除保护更严**：被销售明细、采购明细、退货明细、出入库明细、库存余额、供货关系任一引用的产品禁止删除；**批量删除中任一产品存在引用则整批拒绝**；只有启用状态的产品能被删除（要先停用）。

**⚠️ 一个已知的实现缺口**：文档写"产品停用后不能新增采购、销售单据"，但**代码在采购建单路径只校验产品存在与数量精度，没有校验 `product.status`**——产品状态在采购侧只在"建立供应商供货关系"时被拦。做采购建议时如果要把"产品已停用"当成硬约束，需要自己判断并说明这一点。

## 四、关键口径

### 4.1 数量精度 `quantity_precision`

**含义**：数量允许的小数位，0-2 位。精度 0 → 只能填整数；精度 2 → 最多两位小数。

**存储与校验分离**：库里数量统一按 ×100 整数存储，**小数位由精度快照决定**；把 ×100 整数还原成业务数量时用这个位数。

**强制校验点**：

| 场景 | 规则 |
|---|---|
| 产品新增/编辑 | 安全库存的小数位不得超过同请求声明的精度 |
| 采购下单（新增明细） | 客户端回传的精度必须与服务端产品精度**完全相等**，否则直接拒绝 |
| 采购下单（编辑已有明细） | 用**下单时的精度快照**，不用当前产品精度 |
| 销售下单 | 数量小数位不得超过产品精度 |
| 供货关系 | 最小起订量的小数位不得超过产品精度 |
| 退货单 | 按**来源明细的精度快照**校验 |

**明细的 `quantity_precision` 字段由服务端从产品主数据固化，不接受前端值。精度是历史快照**：查历史单据时读明细上的快照，不要回查当前产品覆盖历史规则。

### 4.2 单位

- 单位只是 `product.unit_name` 这个**自由文本标签**，**没有单位表、没有单位字典、系统里没有任何单位换算机制**。
- **不同单位不能汇总数量**：只有同单位明细才允许展示合计数量。回答"总共多少"时必须按同一产品 + 同一单位分组；跨产品跨单位只能给分项数量或条数，不能给无单位的合计数。

### 4.3 金额与价格

| 字段 | 口径 |
|---|---|
| `product.reference_purchase_price` / `reference_sale_price` | `DECIMAL(18,2)`，**元**，不放大 |
| 各类单据明细 `unit_price` / `total_amount` | `BIGINT`，**分** |

两者比较或换算成比例时必须先统一口径；`supplier.md` 的价格分就是"元参考价 vs 分报价"的例子。

## 五、业务定义

### 5.1 安全库存

- **产品级阈值**（一个产品只有一个值，不区分仓库），×100 整数，与 `warehouse_stock.stock_qty` 同口径。
- 比较对象是**单个 `(仓库, 产品)` 行的可用库存**，不是跨仓合计：

  ```sql
  WHERE (ws.stock_qty - ws.locked_qty) <= p.safety_stock_qty
  ```

  同一产品在 A 仓低于阈值、B 仓充足时，**A 仓仍判为低库存**。
- **系统实现就是拿"可用库存"与"账面口径的安全库存"比**（库存服务与工作台都是这个口径）。含义是：已被预占的量不再支撑新的销售，所以计入缺口。
- **⚠️ 但安全库存本身是账面口径**（与 `stock_qty` 同为 ×100），所以"锁定部分"会被算进缺口。做低库存判断时要写明用的是可用口径；报告里最好同时给出"账面 vs 安全线"的差额，避免读者把已锁定的量误读成可售量或损失量。
- 派生的库存健康状态（`OUT_OF_STOCK` / `NO_AVAILABLE` / `LOW_STOCK` / `NORMAL`）见 `warehouse.md` §5.1，不落库。
- 安全库存是**预警线**，不参与净缺口计算（见 `purchase.md` §5.4）。

### 5.2 最小起订量（与安全库存区分）

`supplier_product.min_order_qty` 是供应商 × 产品级的**下限**（×100），只代表"至少买这么多"，**不是包装倍数，也不是安全库存**。下单路径目前不强制校验它。

## 六、常见错误

1. 把安全库存当成**仓库级**阈值 → 它是产品级，一个产品一个值。
2. 去库存表找 `safety_stock_qty` 或 `min_stock_qty` → 都不在库存表，`min_stock_qty` 根本不存在。
3. 跨仓合计后与安全库存比 → 应逐 `(仓库, 产品)` 行比较。
4. 用当前产品精度校验历史单据 → 要用明细上的精度快照。
5. 把参考价（元）和单据金额（分）直接比或相加 → 口径不同。
6. 跨单位汇总数量 → 件和 kg 不能相加，系统也没有换算机制。
7. 以为 `status` 是英文枚举 → 它是 `1`/`0` 数字。
8. 以为产品停用后采购侧也会被拦 → 采购建单路径当前没校验 `product.status`。
9. 停用分类后以为能自动启用产品 → 启用分类不会重新启用产品。
10. 忘了限定"启用、未删除" → `product` 里一半以上是逻辑删除数据（见 `shared.md`），指标会成倍偏。

## 七、写 `instruction` 时的提醒

1. 安全库存在 `product` 表，比较前要 JOIN 库存表，并说明按 `(仓库, 产品)` 粒度。
2. 数量小数位由精度快照决定，写清"取整 / 保留几位"，并注明用的是单据快照精度还是当前主数据精度。
3. 不同单位不能汇总；跨产品汇总要按单位分组。
4. 产品范围要写明「只统计启用、未删除的产品」（`product` 表状态与逻辑删除两个字段都有）；**用业务说法表达，列名不要写进 `instruction`**。
5. 参考价是 `DECIMAL` 元，不放大；与其它金额字段比较前说明已统一口径。
6. 判低库存要写明用可用库存还是账面库存，不要只给一个数。
7. 数字必须标单位（数量业务单位、金额分或元、评分 0-100），同一需求内保持一致。
