# 采购业务口径

> 适用范围：采购订单、采购入库回写、供应商与供货关系、采购侧的延期与净缺口口径。
> 关联文档：库存三口径、锁定、滞销与周转见 `warehouse.md`；供应商评分公式与交付分见 `supplier.md`；数量放大、删除与日期通用口径见 `shared.md`；数量精度与安全库存字段见 `product.md`。

## 一、速查（先看这几条）

1. 采购状态名的中文最容易搞错：`SUBMITTED` 是**待审核**，`APPROVED` 是**待入库**（不是"已审核/已完成"）。
2. **审核不改库存**——库存与流水是仓库确认入库时才产生的。
3. **在途采购量没有对应字段**，只能用 `quantity − inbound_qty` 按状态算，且有四个坑（见 §4.3）。
4. `inbound_qty` 是**累计已入库量**，不是本次入库量；不要双重减法。
5. **延期清单只算已完全入库的订单**；"超过预计到货日还没到货"是另一个问题（逾期未到），两者不能合成一个数（见 §5）。
6. `CANCELLED` 不参与延期与交付统计；表里的 `cancel_affects_delivery_score` **当前代码没有使用**。
7. 统计成交额用 `approved_at`，不用 `create_time`。
8. **净缺口 = max(0, 需求 − 可用库存 − 期内可信可达采购量)**，安全库存不参与（见 §5.4）。
9. 明细表 `purchase_order_item` **没有 `deleted`**，加了会 SQL 报错。

## 二、对象与字段

### 2.1 采购订单主表 `purchase_order`

| 字段 | 说明 |
|---|---|
| `purchase_no` | 单号，前缀 `PO`，唯一 |
| `supplier_id` / `supplier_code` / `supplier_name` | 供应商，后两个是**下单快照** |
| `warehouse_id` / `warehouse_name` | **目标入库仓库**（引用仓库只用 `warehouse_id`） |
| `status` | 见 §3.1 |
| `total_amount` | 订单总金额，**单位分**（×100） |
| `expected_arrival_date` | **预计到货日 = 承诺日**，提交与审核前必须非空 |
| `submitted_at` | 提交时间（下单日口径看这个，不看 `create_time`） |
| `approved_at` | 审核时间，交付绩效的"承诺起点"，也是成交口径的时间 |
| `fully_received_at` | 使整张单**完全入库**的最后一笔入库确认时间；未完成时为空 |
| `cancelled_at` / `cancel_reason` / `cancel_affects_delivery_score` | 取消信息；其中 `cancel_affects_delivery_score` **当前代码没有使用**，不要据字段名推断规则 |
| `deleted` | 逻辑删除，主表有 |

### 2.2 采购订单明细 `purchase_order_item`

| 字段 | 说明 |
|---|---|
| `purchase_order_id` / `purchase_no` | 所属订单 |
| `supplier_product_id` | 供货关系；必须存在、属于该供应商且产品匹配，提交与审核时**重新校验** |
| `product_id` / `product_code` / `product_name` / `unit_name` | 产品与单位**快照** |
| `quantity_precision` | **下单时从产品固化的精度快照**（0-2 位小数），产品主数据后来改精度不回写历史明细；离散单位（精度 0）数量必须是整数 |
| `quantity` | 采购数量，×100 |
| `inbound_qty` | **累计已入库量**，×100；未入库量 = `quantity − inbound_qty` |
| `unit_price` | 采购单价，**单位分** |
| `total_amount` | 明细金额，**单位分** = `quantity × unit_price / 100` |
| `selected_supplier_score` | 审核瞬间冻结的推荐分快照，见 §5.5 |
| 无 `deleted` | 明细表没有软删列 |

### 2.3 供应商与供货关系

- **下单必须先有供应商档案与供货关系**：`supplier_product_id` 必须存在、属于该供应商、且产品匹配。
- `supplier_product` 维护：供货单价、最小起订量（MOQ）、报价与报价有效期。
- **供应商停用被阻挡的条件**：存在供货产品、存在未完成的采购订单（状态 ∉ {`INBOUND_DONE`, `CANCELLED`}）、存在未完成的采购退货单（状态 ∉ {`COMPLETED`, `CANCELLED`}）。
- **供应商删除的阻挡条件更严**：存在**任意状态**的采购订单或采购退货单就不能删——删除会破坏追溯。
- 供应商编码前缀 `S` + 4 位序号（**不是日期格式**，与单号规则不同）。

## 三、状态机与流转

### 3.1 采购订单状态

| 状态 | 中文名 | 含义 | 能否编辑 | 能否取消 |
|---|---|---|---|---|
| `DRAFT` | 草稿 | 还没提交 | 可以 | 可以 |
| `SUBMITTED` | **待审核** | 已提交，等审核 | 可以（需审核权限） | 可以 |
| `APPROVED` | **待入库** | 审核通过，等仓库收货 | **不可以** | 可以（需先确认无已确认入库） |
| `PARTIAL_INBOUND` | 部分入库 | 收了部分货 | 不可以 | 不可以 |
| `INBOUND_DONE` | 已入库 | 全部收齐 | 不可以 | 不可以 |
| `CANCELLED` | 已取消 | 终态 | 不可以 | — |

报告里描述状态用上表的中文名，别自己造词。

**流转规则**：

- 提交时要求 `expected_arrival_date`（预计到货日）**非空**。
- 审核通过时**冻结供应商推荐分快照**到明细，并生成首张 `PENDING_CONFIRM` 的待确认入库单。
- 审核**不改库存**——库存和库存流水是仓库确认入库时才产生的。
- **`APPROVED` 之后不允许编辑**。要纠正只能通过入库单、冲销或反向单据。

**取消订单怎么算**：`CANCELLED` 是终态，**不参与延期与交付统计**——它没有实际到货事实，不能判定"是否准时"。表里有一个 `cancel_affects_delivery_score` 字段（注释写"是否计入供应商交付扣分"），但**当前代码没有使用它**，取消对供应商评分的影响尚未实现。做延期/交付分析时按"取消不算"处理；不要根据这个字段自行推断业务规则。

### 3.2 入库回写与状态推进

- **不允许超收，只允许欠收**：`本次入库量 <= 采购明细.quantity − 已累计入库量`。
- 入库确认时累加 `purchase_order_item.inbound_qty`，累加的是 **`current_qty`（本次入库总量）**，不是合格数量。
- 状态推进：
  - 所有明细 `inbound_qty >= quantity` → `INBOUND_DONE`，并把**最后一笔入库确认时间**写入 `fully_received_at`（**不得用 `update_time` 代替**）。
  - 否则 → `PARTIAL_INBOUND`，并**自动生成下一张只含剩余量的待确认入库单**。
- **每张分批入库单都重复保存 `plan_qty`（= 采购明细的全量 `quantity`）**。算在途量或应交金额时如果把多张入库单的 `plan_qty` 累加，会**严重重复计数**。

## 四、关键口径

### 4.1 数量与金额

| 字段 | 口径 |
|---|---|
| `purchase_order_item.quantity` | 采购数量，×100 |
| `purchase_order_item.inbound_qty` | **累计已入库量**，×100（不是本次入库量） |
| `purchase_order_item.unit_price` | 单价，单位分 |
| `purchase_order_item.total_amount` | 明细金额，单位分 |
| `purchase_order.total_amount` | 订单总金额，单位分 |

**金额口径**：真实业务数量 × 元单价 = 元金额；直接用库内整数时，明细金额（分）= `quantity × unit_price / 100`，按业务金额规则舍入，订单总金额为明细金额之和。系统未记录含税/未税、运费、折扣拆分，不能伪造这些已发生费用。

### 4.2 时间归期

| 要统计的事 | 用哪个时间 | 不能用哪个 |
|---|---|---|
| 采购成交额、下单口径 | `approved_at`（审核成立那一刻） | `create_time` |
| 交付承诺 | `expected_arrival_date` | 不能当实际到货日 |
| 实际交付完成 | `fully_received_at` | 不能拿 `update_time` 代替 |
| 入库事实 | 入库单 / 流水 `confirmed_at` | 单据创建时间 |

需要"某月下的单"按 `approved_at` 归月；需要"某月到的货"按 `fully_received_at` 或流水 `confirmed_at` 归月。两者结果不同，`instruction` 里必须写清用哪个。

### 4.3 ★ 在途采购量（最关键的口径）

**"在途采购量"在系统里没有对应字段**，必须自己按状态和数量算：

```
在途采购量 = Σ( purchase_order_item.quantity − purchase_order_item.inbound_qty )
             仅统计 status IN ('APPROVED','PARTIAL_INBOUND') 的采购订单
```

**必须避开四个坑**：

1. **不要双重减法**。`inbound_qty` 本身就已经是从 `quantity` 里扣过的累计入库量，不要再减一次"已入库量"。
2. **`PARTIAL_INBOUND` 的订单，已入库那部分不在途，只有剩余量在途**。
3. **别把"已生成待确认入库单但还没确认"的量算出去了**——货还没到账，确认入库才算入库，在途量直到确认才减少。
4. **区分月内到货量与需求窗口可用供应**。只统计"下月内新增到货量"时，按 `expected_arrival_date` 过滤下月；判断下月供需时，应从当前快照衔接到月初，纳入月初前可达供应及此前消耗，不能只保留下月到货。每笔供应只能从可达时点起使用；预计日期为空、逾期或失约时单列不确定性，不自动视为今天到货。

**在途量 ≠ 锁定库存**。采购入库**从不写** `locked_qty`，所以"在途采购量"和库存表的 `locked_qty` 是两套完全不同的数字，不能相加。

**销售方向没有"在途"概念**——销售出库在**提交订单时**就锁了库，所以"在途"只用于采购补货场景。

### 4.4 统计采购成交额

```sql
WHERE po.status IN ('APPROVED','PARTIAL_INBOUND','INBOUND_DONE')
  AND po.approved_at >= ? AND po.approved_at < ?
  AND po.deleted = 0
```

**用 `approved_at` 不用 `create_time`**——成交是审核那一刻成立的。

### 4.5 订单完成率（金额加权，不是数量加权）

```
完成率（%）= Σ(min(inbound_qty, quantity) × unit_price / 100) / total_amount × 100
```

这里数量和单价是数据库原始整数：乘积先除以 100 才是分金额，计算比例时保留中间精度。订单总金额须大于 0；多订单汇总时分母按订单唯一累计，不能连接明细后重复累加。例：10 件、已入 5 件、2 元/件，库内分别为 1000、500、200 分，总额 2000 分，完成率为 `(500×200/100)/2000×100 = 50%`，不是 5000%。

### 4.6 单号规则

- 采购订单号前缀 `PO`，采购退货单前缀 `PR`，入库单前缀 `IB`。
- **查最大单号序列的 SQL 刻意不加 `deleted = 0`**——逻辑删除的单号仍占用唯一索引。

## 五、业务定义

### 5.1 延期交付（延期清单口径）

**只算已完全入库的订单**：`INBOUND_DONE` 且 `fully_received_at` 晚于 `expected_arrival_date` 才算延期交付。

```
延期天数 = 完全入库日期 − 预计到货日        （> 0 才算延期）
```

- `APPROVED` / `PARTIAL_INBOUND` 还没有最终交付事实，**不判延期、不计入延期订单数与平均延期天数**。
- **承诺日当天完成算按时**（与 `supplier.md` 交付分口径一致）。
- 供应商逾期扣分由评分体系按到期订单与逾期系数单独计算（见 `supplier.md`）。延期清单不重复算罚分，也不要另造判定规则。

### 5.2 逾期未到（在途逾期）

用户问"**超过预计到货日但还没到货**"时，这是另一个问题，不要用 §5.1 的延期口径回答：

```
逾期未到：status IN ('APPROVED','PARTIAL_INBOUND')
          且 expected_arrival_date < 今天
          未入库量 = quantity − inbound_qty
```

- 这类订单**不计入"延期交付"**，单列为"逾期未到"；两个数不能相加、不能混成一个指标。
- 要判断"能否赶上下个月"，按 §4.3 坑 4 处理：逾期部分单列不确定性，不自动视为今天到货。

### 5.3 缺货判定（风险预警，看现状）

只看当前快照时，"会不会缺货"按库存健康的风险口径判：可用库存 ≤ 安全库存即触发低库存预警（见 `warehouse.md` §5.1、§5.2）。**这只回答"现在离安全线差多少"，不回答未来够不够**，也不要求需求预测。

### 5.4 净缺口（未来，问答口径）

```
净缺口 = max(0, 需求 − 当前可用库存 − 期内可信可达采购量)
```

- **需求**：优先用用户给的预测；系统没有预测数据时，用"已提交未出库销售订单的剩余量"作为**确定性需求下限**，并在结论里标注这是下限、不是完整预测。**不要用历史销量冒充预测**，除非用户明确要求那样估。
- **当前可用库存** = `warehouse_stock.stock_qty − warehouse_stock.locked_qty`（见 `warehouse.md`）。它已经扣了锁定，**不能再重复扣同一笔销售需求**。
- **期内可信可达采购量**：`APPROVED` / `PARTIAL_INBOUND` 的未入库量中，预计到货日落在窗口内、或早于窗口起点能在窗口开始前到达的部分。**已逾期未入库、预计到货日为空的，单列"不确定性"，默认不计入**；用户要求计入时，给"含逾期 / 不含逾期"两个口径。
- **安全库存不参与净缺口**——它是风险预警线（§5.3、`warehouse.md` §5.2），不是期末目标。
- 结果等于 0 时明确说"按当前口径不缺"，不要留空。

**三个量分开命名，不要混用：**

| 名称 | 公式 | 回答什么 |
|---|---|---|
| 风险缺口 | `max(0, 安全库存 − 可用库存)` | 现在离安全线差多少 |
| 净缺口 | `max(0, 需求 − 可用库存 − 期内可达采购量)` | 未来够不够、缺多少 |
| 建议补货量 | `max(0, 安全库存 × 2 − 可用库存)` | 工作台给出的动作建议量 |

### 5.5 采购测算（逐桶，方案手册口径）

补货方案子图做逐日 / 逐桶测算时用它自己的口径，**不改变上面 §5.4 的净缺口定义**：

```
保护期新增需求 = Σ_t max(0, 本桶总需求预测 − 本桶已锁且与预测重叠的销售未履约量)
新增供应总量候选 = max(0, 保护期新增需求 + 期末目标 − 当前可用库存 − 期内可信可达采购量)
```

- 上述预测消耗以"预测已包含该订单"为前提；输入若已是纯新增需求，不再减重叠量。先逐桶消耗再汇总，不等价于全期汇总后截断。
- 总量候选不保证中途无缺货，仍须按到货和需求时点验证。
- **期末目标由用户或维护政策提供，不能默认发明**；它不参与 §5.4 的净缺口。
- 细节见专家手册 `DEM-004`、`REP-002`—`REP-004`。

### 5.6 供应商推荐分快照

采购订单明细上的 `selected_supplier_score` 是**审核瞬间冻结的推荐分快照**：

- 只有供货关系的 `score_status = 'READY'` 时才写入分数，否则写 `NULL`。
- **有效零分保存 `0`，不可用 `NULL` 混淆**。
- 草稿创建/编辑不接受前端提交该字段，一律写 `NULL`。
- 审核后评分变化**不回写历史单据**，历史空快照**不补填**。
- 审核时还会校验供货关系仍然属于该供应商且产品匹配。

**评分公式、样本窗口、触发源见 `supplier.md`。**

## 六、常见错误

1. 把 `APPROVED` 说成"已审核完成/已结束" → 它的中文是**待入库**。
2. 以为审核采购单会改库存 → 审核不改库存，只有仓库确认入库才改。
3. 双重减法算在途（`quantity − inbound_qty − 已入库量`）→ `inbound_qty` 已经是累计量。
4. 把 `PARTIAL_INBOUND` 的**全量**算进在途 → 只有剩余未入库部分在途。
5. 累加多张分批入库单的 `plan_qty` 算应交量 → 严重重复计数。
6. 用 `create_time` 统计成交额 → 成交口径是 `approved_at`。
7. 把"逾期未到"算成"延期交付"，或把两者相加 → §5.1 与 §5.2 是两个指标。
8. 拿 `fully_received_at` 判部分入库订单是否延期 → 它只在整单收齐时才有值；未收齐的不判延期。
9. 把 `CANCELLED` 算进延期或交付统计；或根据 `cancel_affects_delivery_score` 推断规则 → 该字段当前无业务逻辑使用。
10. 在 `purchase_order_item` 上加 `deleted = 0` → 明细表没有这一列，SQL 报错。
11. 把在途量与库存 `locked_qty` 相加 → 两套完全不同的数字。
12. 净缺口里再加安全库存/期末目标 → 按 §5.4，安全库存不参与净缺口。
13. 把已逾期、预计到货日为空的采购量直接当可用供应 → 按 §4.3 坑 4 单列不确定性。
14. 用产品主数据当前精度改写历史明细的取整规则 → 精度是下单快照。
15. 编造税额、运费、折扣等 ERP 未记录的费用 → 系统未记录，不能当已发生金额。

## 七、写 `instruction` 时的提醒

1. **算在途量**：写成业务口径——"只统计已审核（`APPROVED`）或部分入库（`PARTIAL_INBOUND`）订单的采购数量减累计已入库量，不要双重减法"，并注明目标入库仓库。状态枚举字面量要写全，**表名与字段名不要抄进 `instruction`**。
2. **算可用库存**要去库存侧用"账面 − 锁定"（见 `warehouse.md`）。
3. **算净缺口**按 §5.4 的公式写清三个输入的来源；需求没有预测时用"已提交未出库订单剩余量"并标注是下限；不要把已锁需求从可用库存再扣一遍。
4. **判延期**按 §5.1，**判逾期未到**按 §5.2；两条问题的口径不同，不要混写。
5. **算成交额**按 §4.4 说清"按审核时间归期 + 三个有效状态 + 排除逻辑删除"；**算完成率**按 §4.5 说明是金额加权。时间字段与状态枚举用业务说法表达，具体列名由取数子图按表结构选。
6. **算金额**：业务数量 × 元单价 = 元；用库内整数时按"采购数量 × 单价 ÷ 100 得分金额"的口径说明量纲，按业务规则舍入并防溢出。系统未记录税、运费、折扣，不能编造；用户提供的外部费用情景须单列来源。
7. **数字必须标单位**：金额写「分」或换算后的「元」，数量写业务单位；同一需求内保持一致。
8. **过滤状态要写全枚举字面量**（`APPROVED`、`PARTIAL_INBOUND`、`INBOUND_DONE`），不要用中文。
9. 需要"某时点库存"或逐日缺口时，说明用品流回溯重建，不接受用当前余额顶替历史。
