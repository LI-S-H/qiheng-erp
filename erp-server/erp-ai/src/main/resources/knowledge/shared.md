# 公共业务口径

> 适用范围：读懂 ERP 任何一张表的前提——数量与金额的放大口径、逻辑删除、状态枚举的中文读法、日期语义、单号规则、快照字段。
> 本文对所有用户都注入。各模块的具体规则见对应模块文档。

## 一、速查（先看这几条）

1. **数量是 ×100 整数、金额是「分」**；`product.reference_purchase_price` / `reference_sale_price` 是 DECIMAL 元，**唯一不放大**的金额字段。评分也是 ×100。
2. 统计**金额类指标按业务发生时间**（采购按 `approved_at`、出入库按 `confirmed_at`），**不能按 `create_time` 归期**。
3. **`SUBMITTED` 的中文是"待审核"，不是"已提交"**；`APPROVED` 在采购单是"待入库"，在销售单是"待出库"。
4. **不是每张表都有 `deleted`**：明细表和流水表都没有，加了会 SQL 报错（清单见 §2.1）。
5. `product` 与 `sales_order` 里**一半以上是逻辑删除数据**（含 `TEST_*` 测试单），漏掉 `deleted = 0`，指标直接错一半。
6. **预计日 ≠ 实际日**，`update_time` 不能当业务完成时间。
7. 单据明细里的 `product_name` / `unit_name` / `quantity_precision` 等是**创建时快照**，主数据后来改了不跟随（唯一例外：`warehouse_stock.warehouse_name`）。
8. 状态值一律用**英文字面量**过滤，不要用中文。

## 二、通用字段与表规则

### 2.1 逻辑删除 `deleted`

**没有 `deleted` 列的表（加了会报错）**：

- `purchase_order_item`（采购明细）
- `return_order_item`（退货明细）
- `inbound_bill_item` / `outbound_bill_item`（出入库明细）
- `stock_bill` / `stock_bill_item`（库存流水）
- `warehouse_stock`（库存余额）
- `supplier_score_change_log`（评分日志）

**有 `deleted` 且默认要过滤的表**：`purchase_order`、`supplier`、`supplier_product`、`return_order`、`warehouse`、`inbound_bill`、`outbound_bill`、`customer`、`product`、`sales_order`。

**MyBatis-Plus 的 `@TableLogic` 只对标准 Mapper 方法与条件构造器自动追加 `deleted = 0`；手写 `@Select` 注解的 SQL 不会自动过滤**，必须自己写。

**逻辑删除在实际数据里用得很凶**（2026-10-22 真实库统计）：

| 表 | 总行数 | 已逻辑删除 |
|---|---|---|
| `product` | 171 | **88** |
| `sales_order` | 44 | **24** |
| `outbound_bill` | 27 | 1 |
| `customer` | 14 | 1 |
| 其余（采购单、退货单、供应商、仓库、出入库单） | — | 0 |

`product` 有一半是删掉的，`sales_order` 有一半是删掉的（删掉的那批全是 `TEST_*` 开头的测试单）。**漏掉 `deleted = 0` 的查询，指标会直接错一半。**

**"有效数据"通常要同时过滤状态和逻辑删除**，例如统计采购成交额：

```sql
WHERE po.status IN ('APPROVED','PARTIAL_INBOUND','INBOUND_DONE')
  AND po.deleted = 0
```

**但"查最大单号序列"这类查询刻意不加 `deleted = 0`**——逻辑删除的单号仍然占用唯一索引，跳过它们会生成重复单号。

### 2.2 快照字段

单据明细里有大量**快照字段**（`product_name`、`warehouse_name`、`unit_name`、`quantity_precision`、`selected_supplier_score` 等），它们是**创建那一刻的副本**：

- 主数据后来改了，**历史单据上的快照不跟着改**。
- 查询历史单据时读快照值，**不要回查当前主数据覆盖历史规则**。
- 唯一例外：`warehouse_stock.warehouse_name` 是**当前态冗余**，仓库改名时会同步更新。

### 2.3 单据号规则

格式统一是 `{前缀}{yyyyMMdd}{序号}`，序号**按天重置**，零填充。

| 前缀 | 单据 |
|---|---|
| `PO` | 采购订单 |
| `PR` | 采购退货单 |
| `SR` | 销售退货单 |
| `SO` | 销售订单 |
| `IB` | 入库单 |
| `OB` | 出库单 |

编码类（不是单号）：仓库 `WH` + 6 位序号，供应商 `S` + 4 位序号。

**两个真实的坑**：

1. **历史号段与现行号段并存。** 2026-06 的一批退货单用的是 `PRO` / `SRO` 前缀，现行是 `PR` / `SR`。按前缀匹配要用 `LIKE 'PR%'` 而不是精确等于，而且**判断退货方向要用 `return_type` 字段，不要用单号前缀**。
2. **测试数据也在库里。** 销售订单里有一批 `TEST_RANK_*_SO_*` 开头的单（排行榜功能测试留下的），它们**全部是已逻辑删除的**。任何统计只要带上 `deleted = 0` 就不会算进去；漏了 `deleted = 0` 就会把测试数据算进业务指标。

## 三、状态机的通用读法

ERP 的状态值一律是**英文大写枚举**，写过滤条件时必须用字面量，不能用中文。

| 状态 | 通用含义 | 注意 |
|---|---|---|
| `DRAFT` | 草稿，可以随便改 | 未生效，不参与统计 |
| `SUBMITTED` | **待审核** | 中文不是"已提交"，是"已经提交、正在等审核" |
| `APPROVED` | 审核通过 | 采购单中文是**待入库**，销售单是**待出库** |
| `PENDING_CONFIRM` | 待仓库确认 | 出入库作业单专用，库存尚未变动 |
| `PARTIAL_*` | 部分完成（部分入库 / 部分出库 / 部分执行） | 已发生一部分事实 |
| `*_DONE` / `COMPLETED` / `CONFIRMED` | 全部完成 / 已确认 | 终态，之后不可改 |
| `CANCELLED` | 已取消，**终态** | 过滤有效数据时永远排除 |

各模块的完整状态机在对应文档：采购见 `purchase.md`，销售见 `sales.md`，退货见 `return.md`，仓储见 `warehouse.md`。

## 四、关键口径

### 4.1 数量、金额、评分的存储与换算

**这是最容易被算错的地方。** ERP 的数量与金额在库里都放大了 100 倍。

| 输入 | 库内原始口径 | 举例 | 进入计算 / 展示时的口径 |
|---|---|---|---|
| 库存、锁定、订单数量 | `BIGINT`，真实值 ×100 | `quantity = 2400` | 业务数量 **24.00**（除 100） |
| 交易单价、金额 | `BIGINT`，单位**分** | `unit_price = 3520` | 元 **35.20**（除 100） |
| 产品参考采购价 / 参考售价 | `DECIMAL(18,2)`，**单位元** | `12.50` | **直接用，不再除 100** |
| 评分 | `INT`，真实值 ×100 | `recommend_score = 9200` | **92.00** 分（满分 100） |
| 到货周期（`avg_delivery_days`） | `DECIMAL(10,2)`，单位天 | — | 直接用，并注明是历史统计值 |

**推论**：

- 同口径数量相加、相减的结果仍是 ×100 口径；**数量相除得到的是比例，不能再按 ×100 数量解读**。
- 两个放大数相乘必须重新核对量纲：数量 `Q100` × 单价 `Pcent` 得金额（分）时应除以 100 并按业务规则舍入。例：`2500 × 3520 / 100 = 88000` 分，即 25 件 × 35.20 元 = 880.00 元。计算须防整数溢出，不能把乘积直接当作 ×100 数量或金额。
- 金额相加结果仍是分。
- 换算**在一次底表整理里做完**，不要在每个场景重复除 100。
- **跨单位不能汇总数量**：只有明细单位相同才能求合计；跨单位时合计数量应为空，不要硬加。

### 4.2 日期字段的语义

| 字段后缀 | 含义 | 注意 |
|---|---|---|
| `create_time` / `update_time` | 记录创建 / 更新时间 | `update_time` 会随任何字段变更刷新，**不能当作业务完成时间** |
| `submitted_at` | 提交时间 | 下单日口径看这个，不看 `create_time` |
| `approved_at` | 审核时间 | 采购交付绩效的"承诺起点"，成交额按它归期 |
| `confirmed_at` | 作业单确认时间 | **实际到货 / 实际出库的事实时间** |
| `fully_received_at` | 整单完全入库的时间 | = 最后一笔入库单的 `confirmed_at`；**不得用 `update_time` 代替** |
| `expected_arrival_date` | 预计到货日（**承诺日**） | 与实际到货时间**不能互相替代** |
| `expected_delivery_date` | 预计发货日 | |
| `expected_execution_date` | 预计退货执行日 | |

**"预计"与"实际"是两回事**，报告里要区分清楚，不能拿承诺日当实际日。

**★ 按自然月归期，必须用"实际发生时间"，不能用 `create_time`：**

| 统计的事 | 归期字段 |
|---|---|
| 销售出库按月 | `outbound_bill.confirmed_at` |
| 采购入库按月 | `inbound_bill.confirmed_at` |
| 采购成交额按月 | `purchase_order.approved_at` |

用 `create_time` 归期，单据在月末建、次月初确认，就会落到错误的月份，**月度量与预测全部偏移**。（这条是 2026-10-22 真实模型联调时由需求审阅节点挑出来的——写文档时漏了。）

### 4.3 时间窗口写法

- 区间要写明确边界（含不含端点），不要只写"最近一个月"。
- 相对时间（本月、上月、下月、近 90 天）按输入给出的时间口径换算成绝对区间。
- 跨模块统计时，各模块用各自的业务时间，不能用同一个 `create_time` 拉平。

## 六、常见错误

1. 把 ×100 的数量或"分"直接当业务值写进报告 → 大 100 倍。
2. 把 `reference_purchase_price`（元）当成分再除 100 → 小 100 倍。
3. 用 `create_time` 归月做销量、成交额 → 月份偏移。
4. 用 `update_time` 当完成时间、用 `expected_arrival_date` 当实际到货 → 语义错。
5. 在没有逻辑删除列的表（明细表、流水表、库存余额表）上要求"过滤已删除" → SQL 报错；这类表按"有效单据"的业务口径表达即可。
6. 漏掉 `deleted = 0` → 把测试单和已删主数据算进指标。
7. 用单号前缀判断退货方向 → 历史号段 `PRO`/`SRO` 与现行并存，要用 `return_type`。
8. 跨单位汇总数量 → 件和 kg 不能相加。
9. 用当前主数据覆盖历史单据的快照 → 精度、单价、名称都应读快照。
10. 状态过滤用中文 → 必须用英文字面量。

## 七、给模型的通用提醒

1. **只用输入里给出的表和字段**。看不到的表不代表系统里没有，是当前用户没有权限。
2. **数字类必须标单位**：金额写「分」或已换算的「元」、数量写业务单位、评分写 0-100；同一需求内保持一致，不要混用。换算由取数与计算方按 §4.1 做一次，`instruction` 不写除法步骤。
3. **状态过滤要写全**：要排除的状态（草稿 `DRAFT`、已取消 `CANCELLED`）用业务说法写进 `instruction`。**状态枚举值要写，表名和列名不要写**，取数方按表结构自己选列。
4. **日期区间要写明确边界**和业务归期字段，不要只写"最近一个月"。
5. **不要在 `instruction` 里编造不存在的字段，也不要把取数写法写进需求**——要指明按哪个时间、哪些状态、哪一层口径时，用表结构注释里的中文说法描述（「按出库确认时间统计」「按审核通过的订单统计」），不要写英文列名或比较式；选哪张表、怎么 JOIN 由取数方决定。
6. **本文档与代码不一致时以代码为准**，并在文档里标注出来，不要写代码里没有的断言。
