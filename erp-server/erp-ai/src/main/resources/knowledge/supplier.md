# 供应商业务口径

> 适用范围：供应商档案、供货关系、报价维护、供应商评分体系（价格 / 质量 / 交付 / 服务）与重算触发。
> 关联文档：采购订单状态与在途、延期清单见 `purchase.md`；数量放大与金额单位见 `shared.md`；参考采购价字段见 `product.md`。

## 一、速查（先看这几条）

1. **没有"等级"（A/B/C）字段**，只有 0-100 的百分制分数 + `score_status`（`READY` / `NOT_READY`）。
2. **评分列是 ×100 整数**：库里 `9200` = 真实 `92.00` 分。
3. **`NULL` ≠ `0`**：`NULL` 表示样本不足或未人工设定，`0` 表示算出来就是零。任一分项为 `NULL`，综合分与推荐分就是 `NULL`，**不重新分配权重**。
4. 权重固定：价格 30% + 交付 30% + 质量 30% + 服务 10%。
5. **交付分与"延期清单"是两个指标**：交付分按到期订单算扣分（含 `APPROVED` / `PARTIAL_INBOUND`），延期清单只算已完全入库的订单（见 `purchase.md` §5.1）。不要互相顶替，也不要拿交付分去回答"哪些供应商延期了"。
6. `score_basis_amount`（近 180 天已确认样本金额，单位分）**只用于价格分的金额加权与展示，不参与质量分**。
7. 最小起订量 `min_order_qty` **下单时不强制校验**，只在维护供货关系时校验"大于 0 且精度符合产品精度"。
8. 参考采购价是 `DECIMAL` **元**，供货报价是**分**，两者口径不同。

## 二、对象与字段

### 2.1 供应商档案 `supplier`

主要字段：编码（`S` + 4 位序号，**非日期格式**）、名称、联系人、联系方式、地址、`status`（`1` 启用 / `0` 禁用）、`avg_delivery_days`、四项分项评分 + `overall_score`、`score_basis_amount`、`score_status`、`service_score_reason`、`deleted`。

| 字段 | 口径 |
|---|---|
| `avg_delivery_days` | 最近 180 天**完全入库**订单的**金额加权**平均到货周期，单位天，`DECIMAL(10,2)`，不放大 |
| `delivery_score` / `quality_score` / `price_score` / `service_score` / `overall_score` | ×100 整数（0-10000 ↔ 0.00-100.00），可为 `NULL` |
| `score_basis_amount` | 近 180 天已确认样本金额，单位分；不足样本时为空 |
| `score_status` | `NOT_READY` 样本不足；`READY` 可参与评分 |

### 2.2 供货关系 `supplier_product`

一个供应商与一个产品的供货关系，维护：`quoted_purchase_price`（人工有效报价，分）、`quote_valid_until`（报价有效截止日）、`quoted_price_reason`、`quoted_price_updated_at`、`latest_purchase_price`（由已确认入库事实维护的最近成交单价，分）、`last_purchase_at`、`min_order_qty`（×100）、`avg_delivery_days`（金额加权到货周期，仅供分析）、`quality_score`、`price_score`、`recommend_score`、`score_basis_amount`、`score_status`、`status`、`deleted`。

- **新建 / 编辑供货关系要求供应商与产品都处于启用状态**（这是全系统少数几处真正校验"启用状态"的地方）。
- 下单前必须存在供货关系，且明细的 `supplier_product_id` 属于该供应商、产品匹配；提交与审核时**重新校验**。

### 2.3 评分变化日志 `supplier_score_change_log`

记录每次评分变化的前后值、规则版本（`SCORE_V1` / `SCORE_V2`）、触发来源（`PRICE_TRIGGER`、`SERVICE_TRIGGER`、`INBOUND_TRIGGER`、`QUOTE_EXPIRED_TRIGGER`、`DAILY_TRIGGER`、`MERGED`）、批次号、操作人与原因。

**这张表没有 `deleted`**。

## 三、启停与删除保护

**停用被阻挡**：存在供货产品、存在**未完成**采购订单（状态 ∉ {`INBOUND_DONE`, `CANCELLED`}）、存在**未完成**采购退货单（状态 ∉ {`COMPLETED`, `CANCELLED`}）。

**删除被阻挡（更严）**：存在供货产品、存在**任意状态**的采购订单、存在**任意状态**的采购退货单。

**评分归属校验时要包含逻辑删除的供货关系**——删掉供货关系不能让历史入库事实的质量归属消失。

## 四、关键口径

### 4.1 报价维护

- 报价、有效期、原因**三者成组**：清空时全部传空并把当前原因置空串；有值时报价 > 0、有效期不早于当前业务日、原因非空。
- 报价最多两位小数。
- 报价修改后**同事务触发价格分重算**。
- 初始报价不写评分日志。

### 4.2 服务分的人工维护

- 只能用专用接口维护，**最多两位小数**，**必须填原因**。
- **分数与原因成组**：分数为空则原因清空；分数非空则原因不能为空。
- **分数未变 → 只换原因，不写评分日志**；分数变化 → 写一条评分日志。
- 建档时的初始服务分只保存原因，**不写日志**。

### 4.3 单位与口径

| 输入 | 口径 |
|---|---|
| 各评分列 | ×100 整数，展示前除 100 得 0-100 分 |
| `quoted_purchase_price` / `latest_purchase_price` / `score_basis_amount` | 单位**分** |
| `product.reference_purchase_price` | 单位**元**，`DECIMAL(18,2)`，不放大 |
| `min_order_qty` | ×100 |
| `avg_delivery_days` | 天，不放大；注明是历史统计值 |

比较报价与参考价时**两者口径不同**，必须统一后再比。

### 4.4 评分重算的触发源

| 触发 | 时机 |
|---|---|
| 服务分人工调整 | 业务事务内**同步**重算 |
| 报价调整 | 业务事务内**同步**重算 |
| 参考采购价变更 | 业务事务内**同步**重算 |
| 首次完全入库 | 事务提交后延迟消息（5 分钟合并窗口） |
| 报价过期扫描 | 每日 01:30 |
| 每日兜底重算 | 每日 02:00，逐供应商持锁重算 |

**部分入库不触发即时评分重算**，由每日兜底覆盖。规则版本：历史用 `SCORE_V1`，当前是 `SCORE_V2`（金额质量率 + 到期订单交付事实）。

## 五、业务定义：评分体系

**权重固定**：价格 30% + 交付 30% + 质量 30% + 服务 10%。

| 分项 | 口径 | 样本窗口 |
|---|---|---|
| 产品质量分 | `Σ(合格金额) / Σ(合格金额 + 不合格金额) × 100` | `INBOUND_DONE` 且 `fully_received_at ∈ [D-179 00:00, D+1 00:00)` |
| 供应商质量分 | 全部有效产品合格金额 / (合格 + 不合格) 总金额 × 100 | 同上 |
| 价格分 | `min(100, 产品参考采购价 / 有效报价 × 100)` | 参考价与有效报价 |
| 供应商交付分 | `max(0, 100 × (1 − Σ罚额 / Σ到期应交金额))` | `expected_arrival_date ∈ [D-180, D)` 且状态 ∈ {`APPROVED`, `PARTIAL_INBOUND`, `INBOUND_DONE`} |
| 服务分 | **人工设定**，必须填原因 | — |
| 推荐分 / 综合分 | 价格 30% + 交付 30% + 质量 30% + 服务 10% | — |

**交付逾期系数（固定五档）**：按时（≤0 天）0%、1-3 天 25%、4-7 天 50%、8-15 天 75%、超过 15 天 100%。**承诺日当天确认算按时。**

**供应商价格分的汇总**：`Σ(score_basis_amount_i × price_score_i) / Σ score_basis_amount_i`，只统计**启用、价格分有效且 `score_basis_amount > 0`** 的供货关系。

**供应商综合分**用供应商维度的分项（价格 30% + 交付 30% + 质量 30% + 服务 10%），不是把产品分简单平均——**质量分天然按金额加权，不平均已舍入的产品分**。

**到货周期**：`avg_delivery_days` 是最近 180 天**完全入库**订单的金额加权平均到货天数，只能用作历史参考，**不能当本次可承诺交期**。

## 六、常见错误

1. **把 `NULL` 归一成 `0`** → `NULL` 是样本不足，任一分项为 `NULL` 时综合分/推荐分必须为 `NULL`，不重新分配权重；`score_status` 相应为 `NOT_READY`。
2. **用采购明细 `total_amount` 算质量分** → 质量分用 `inbound_bill_item.unit_price` × 质检数量；`score_basis_amount` 只用于价格分加权与展示。
3. **拿历史推荐分快照当当前分** → `purchase_order_item.selected_supplier_score` 是审核瞬间冻结的快照，之后不回写、空快照不补填。
4. **样本窗口边界搞混** → 质量分窗口**含当天**（`[D-179, D+1)`），交付分窗口**不含当天**（`[D-180, D)`）；未到承诺日的订单不进交付分分母；`CANCELLED` 不进任何样本。
5. 用 `reference_purchase_price`（元）和 `quoted_purchase_price`（分）直接相除 → 口径不同，先统一。
6. 把交付分当成延期清单，或反过来 → 两者样本与含义不同（见 §一.5）。
7. 以为下单会校验最小起订量 → 目前不强制校验。
8. 在 `supplier_score_change_log` 上加 `deleted = 0` → 该表没有这一列。
9. 把 `avg_delivery_days` 当本次承诺交期使用 → 它只是历史统计。

## 七、写 `instruction` 时的提醒

1. 评分要写成 0-100 的业务分值并注明库里是 ×100 整数。
2. 算综合分/推荐分前先判空：分项为 `NULL` 就不计算该供应商的综合分，并说明是样本不足，不要当 0。
3. 算价格分要写明分子是 `reference_purchase_price`（元），分母是有效报价（分），口径需统一。
4. 统计成交金额要写明"按审核时间归期并排除已取消"。
5. 判"供应商是否延期交付"按 `purchase.md` §5.1 的延期口径；要"交付表现分数"才引用本文的交付分。两者不要写在同一条证据里。
6. 用到货周期时必须注明它是最近 180 天的历史统计值。
7. 数字必须标单位（分 / 元 / 天 / 0-100 分），同一需求内保持一致。
