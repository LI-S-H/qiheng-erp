# ERP 方案操作手册 · 通用入口

> 版本 2.1；核对日期 2026-10-24。专业及项目来源见 docs/ai-expert-knowledge-guide.md。下列案例是假设，不是当前经营数据。

## 通用入口：先确定这次要交付什么

拿到业务问题后，从 COM-001 选一条路线，不要把八份文件依次执行。方案规划时，按步骤列出需要复用、查询、计算或向用户确认的证据；实际结果回来后，再按对应分支选择动作。本文不新增工具、暂停点或接口。

如果你是 `need_review`，直接使用 COM-005：审查待执行清单能否回答问题，不执行 SQL，不因“任务尚未执行、没有结果”就判漏查。

## COM-001 第一步：把用户问法变成一条最短路线

1. 从上下文写出一句任务：“针对哪些仓库、哪些产品，在什么时间内，交付什么判断或动作”。只查当前状态时，时间就是本次快照；只有决策涉及未来时才需要保护到哪天。沿用已经明确的参数，不反复询问。
2. 查下表，选入口。不要因为用户提到“采购”，就自动启动预测、安全库存优化和经济订货量模型。

| 用户要什么 | 现在从哪里开始 | 到哪里可以交付 |
|---|---|---|
| 当前库存、缺货、安全线差多少 | REP-001 | 当前差额表；没有行动目标即可结束 |
| 未来一段时间是否够、还需补多少 | REP-002 → REP-003 → REP-004 | 净补货量、首次缺口日、可及时覆盖的动作 |
| 已定外购，买多少、向谁买 | PUR-001 与 SUP-001 | 取整后数量、有效候选、货值、到货及待确认项 |
| 能否从别仓支援 | TRF-001 | 只问余量则结束；要调拨再走 TRF-002/003 |
| 筛选促销商品、测算降价是否值得 | PRM-001 的两个入口 | 候选清单，或有成本依据的贡献情景 |
| 清理低周转库存 | CLR-001 → CLR-002 | 可保留动作与数量；需落实时再走 CLR-003 |
| 缺未来需求估计 | DEM-001 | 依 DEM-002/003 选择可用基线，再回原场景 |
| 明确要求优化安全库存/经济批量 | DEM-005 / PUR-004 | 参数足够才算候选策略；否则给参数补充任务 |

3. 仅补问会改变所选路线的条件。例如“给我补货建议”未给期间，可先查当前余额，同时确认要覆盖几天；不能凭空用14天。把预算、交货期限、利润底线分清“用户硬要求”和“尚未提供”，不要替企业设政策。

**本步留下**：一行任务说明、所选入口、已有参数、真正需要澄清的条件。下一步 COM-002；若用户只要解释一个概念，直接解释，不创建整套分析。

## COM-002 第二步：把输入整理成同口径底表

1. 每条输入标出产品、仓库、单位、日期和来源证据 ID。仓库产品的需求不能用全公司产品销量分别复制给每个仓；同叫“件”的不同产品也不能抵供。
2. 告诉取数/计算任务统一口径后再算。原始整数需要转换如下；产品参考价是例外，已经是元。

| 输入 | 原始口径 | 进入计算的口径 |
|---|---|---|
| 库存、锁定、订单数量 | 真实数量 ×100 | 除100为业务数量 |
| 交易单价、金额 | 分 | 除100为元 |
| 产品参考采购价/售价 | DECIMAL 元 | 直接用，不再除100 |
| 评分 | 真实分值 ×100 | 除100为0—100分 |
| 历史平均交期 | 普通天数 | 直接用，注明是历史统计 |

3. 使用精确计算。业务数量×元单价=元；直接用库内整数时，金额（分）=Q100×Pcent/100，再按业务规则 HALF_UP 舍入并防溢出。数量加减仍为原数量口径；数量相除是比例，不能仍当 ×100 数量。假设2500代表25件、3520代表35.20元，则货值880.00元。
4. 从本次适用的 `quantity_precision` 得到步长 δ=10^(-quantity_precision)。为了满足最低需求向上取整，为了不超库存/预算上限向下取整；取整后重算金额和约束。MOQ（起订量）只代表下限，不能当包装倍数。历史分析用单据快照，不用新精度改写旧单。
   - ceil(x)是向上取整，floor(x)是向下取整；最低所需量Q_min与实际允许上限Q_cap要分别算。Q_cap指依实际业务计价及约束核验后的硬上限，保守估计不是最终上限。若Q_min>实际Q_cap，本候选不满足全部条件，不能削量后仍称足量；预算边界按PUR-002先做金额舍入再判断。例：实际最多25件、最低需26件，应协商条件，不能推荐25件并称已补足。
5. 库存先保留账面 H、仓储锁定 R，再算账面可用 A=H−R。发现负值或 R>H，列出异常并停止对该行承诺可用量，保留其它正常行继续。余额没有质量分桶，不能用历史次品累计量猜当前不可售余额。[ERP-PRODUCT][ERP-WHS][ERP-PUR]

**本步留下**：可以直接用于后续公式的同口径底表，另列异常行。不要在每个场景重复除100。下一步 COM-003。

## COM-003 第三步：补齐证据清单，而不是猜数字

对所选场景的每一项输入按下面顺序处理：

1. **已有合格结果**：引用原证据 ID，核对粒度、窗口与时点；同一事实不再查询一遍。旧报价不能证明今天可买，当前余额不能还原历史每日库存。
2. **系统有数据、尚未执行**：写清一项业务语言取证任务。例如“按采购明细唯一统计已审核未收量及预计到货日，按仓库和产品返回”；具体表、字段和 JOIN 由取数子图按授权 Schema 选择。该项在清单内且口径足够，就属于已安排，不要求审核前先执行完。
3. **只有基础事实，没有所需计算**：单列计算项，写明用哪些证据、怎样计算、产物是什么，并将实际使用的证据 ID 写入该项 depends；引用跨需求证据时，需求级 depends 也声明所引用的需求。
4. **系统没有、用户也没给**：给出具体确认事项和影响，不创建不存在的 SQL 查询。例：“请提供活动商品成本口径；未提供前仅比较收入，不得下增利结论。”已有来源的代理值可做具名情景，但不能改称事实。
5. **执行后才发现缺记录、空日期、过期或异常**：记录具体原因，按场景的缺数分支退回补证或降低结论。NULL、未知和真零分开，缺历史不等于无需求；能完成的其它部分继续。

为避免遗漏，可留下这个工作表；它是规划用说明，不是新增接口：

| 要回答的判断 | 需要哪项证据 | 已有/待取/待算/待确认 | 下一动作 |
|---|---|---|---|
| 新采购能否赶上缺口 | 首次缺口日、本次可承诺到货日 | 缺口待算；到货待确认 | 安排时点计算；向供应商确认本次交付 |
| 能否保证总预算 | 取整后货值、预算包含的费用 | 货值可算；运费未知 | 先给货值，补运费；不写总成本已满足 |

取数任务要说明业务时间及起止边界：确认出入库按确认时间，采购生效按审核时间，预计日不能当实际日，更新时间不能当完成日。多次取数无法同快照时记录时间差；一对多明细先去重/聚合，避免重复量。[ERP-WHS][ERP-PUR][ERP-SALES]

以快照时刻t0为库存起点，未来桶只覆盖t0之后尚未发生的部分；当前日若已过一半，不能把全天需求再扣一遍。半开区间如[start,end)含start、不含end，须统一业务时区。若输入只有全天总预测，先用当天已确认销售出库X_done得到剩余预测F_rem=max(0,F_day−X_done)，再按DEM-004匹配剩余锁单；X_done已影响当前库存，不从A再扣。若输入本来就是剩余预测，直接用，不再减X_done；如果跳过今天余下时间直接预测明天，先安排两者之间的供需衔接。

**本步留下**：已有引用、待取证项、计算依赖、外部确认事项。足以规划时进入所选场景；如果决定动作的关键条件仍未知，交付“条件候选+补证任务”，不要宣称已可执行。

## COM-004 第四步：比较动作并核销共享量

1. 每个候选先写“解决哪个仓品的哪段缺口、计划何时做”。未选候选可以各自模拟；要联合执行的动作必须放入同一份分配表。
2. 对组合按时间依次分配：先调拨覆盖的部分从外购需求中扣掉；某笔采购已计入既有到货，不能再次作为新增采购覆盖同一缺口。已锁销售需求按 DEM-004 去重，不能从 A 再扣一次。
3. 把每个共享来源的分配量相加，与其可承诺上限核对。超出就减少分配或增加别的来源，不能给两个目标仓分别承诺同一库存。MOQ/精度造成多买时，重新算资金和期末余量。
4. 按用户目标选择：期限是硬要求，先排除赶不上的候选；预算是硬要求，先检查同口径已知支出。剩余候选再比较货值、风险与操作次数。关键费用或到货未知时保留条件，不用自创综合分选“最优”。

**假设走一遍**：目标缺口20件；B仓确认可及时支援8件。组合里先分配调拨8件，再比较外购12件。如果供应商MOQ25件，外购不是12件，而是25件；组合共33件，超过缺口13件。此时回到候选比较：取得起订豁免、取消调拨改仅购25件，或由用户接受超补；不能把“8+12刚好20”直接提交。

**本步留下**：

| 候选 | 动作和时间 | 覆盖多少 | 多补/未覆盖 | 已知货值 | 关键确认项 |
|---|---|---|---|---|---|
| 仅外购 / 组合 | 分开列 | 从共享表核销 | 显式保留 | 按取整后数量 | 本次交期、额外费用等 |

按原架构由用户选择/调整候选并做可行性验证；涉及哪些取数由对应节点安排，本文不增加“确认前一律禁止取数”的规则。用户选中后，方案子图将其展开为 D 段待执行需求；必要可行性数据已有则复用。下一步 COM-005。[MS-PLAN][ERP-AI]

## COM-005 第五步：交接成需求，审核只找真正缺项

**方案子图怎样交接**：把选中方案中尚待完成的工作写成业务证据清单；不把整份专家手册复制进 instruction，不把下单混在查询计算里。下面是假设“测算已选外购方案”的清单示意，不是完整 DTO：

| 证据项 | 要做什么 | 来源 | 实际依赖 |
|---|---|---|---|
| 已有 N1-E1 | 当前仓品库存及单位 | 已有结果，直接复用 | — |
| 已有 N1-E2 | 已去重的逐日新增需求与目标 | 已有结果，直接复用 | — |
| D1-E1 | 目标仓品的未收采购量、预计到货及不确定项 | SQL | 无 |
| D1-E2 | 用库存、逐日需求和可达采购算完整余额日表、未覆盖缺口列表及期末净补量，并保留期末目标 | PYTHON | N1-E1、N1-E2、D1-E1 |
| D1-E3 | 选中供货关系的报价、有效期、起订量、数量精度及交期依据 | SQL | 无 |
| D1-E4 | 用余额日表先确定本次外购承担的时点需求，按供货条件取整，再将新到货插回日表算货值、额外库存与未覆盖风险 | PYTHON | D1-E2、D1-E3 |

D1 的需求级 depends 包含 N1。若本次到货承诺来自用户确认，明确作为参数来源；不能说 D1-E3 查询历史均值就取得了本次承诺。清单已有合格证据则引用原 ID，不额外建重复项。

**need_review 按顺序做**：

1. 读这条待审需求的目标，按 COM-001 找到相应场景，只沿它选中的路线检查。
2. 对每个声称要产出的判断问：“清单已安排哪些输入、哪个计算项会用它们？”缺实际执行结果本身不是问题；缺必要输入、口径不支持或根本取不到才报。
3. 检查共享量、窗口、假设和跨项引用是否足以支持判断。只是查当前安全线差额，不因没有预测而退回；只筛促销候选，不因没有完整利润模型而退回。
4. 缺项时指到证据项 ID，写业务后果和具体修改动作。例如：“D1-E4 将保证按时补货，但 D1-E3 只有历史平均交期；请补本次可承诺到货及来源，或将结论改为历史交期情景，并在 D1-E4 同步核验首次缺口。”
5. 必需工作已覆盖则通过；结构校验归 need_check，数值执行与结果核验归后续链路。当前审核节点不执行 SQL、不出方案、不新增需求，也不负责修正固定专家公式。[ERP-AI]

**最终交付**：有结果时交“建议动作、数量、时点、已知金额、依据、仍需确认”；仅完成规划时交“待取证清单、计算依赖、候选条件”，不要写成已经取数、下单或执行。当前调拨链、促销费用和完整销货成本能力不足时，按对应手册说明可做部分，不凭空宣布闭环完成。[ERP-PUR][ERP-WHS][ERP-SALES]
