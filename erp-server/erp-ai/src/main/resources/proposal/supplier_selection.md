# 专家知识 · 供应商选择操作手册

> 版本2.1；核对日期：2026-10-24。贯穿案例为教学假设；来源索引见作者指南，不代表已取得供应商承诺。

## SUP-001 候选准入：先做候选表，再区分不满足与尚未知

拿到“选哪家供应商”的问题，从这里开始。最短路线：SUP-001列候选并核硬条件→SUP-002看同维度历史评分→SUP-003核本次到货→SUP-004给主候选、替补及确认项。只查询评分时停在SUP-002，不强制完成采购策略；只比较已知报价时，可先交付价格表，但不能扩大成已可执行采购推荐。

规划时复用已经取得的合格证据；没有数据时，先把需要的查询、供应商确认与计算安排进清单。必要可行性取证可以服务候选比较，不要求所有查询等到用户选择后才允许；用户确认方案后，方案子图再围绕所选动作派生D需求。执行链依现有协议取数、计算，知识本身不新增工具或授权写订单。审核检查证据清单的完整性，不把尚未运行当成没有安排。

**现在做：建立一个在同一采购条件下比较的表。**

1. 固定产品、单位、外购剩余缺口、要求到货日与预算覆盖范围。复用REP/PUR的缺口，不重新加入已锁销售；不知道还需外购多少时，安排补货核算，而不是先按供应商分数下结论。
2. 安排查询该产品已有的供货关系、供应商与产品状态、报价及有效期、MOQ，核对产品与供货关系归属。本次实时可供量和承诺到货日期须向供应商确认并记录来源，历史采购不能推出实时产能。同名、相似规格或低价产品不能直接当成可互换替代品。
3. 逐项标结果：已知满足的保留；已知违反用户确认硬条件的剔除出本轮可行候选，并写原因；未知的标“待确认”，既不当通过，也不自动判不合格。合同例外和企业政策须有来源，不能把模型偏好升格为硬规则。
4. 先按PUR-001/002算本次实际批量与货值，再比较单价；别忽略MOQ造成的多买、税费口径和报价适用日。系统接口未全面硬校验起订及报价有效，不等于方案可忽略它们。

**贯穿教学例**：需要产品P共20件，第4日前到，预算900元。甲30元/件、MOQ100件；乙35.20元/件、MOQ25件，精度0，两家状态与报价均假设有效。甲需100件、货值3000元，乙需25件、货值880元；已知甲超预算，不能因为单价低把它排第一。乙的运费和本次交付能力未知，先保留待确认。

**本步留下**：候选、产品/单位、数量与起订、报价时效、已知货值、已知硬不满足原因、未知项。候选表齐→SUP-002；无候选满足→明确是已知条件冲突还是数据不足，给可协商条件，不伪造新供应商。[ERP-PUR]

## SUP-002 历史评分：先看缺项和维度，再解释分数

**现在做：给候选表补历史表现，避免用一个分数替代全部判断。**

1. 复用或安排查询供货关系推荐分、产品级价格/质量分、供应商级交付/服务分及样本时间、READY/NOT_READY。数值先按COM-002还原为0至100；供应商综合分与某产品推荐分分列，不能随意混搭。
2. 先查必要分项是否为NULL。任一缺失→综合不可用，写明缺项；不是0分，不重新分配固定权重，也不以缺评分直接淘汰供应商。必要输入齐→才解释既有计算：S=0.3S_p+0.3S_d+0.3S_q+0.1S_s，分别为价格、交付、质量、服务分。
3. 需要解释原因时，检查分项业务口径：价格分S_p=min(100,参考采购价/有效报价×100)，价格先统一元；质量分S_q=合格金额/(合格金额+不合格金额)×100，依据完全入库样本，不是件数合格率；交付分S_d=clip(100×(1-逾期折算罚额/到期应交金额),0,100)，clip限制到0至100。分母为0不能算有效分。
   - 价格分还要求参考采购价>0、有效报价>0、供货关系启用且报价有效期满足评分业务日；否则为NULL，不是0分。质量金额分母>0而合格金额=0时，是有效0分；交付/服务的有效0分同样保留。缺项检查只看NULL或缺失，不用“分数为0”判断。具体分项按现有服务的放大与舍入结果解释，不用展示分数重建另一套近似评分。
4. 质量取完成收货窗口样本；交付还包含已到期但未完全入库订单，已交按实际确认日、未交余额按业务日计罚。窗口、系数与舍入沿用评分服务，供应商价格汇总按相应样本金额加权，不另造一套评分。

**例子继续**：假设甲价格90、交付80、质量100、服务70，既有评分为27+24+30+7=88。乙服务分缺失，推荐分应为空。记录“甲历史88但本轮已知超预算；乙评分不全，仍可继续核实价格与交付”，不能因为88好看而反转预算硬条件，也不能把乙当0分。

**本步留下**：同维度分项、综合是否可用、样本/更新时间、缺项及与本次目标的关系。只要用户查询评分→交此表及解释；需要实际选供应商→SUP-003。审核确认清单已安排必要分项，不要求规划时重跑评分系统；高历史分也不是本次交货保证。[ERP-PUR]

## SUP-003 交期判断：把历史平均、当前逾期与本次承诺分开

**现在做：判断候选能不能赶上本次日期，而不是只抄一个平均天数。**

1. 查询本产品供货关系已有的avg_delivery_days、样本依据与更新时间；本次实时可供量和承诺到货日另向供应商确认并记录来源，不能暗示ERP已经保存实时产能或本次供货承诺。供货关系均值对应本产品；供应商级均值可能混合其他产品，不能不说明就替代。
2. 理解历史数：只取完全入库采购，单笔周期l_i=max(0,fully_received_at-approved_at)/86400天，时间差按秒；明细金额a_i为权重，L_hist=Σ(a_i×l_i)/Σa_i，保留两位小数。不要把它说成按订单简单平均、固定交期或供应商当前承诺。
3. 检查偏差：实际查询起点为计算日减180天零点，只在完全收货回写时更新；无新样本可能保留旧值，非每次查询滚动更新。部分入库无完整终点，不进均值；长时间未完成慢单被排除，完成样本可能偏乐观。因此同时查看当前逾期未收，不只选择好看的完成订单。
   - 上述“计算日”是最近一次实际重算日，不一定是本次查询日；主数据update_time也可能由其它修改刷新，不能当统计重算时间。无可核实重算依据时注明新鲜度未知；有权限取基础采购事实时，可按本次明确窗口重算对照并标明口径，不冒称原字段实时值。
   - 本服务样本须有审核/完全收货时间、供货关系ID且明细金额a_i>0，分母Σa_i>0才算新均值；无有效样本会保留旧值，不能解释为0天。有效同日完成所得0天可以参与加权，NULL不当0天。时间差为负虽被代码截0，发现这种异常时仍列数据核对，不能据此认为供应商交付极快。
4. 有明确本次承诺→按其量与日期交REP-003核首次缺口；只有历史均值→列“历史交期情景，待确认”；承诺已知晚于要求→按原条件不能解决急缺，进入SUP-004讨论替补或拆批。均值NULL不填0，不从采购频率猜实时产能。

**可复算例子**：两笔完成样本分别4天/金额1000元、8天/金额3000元，历史加权均值=(4×1000+8×3000)/4000=7天；不是简单平均6天，也不保证下一单7天。继续前例，若乙仅愿第6日整批到25件，它不能解决第4日前20件的需求，需要确认分批或另找供应。

**本步留下**：历史均值的层级/样本/更新时间、当前逾期、已确认本次量和日期、尚待确认的量与日期，三种信息分列。交SUP-004；若用户只要历史交期，交付历史统计即可。需要固定提前期安全库存时，不能拿L_hist自动满足DEM-005假设。[ERP-PUR]

## SUP-004 推荐与替补：按用户目标交付可执行条件，不发明总权重

**现在做：综合候选表，明确推荐成立的条件与后续行动。**

1. 先按已确认目标比较：紧急补缺优先检查能否按时，预算限制比较同口径总货值及费用，质量关注看对应样本分项。若交期、金额和风险不能同时占优，列出取舍请求确认；没有企业权重或集中度上限，不自行算一个新“总分”或固定七三分单。
2. 需要多来源时，列每家拟分配量与到货批次，合计覆盖需求；逐家重验MOQ、精度、报价、费用和预算，并按REP-003看时间。共享供应或产能只分配一次，见COM-004。缺运输费不假定拆单免费，缺供货承诺不以历史均值补成事实。
3. 推荐与未验证条件分开。已知满足全部本轮条件→给主候选及理由；部分未知→给“优先核实候选”与确认清单；已知均不满足→说明原条件下没有满足要求的候选，提出可协商日期、批量或预算，不凭空创建替代品或保证产能。
4. 用户确认所选路线后，派生具体D需求或复用已有合格证据，安排计算调整后货值、批次供需与余量。审核关注这些已声称结论是否都有必要证据及依赖，不对纯评分查询强制补整套采购模型；未取得证据的结果不写成已执行。

**前例收口**：若教学后续确认乙运费15元，且接受25件按第3日20件、第6日5件交付，则已知总额895元；在账面可用、质量等复核同样通过的条件下，乙可作为本轮推荐，说明多买5件及历史评分缺项。甲仍不是现条件下可行替补：只有取得起订例外、重新确认对应报价并满足预算/交期后，才能恢复比较。

**交付模板**：

| 对象 | 本次数量/已知金额 | 到货与预算判断 | 历史证据 | 下一步 |
|---|---|---|---|---|
| 主候选或优先核实候选 | 原缺口、实际采购量、多买量、货值及已知费用 | 已满足/已知不满足/待确认，并给原因 | 同维度评分、缺项、交期样本局限 | 哪项需用户决定，哪项安排取证或复核 |
| 替补 | 条件变化后需重算的数量与金额 | 重新准入条件 | 不确定性 | 触发条件及所需确认 |

输出包含推荐理由、放弃其他候选的具体原因、替补触发条件及待办证据。无实际成本不伪造COGS或利润，不替用户创建采购单。完成后交方案确认与既有执行链，权限和审核范围按COM-001/COM-005。[ERP-PUR][MS-PLAN]
