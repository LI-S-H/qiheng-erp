# 补货规划

## 硬规则

- 先判断场景，再决定要什么证据；不因为用户提到"采购"就自动进入采购、预测或经济批量。
- 不编造数量和日期：缺参数时先确认，不能自设 14 天、自选安全库存或用行业值填补。
- 交办给分析专家时写清口径：仓库、产品、时间范围、期末目标、数据来源。

## 场景判断

| 用户问法 | 场景 | 交付 |
|---|---|---|
| 现在缺什么、离安全线差多少 | 当前缺口 | 仓品差额表 |
| 未来两周够不够、要补多少 | 未来缺口 | 净补货量、首次缺口日、候选动作 |
| 已有一批采购但来晚了 | 到货延迟 | 最早未覆盖缺口、可补救条件 |
| 已经决定买或调拨 | 交给采购或调拨技能 | 调整后的数量 |

## 当前缺口

需要确认：目标仓库、产品、是否排除停用主数据。

需要的证据：当前账面库存、仓储锁定、产品安全库存、单位与数量精度。

交办：让分析专家计算可用量和安全线差额。

停止：用户只要当前差额时，交付差额表即结束，不自动进入未来预测。

## 未来缺口

需要确认：覆盖到哪天、期末要保留多少；未确认时先问，不默认 14 天。

需要的证据：

- 已有去重的逐日新增需求，或包含既有订单的总预测
- 已审核未收采购的剩余量和预计到货日

交办：让分析专家展开日表，找首次缺口日和期末净补量。

停止：覆盖期间和期末目标未确认时，只给"跌破零的风险"，不宣称满足自创目标。

## 到货延迟

需要确认：哪批采购、原预计到货日、本次可承诺到货日及依据。

需要的证据：未收采购明细、当前库存、期间需求。

交办：让分析专家把在途排进日表，检查是否还有更早的缺口。

停止：到货证据只来自历史均值时，标注为情景，不承诺按时。

## 交付判断

拿到分析结果后：

- 先说结论：当前是否低于安全线、未来哪一天首次不足、需要补多少。
- 再给关键依据：可用量、首次缺口日、净补货量。
- 最后列限制：哪些到货日期是承诺、哪些是历史估计、哪些参数仍需确认。

## 不做的事

- 不在这里写公式和取整规则；需要时加载 `common`。
- 不自己取数或计算，交给分析专家执行。
