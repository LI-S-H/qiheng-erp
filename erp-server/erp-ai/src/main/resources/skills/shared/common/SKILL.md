# 通用方案规则

## 硬规则

- 库存、锁定、订单数量按库内值除以 100 还原；交易单价和金额按分除以 100；产品参考价是元，不再除。
- 每个数字必须有来源：已有结果的证据 ID、本次查询结果，或明确标注的假设。没有来源就写"待确认"，不填猜测值。
- 只读，不修改任何业务数据。
- 缺数据和真零分开：缺历史不等于无需求，缺记录不等于零库存。

## 单位与取整

| 输入 | 库内口径 | 进入计算 |
|---|---|---|
| 库存、锁定、订单数量 | 真实数量 ×100 | 除以 100 |
| 交易单价、金额 | 分 | 除以 100 |
| 产品参考价 | 元 | 直接用 |
| 评分 | 真实分值 ×100 | 除以 100 |
| 历史平均交期 | 天 | 直接用，标注是历史统计 |

- 取整步长 = 10 的负 quantity_precision 次方。
- 满足最低需求时向上取整，不超过库存或预算上限时向下取整。
- 起订量 MOQ 只是下限，不能当包装倍数。
- 取整后必须重算金额和约束；最低所需量大于实际上限时，该候选不成立，不能削量后声称足量。

## 证据清单

对每一项输入按顺序判断：

1. 已有合格结果：引用证据 ID，核对粒度、窗口和时点。
2. 系统有数据但未执行：写成一句业务语言的取证任务。
3. 只有事实没有计算：单列计算项，写明输入、算法和产物。
4. 系统和用户都没有：给出确认事项和影响，不编造查询。
5. 执行后发现缺失或异常：记录原因，降低结论或退回补证。

## 动作比较与共享量

- 每个候选写清楚解决哪个仓品的哪段缺口、计划何时执行。
- 共享来源的分配量必须相加后与可承诺上限核对，不能给两个目标仓承诺同一库存。
- 已计入既有到货的采购量，不能再次作为新增采购覆盖同一缺口。
- 期限和预算是硬约束时先排除不满足的候选，不用自创综合分选"最优"。

## 验证门

- 账面可用 A = 账面 H − 仓储锁定 R；出现负值或 R 大于 H 时，该行停止承诺可用量。
- 同一事实不在两个场景重复扣减。
- 交付前用第二种方式复算关键数字，例如用明细汇总校验合计。
- 结论必须区分：已确认事实、计算结果、仍需确认的假设。
