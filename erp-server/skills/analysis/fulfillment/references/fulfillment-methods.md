# 订单履约方法

## 待发量口径

```text
待发量 = 订单数量 − 已出库数量
```

- 只统计已提交、已审批、部分出库三种状态
- 草稿不占用库存，已取消不发货，都不计入
- 按仓库和产品汇总，不能用全公司总量代替，货在哪个仓决定能不能发
- 数量按业务数量，不按金额

## 缺口计算

```text
缺口 = max(0, 待发量 − 账面库存 − 交付日前可到的在途)
```

- 用账面库存 `stock_qty`，不用可用库存：待发订单的货已经锁定在账面里
- 可用库存 `stock_qty − locked_qty` 只用于判断还能不能接新单
- 在途只有预计到货日早于交付日才计入
- 缺口大于 0 表示按当前供给无法按时发完

## 覆盖率

```text
覆盖率 =（账面库存 + 交付日前可到在途）÷ 待发量
```

| 覆盖率 | 含义 | 处理 |
|---|---|---|
| ≥ 1.0 | 能覆盖 | 正常发货 |
| 0.9 – 1.0 | 临界 | 跟到货，准备备选 |
| < 0.9 | 不足 | 列入风险，给处置选项 |

- 临界区间要考虑在途到货波动，不能直接按能覆盖处理
- 覆盖率只在待发量大于 0 时计算

## 风险分级

按优先级从高到低：

1. **逾期**：交付日已过且未发完，按逾期天数排序
2. **高风险**：缺口大于 0 且没有能赶上的在途
3. **有条件风险**：缺口大于 0 但有在途能赶上，取决于到货是否准时
4. **潜在风险**：当前能覆盖，但发完后库存低于安全库存

## 处置选项

| 选项 | 适用条件 | 能解决多少 | 需要确认 |
|---|---|---|---|
| 调拨 | 其他仓有货且能赶上交付日 | 源仓可调出量 | 运输时效、源仓保留 |
| 催采购 | 在途晚于交付日 | 提前到货的部分 | 供应商能否提前 |
| 拆单 | 部分有货 | 有货部分先发 | 客户是否接受分批 |
| 延期 | 供给确实不足 | 全部或部分 | 客户是否同意新日期 |

- 四个选项要写清各自解决多少、剩余多少
- 多个选项组合时，合计不能超过缺口
- 调拨和催采购都依赖外部确认，不能承诺一定赶上

## 调拨可行性

- 源仓可释放量 = 净可用 − 保留量，口径与 `transfer` 技能一致
- 源仓调出后不能低于安全库存
- 运输时间系统里没有，需要物流确认，赶不上交付日则不能作为方案

## 历史履约率

```text
履约率 = 按期出库订单数 ÷ 已出库订单数
```

- 按期 = 出库确认日不晚于客户要求交付日
- 窗口与本次分析一致
- 样本少于 20 单时只作参考
- 履约率低说明是系统性问题，要结合库存和补货规则一起看

## 锁定核对

- 订单锁定量合计应接近待发量
- 锁定少于待发量：有订单没预占库存，存在超卖，后续可能被其他订单抢走
- 锁定多于待发量：可能有已完成或取消订单没释放锁定，账面可用量被低估
- 核对结果要单独说明，不要和缺口混在一起

## 边界情况

| 情况 | 处理 |
|---|---|
| 没有交付日 | 按订单创建日加默认交期估计，标注是估计 |
| 没有在途 | 缺口按无在途计算，说明会偏大 |
| 没有锁定 | 跳过硬核对，提示超卖风险无法确认 |
| 库存记录缺失 | 按该仓不铺此货处理，不当成 0 |
| 多个订单同一产品 | 按交付日先后分配，先到期先保 |
| 交付日已过 | 单列逾期，按天数排序 |
| 客户要求变更 | 系统无记录，需业务确认 |

## 复核

- 发货后核对实际出库日与交付日
- 逾期订单跟踪原因：缺货、库存分配、物流
- 履约率持续下降时，回到补货和库存策略检查
