# 采购执行计算

## 能算出的结果

| 结果 | 需要的数据 | 算法 | 输出 |
|---|---|---|---|
| 调整后采购量 | 缺口、MOQ、精度、包装 | 向上取整到步长 | 数量 |
| 多买量 | 调整后数量、缺口 | 差值 | 数量 |
| 货值 | 数量、单价 | 数量 × 单价 | 元 |
| 预算可用量 | 预算、已发生费用、单价 | 预算除以单价后取整 | 数量 |
| 到货可行性 | 要求到货日、供应条件 | 日期比较 | 结论 |
| 经济批量 | 年需求、订货成本、持有成本 | EOQ | 批量 |

## 算法与口径

- 步长 u = 10 的负 quantity_precision 次方
- 有包装步长 b 且 b 能被 u 整除时用 b
- 采购量 = ceil(max(缺口, MOQ) / 步长) × 步长
- MOQ 是下限，不是包装倍数
- 货值 = 各候选数量 × 单价之和，金额按元
- 预算可用量 = 步长 × floor((预算 − 已发生费用) / (单价 × 步长))
- 报价必须先确认有效期、币种和是否含税；过期报价只能作参考，不能直接用于下单决策
- 公式细则见 `references/purchasing.md`

## 计算步骤

### 第一步：确认可采购量

- 从补货结果取缺口：期末净补量和未覆盖的救急量，两者不能直接相加
- 已经由调拨或已有在途覆盖的部分先扣掉，避免重复采购
- 没有经过时点核验的缺口写"待定"，不能填 0
- 可采购量为 0 时停止，不因为 MOQ 强买
- 只有期末净补量为 0、但中途有缺口时，先调用 `replenishment` 技能确认救急量，不在这里自行加量

### 第二步：逐候选取整

- 步长 u = 10 的负 quantity_precision 次方
- 有包装步长 b 且 b 能被 u 整除时用 b
- 采购量 = ceil(max(可采购量, MOQ) / 步长) × 步长
- 多买量 = 采购量 − 可采购量
- 例：缺口 26 件、MOQ 25 件、精度 0，采购量是 26 件，不是 50 件
- 例：缺口 26 件、MOQ 25 件、每箱 12 件，采购量是 36 件
- MOQ 未知时保留候选并标注待确认，不能默认为 0
- 包装步长不能被精度整除时，先确认换算规则，不直接套公式
- 不同产品不能为了凑 MOQ 混合下单，除非有合同依据

### 第三步：按调整后数量核价

- 货值 = 各候选采购量 × 确认单价之和
- 阶梯价按实际采购量落入的档位计价
- 报价先确认有效期、币种、是否含税
- 过期报价只能作为参考，不能用于下单决策
- 同一候选有多个报价时，按同口径比较，不混用含税和不含税

### 第四步：核对预算

- 先确认预算覆盖哪些费用：只含货值，还是含运费和税
- 预算可用量 = 步长 × floor((预算 − 已发生费用) / (单价 × 步长))
- 估算数量偏低时，按实际计价再检验一次，不直接判失败
- 多产品共享预算时逐项计价后汇总，不套单项简式
- 超出预算时列出超出金额，不只写"超预算"

### 第五步：检查到货

- 比较本次承诺到货日和首次缺口日
- 分批到货时逐批核对，每批都要早于对应缺口日
- 到货日只有历史平均交期时，标注为情景，不承诺按时
- 数量够但到货晚于首次缺口日，结论是未解决，不能写成能接上

### 第六步：经济批量

- 只有用户明确要求优化批量时才计算
- 先检查是否有每次订货成本和单位持有成本，缺参数就返回缺什么，不估算
- EOQ 只作基准，最终采购量仍要按 MOQ 和精度取整
- 需求波动大或有批量折扣时，说明 EOQ 会低估合适批量

## 多候选比较

每个候选输出一行，按可执行性排序：

| 候选 | 采购量 | 多买量 | 货值 | 预算占用 | 到货日 | 是否解决首次缺口 | 待确认 |
|---|---|---|---|---|---|---|---|
| 供应商甲 | | | | | | | |

- 数量够且到货早于首次缺口日的排在前面
- 需要补确认价格或交期的排在后面，逐项列出待确认内容
- 数量接近时，多买量和资金占用作为次要参考
- 不要用自创的综合评分选"最优"，把差异列出来让用户决定

## 边界情况

| 情况 | 处理 |
|---|---|
| 阶梯价 | 按实际采购量落入的档位计价；跨档时比较相邻档位的总价，取更低的合法档位 |
| 部分到货 | 逐批核对日期和数量，未到部分不视为已覆盖 |
| 起订量豁免 | 有合同或供应商书面确认时可按实际缺口下单，记录依据 |
| 报价过期 | 只能作参考，下单前要求重新报价 |
| 多产品共享预算 | 逐项计价后汇总，按用户给定的优先级分配，优先级未给时先问 |
| 已有在途覆盖 | 先从缺口扣掉，不重复下单 |
| 数量很多、候选很多 | 先按能否赶上首次缺口日筛掉一批，再比较其余候选 |

## 数据不足时

- 缺 MOQ：保留候选并标注待确认，不按 0 计算
- 缺精度：不取整，标注未取整
- 缺单价：只给数量，货值不计算
- 缺预算费用项：只报已知货值，不判断预算满足
- 缺到货依据：标注为情景，不承诺按时

## 验证门

- 采购量不小于缺口，也不小于 MOQ
- 采购量是步长的整数倍
- 货值按调整后数量计算，不按缺口计算
- 多买量 = 采购量 − 缺口，不能遗漏
- 到货日晚于首次缺口日时，结论必须是未解决
- 预算结论必须说明覆盖的费用项
- 各候选货值合计必须等于逐项相加结果，用第二种方式复算
- 采购量和货值的单位、币种在整份结果里保持一致

## 输出格式

按顺序返回，没有的写未提供：

1. 口径：缺口、候选、MOQ、精度、预算、到货要求
2. 各候选：调整后数量、多买量、货值
3. 预算：已知货值、可用额度、是否满足
4. 到货：能否早于首次缺口日
5. 建议候选和需要确认的条件
6. 限制：缺失数据、假设参数
