# 补货计算

## 硬规则

- 数量按库内值除以 100 还原，金额按分换算；取整规则按 `common`。
- 每个数字来自实际查询或计算，缺数据写"无法判断"，不用零或行业值填补。
- 只读，不修改业务数据。

## 输入要求

- 仓库、产品、期间起止日、期末目标
- 当前账面库存、仓储锁定
- 产品安全库存、单位、数量精度
- 已审核未收采购的剩余量和预计到货日
- 期间的逐日新增需求，或包含既有订单的总预测

输入不完整时，先返回缺少的项，不要用默认值继续。

## 当前缺口

1. 还原业务数量：账面库存和仓储锁定都除以 100。
2. 可用量 A = 账面库存 H − 仓储锁定 R。H 或 R 缺失时该行标记"未确认"，不当零处理；负值或 R 大于 H 时停止对该行承诺。
3. 差额 G = max(0, S − A)。
4. 分支：
   - A 大于 S：未低于安全线，G = 0。
   - 0 小于 A 且 A 不大于 S：列低库存提示和 G。
   - A = 0：说明无未占用库存。
   - S 缺失：只给 A，并说明无法判断安全线差额。

产物：仓品差额表，列仓库、产品、单位、快照时点、H、R、A、S、G、异常说明。

## 未来缺口

1. 逐日新增需求：
   - 有总预测 F_t 且已锁定销售 C_t：D_new,t = max(0, F_t − C_t)
   - 预测已排除订单：直接用 F_t
   - 期间合计为各日相加
2. 从当前快照逐日滚动余额：

   ```text
   PAB_free(t) = A + 截至 t 的可达到货 − 截至 t 的逐日新增需求
   ```

   可达到货只加截至当天可达且未被其它动作占用的量；已锁订单不再扣。
3. 记录首次为负的日期和数量。负值是未覆盖需求，不是允许的负库存；未来到货不能倒填之前的缺口。
4. 期末净补量 = max(0, 期间新增需求合计 + 期末目标 − A − 期间可达到货)。

产物：逐日余额表，列日期、当日新增需求、累计需求、可达到货、余额；另给首次缺口日和期末净补量。

## 到货延迟

1. 未收采购按明细剩余量计算：订单数量减已入库数量。
2. 按预计到货日排入日表：
   - 日期有效：放到可达日，标注是计划不是实际收货。
   - 日期已过、为空或失约：保留未收事实，单列待确认，保守情景不计。
   - 期间之后才到：不覆盖期内缺口，但保留后续敞口。
3. 重新滚动余额，找最早未覆盖的日期。
4. 若只增加一批在 τ 时点可用的供应，先检查所有 τ 之前的时点：

   ```text
   若 τ 之前任一余额为负，本批无法解决更早的缺口。
   需要量 = max(0, τ 之后的最大负余额到 0 的距离, 期末目标 − τ 时点余额)
   ```

   多批、多来源或原采购改期时不用这个简式，回完整日表重算。

## 验证门

- A = H − R 且 A 不小于 0；R 大于 H 时该行异常。
- A 大于 S 时 G 必须为 0。
- 逐日新增合计必须与逐日明细一致，用第二种方式复算。
- 首次缺口日之前余额不得为负，之后才允许出现负值。
- 期末净补量为 0 不等于中途没有缺口，必须单独检查首次缺口日。
- 取整后重算金额和期末余量。

## 输出

返回：输入口径、证据 ID、逐日余额表、首次缺口日、期末净补量、候选动作及限制。

不向用户下最终结论，不写"已下单"。
