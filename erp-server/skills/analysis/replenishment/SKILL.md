# 补货计算

## 能算出的结果

| 结果 | 需要的数据 | 算法 | 输出 |
|---|---|---|---|
| 可用量 | 账面库存、仓储锁定 | H − R | A |
| 安全线差额 | 可用量、安全库存 | max(0, S − A) | G |
| 逐日需求 | 历史出库、锁定订单 | 移动平均、指数平滑、趋势、Croston | D(t) |
| 逐日余额 | 可用量、在途、逐日需求 | 滚动累加 | PAB(t) |
| 首次缺口 | 逐日余额 | 第一个负值 | 日期和数量 |
| 净补货量 | 期间需求、期末目标、可用量、在途 | 期末目标 − 可用 − 在途 + 需求 | Q |
| 安全库存 | 需求波动、交期波动 | max/min 或服务水平 Z 值 | SS |
| 经济批量 | 年需求、订货成本、持有成本 | EOQ | 批量 |

## 算法选择

- 需求平稳：移动平均 3 到 7 期，或指数平滑 α 0.2 到 0.4
- 有明显趋势：Holt 线性趋势
- 有季节性：Holt-Winters
- 间歇性需求、大量零值：Croston
- 历史不足 3 到 4 期：返回数据不足，不给预测
- 有服务水平要求和足够数据：Z 值法算安全库存
- 只有观测到的最大最小值：max/min 法
- 批量：EOQ 只作基准，最终按 MOQ 和数量精度取整

预测方法的公式、参数和历史长度要求见 `references/forecasting.md`。
滚动余额、单批补救、取整和安全库存公式见 `references/inventory-calc.md`。
需要具体计算时先读取对应文件。

## 计算步骤

### 当前缺口

1. 数量按库内值还原：库存、锁定、订单都除以 100；产品参考价是元，不再除
2. 可用量 A = H − R
   - H 或 R 缺失：该行标记未确认，不按零处理
   - A 小于 0，或 R 大于 H：停止对该行承诺可用量，其他正常行继续
3. 差额 G = max(0, S − A)
4. 分支：
   - A 大于 S：未低于安全线，G = 0
   - 0 小于 A 且 A 不大于 S：列低库存提示和 G
   - A 等于 0：说明没有未占用库存
   - S 缺失：只给 A，说明无法判断安全线差额

输出：仓品差额表，列仓库、产品、单位、快照时点、H、R、A、S、G、异常说明。

### 未来缺口

1. 逐日需求：有总预测 F 和已锁定销售 C 时，D = max(0, F − C)；预测已排除订单时直接用 F
2. 从当前快照逐日滚动余额，可达到货只加当天可达且未被其他动作占用的量
3. 找第一个负值，记录日期和金额
4. 净补货量 = max(0, 期间新增需求合计 + 期末目标 − A − 期间可达到货)

滚动公式和边界处理见 `references/inventory-calc.md`。

### 到货延迟

1. 未收量按明细算：订单数量 − 已入库数量
2. 按预计到货日排入日表，日期已过或失约的单列待确认，保守情景不计
3. 重新滚动余额，找最早未覆盖的日期
4. 单批补救时先检查更早的时点是否还有缺口

单批补救公式见 `references/inventory-calc.md`。

## 数据不足时

- 安全库存缺失：只报可用量，不判断是否低于安全线
- 历史不足：返回数据不足，不给预测
- 到货日期缺失：给确定和不确定两张日表，不写保证不断供
- 数量精度缺失：不取整，标注未取整

## 验证门

- A = H − R，且 A 不小于 0；R 大于 H 时该行异常
- A 大于 S 时 G 必须为 0
- 逐日需求合计必须等于逐日明细之和，用第二种方式复算
- 首次缺口日之前余额不能为负，之后才允许
- 净补货量为 0 也要单独检查首次缺口，总量够不等于中途不断供
- 取整后重算金额和期末余量

## 输出格式

按顺序返回，没有的写未提供：

1. 口径：范围、期间、期末目标、数据来源和快照时点
2. 当前状态：H、R、A、S、G
3. 时间线：逐日余额表，包含日期、当日需求、当日到货、余额
4. 首次缺口：日期和数量，全期无缺口写无
5. 净补货量：覆盖了哪些日期、哪些日期仍覆盖不到
6. 限制：缺失数据、假设参数、到货依据
