# 订单履约风险规划

## 什么时候用

- 这批待发订单能不能按期交付
- 哪些订单有断货风险、影响多大
- 客户催单，还来不来得及
- 要不要从别的仓调、要不要催采购
- 要不要拆单先发一部分

判断库存整体够不够用 `replenishment`；已经确定要对外采购用 `purchase`；需要仓间支援用 `transfer`。

## 系统边界

- 销售单有客户要求交付日 `expected_delivery_date`，没有承诺发货日字段
- 待发订单的货在提交时已经锁定，判断风险用的是库存总量与待发量的差，不是可用库存
- 系统没有仓间运输时效，调拨能否赶上交付日需要物流确认
- 系统没有发运单，交付完成以出库确认为准

## 规划流程

### 第一步：确认范围和时点

- 哪些仓库、哪些客户、哪些产品
- 看到哪一天为止的待发订单
- 是全部订单还是只看逾期和临近交付的

待发订单超过 100 条或覆盖多个仓库时，先给按仓库汇总的风险分布，选一个仓或一类客户再展开逐单判断，不要一次把所有明细都拉出来。

### 第二步：确认待发口径

- 待发量 = 订单数量 − 已出库数量
- 包含状态：已提交、已审批、部分出库
- 草稿和已取消不计入
- 按仓汇总，不能只看全公司总量，货在哪个仓决定能不能发

### 第三步：核对供给

- 各仓账面库存
- 在途采购及预计到货日
- 已锁定数量用于核对待发订单是否都被预占

在途只有在交付日之前能到的才算有效供给。

### 第四步：识别风险

| 情况 | 判断 |
|---|---|
| 库存足够覆盖待发量 | 无风险 |
| 库存不足，但在途能在交付日前到 | 有条件风险，跟到货 |
| 库存和在途都不够 | 高风险，需要处置 |
| 交付日已过仍未发 | 已逾期，优先处理 |

### 第五步：给处置选项

- 调拨：别的仓有货，且能赶上交付日
- 催采购：在途晚到，确认能否提前
- 拆单：先发有货部分，剩余部分延期
- 延期：和客户协商新的交付日

每个选项都要写清能解决多少、还剩多少、需要谁确认。

### 第六步：交办分析专家

调用 `analyzeData`，不要自己用 `query_sql_data` 取明细。

- goal：写清范围、截止日期、要判断的订单和产品
- context：写明仓库、客户、交付日口径、是否包含部分出库订单
- 返回：待发量、缺口、风险订单清单、最早断点日期、处置建议

### 第七步：解读

- 先给整体履约率，再列风险订单
- 风险订单按交付日从早到晚排序
- 每个风险订单给出缺口和可选处置
- 说明调拨时效和采购到货日都依赖外部确认，不能保证

## 交付要求

- 待发量按仓汇总，不只给总数
- 缺口计算说明是否扣了在途
- 风险订单列出客户、产品、交付日、缺口
- 处置选项写明能解决多少、剩余多少
- 已逾期订单单独列出

## 常见误判

- 用可用库存判断风险，忽略已锁定的待发订单
- 只看全公司总量，不看仓库分布
- 把在途当可用，忽略到货日
- 拆单时没有说明剩余部分怎么处理
- 承诺调拨一定能赶上，不确认运输时效
- 把草稿订单也算进待发量

## 相关技能

- 需要跨仓支援：`transfer`
- 需要对外采购：`purchase`
- 补货缺口怎么算：`replenishment`
