# 采购执行规划

## 什么时候用

- 缺口已经确认，要决定买多少
- 起订量和包装会导致多买，怎么处理
- 预算够不够、不同报价怎么比
- 什么时候到、能不能接上首次缺口

缺口还没确认时，先调用 `replenishment` 技能完成缺口计算，再回到本技能。

## 规划流程

### 第一步：确认缺口来源

- 外购量来自补货的净补货量，还是救急量
- 是否已经有调拨（`transfer`）或其他供应覆盖
- 没有经过时点核验的缺口，先回补货确认

### 第二步：确认候选和起订条件

- 候选供应商和本次有效报价
- 供应商评分直接引用系统结果，不在采购环节重算
- 起订量 MOQ
- 数量精度 precision
- 是否有整箱、整托的包装步长

缺 MOQ 或精度就问，不能默认 0。

### 第三步：确认时间要求

- 首次缺口日
- 本次要求到货日和依据
- 能否分批到货

### 第四步：确认预算口径

- 预算只含货值，还是含税、运费
- 是否有阶梯价或最低起订金额

### 第五步：交办分析专家

调用 `analyzeData`，不要自己用 `query_sql_data` 取明细。

- 目标：算采购量、货值、到货可行性
- 输入：缺口、候选、MOQ、精度、预算、到货要求
- 返回：各候选调整后数量、多买量、货值、预算占用、到货结论

### 第六步：解读

- 数量够但来晚，不能说解决
- 多买要说明期末余量
- 预算只覆盖部分费用时，不宣布预算满足

### 第七步：反馈给补货

采购确认或变更后，回补货更新日表：

- 实际到货日晚于预期：回补货重新检查首次缺口
- 实际到货数量多于计划：更新期末余量
- 采购取消或改期：回补货重算缺口
- 这些变化会改变后续的补货结论，不能只在采购侧记录

### 第八步：需要草稿时交给用户确认

规划完成后，如果用户需要生成采购草稿，调用 `prepare_purchase_order_draft` 把方案交给用户确认，并按 `purchase-order` 技能完成后续的创建、编辑、提交和取消处理。

草稿工具只负责把方案交给用户，创建动作由用户在确认页完成，不在本技能里直接写入。

## 交付要求

- 采购量按起订量和精度取整后给出，不直接给缺口
- 货值按调整后数量计算
- 到货日期标注是承诺还是历史估计
- 预算结论说明覆盖了哪些费用
- 候选按可执行性排序：能立即下单的排在需要补确认的前面，不按金额大小排

## 常见误判

- 把缺口直接当采购量
- 把 MOQ 当包装倍数
- 只看单价不看总货值
- 数量够但来晚，仍说能接上
- 预算只算货值，忽略运费和税

## 相关技能

- 缺口来源：`replenishment`
- 候选供应商和评分：`supplier-selection`
- 采购单创建、编辑、提交和取消：`purchase-order`
