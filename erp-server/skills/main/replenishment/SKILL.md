# 补货规划

## 什么时候用

- 现在缺什么、离安全线差多少
- 未来一段时间够不够、要补多少
- 已下的采购要晚到，还能不能接上
- 会不会断供、什么时候断

用户只是要查某个商品当前库存余额时，不需要走这个流程。

## 规划流程

### 第一步：判断是哪类补货问题

| 用户的表现 | 场景 |
|---|---|
| 只问现在 | 当前缺口 |
| 提到未来一段时间 | 未来缺口 |
| 提到已下单的采购、到货时间 | 到货延迟 |

依据是用户有没有提未来、有没有提在途订单，不是他用了哪个词。

### 第二步：补齐范围和时间

- 哪些仓库、哪些产品
- 覆盖到哪一天
- 期末要保留多少库存

用户没说就问。期间和期末目标不能自己假设，它们是后面所有计算的基准。

### 第三步：确认需求数据从哪来

- 期间内已有订单和预测：直接用，注明来源和时点
- 没有现成需求，用户给情景：按情景算，标注是情景
- 没有现成需求，用户要求预测：交给分析专家先做需求预测
- 都不满足：说明缺什么、影响是什么，不凭空假设日均需求

### 第四步：交办计算

交办内容必须包含：

- 目标：算当前差额，还是算未来缺口和净补货量
- 范围：仓库、产品、期间、期末目标
- 已知数据：库存快照、在途采购、需求来源
- 需要返回：差额表或逐日余额表、首次缺口日

分析专家完成计算，主智能体不自己算。

### 第五步：根据结果决定下一步

- 当前缺口：交付差额表，结束
- 未来缺口：有缺口进采购或调拨；没缺口说明依据
- 到货延迟：判断催交、改单还是另购

### 第六步：交付

先结论，再关键数字，最后限制条件。

## 交付要求

- 结论要回答用户最初的问题，不扩展到没问的范围
- 关键数字给出来源和时间点
- 限制要写：哪些数据缺失、哪些日期只是承诺、哪些参数是假设

## 常见误判

- 把安全线差额直接当采购量
- 期末总量够就说没问题，忽略中间断供
- 自己假设期间和期末目标
- 把仓储锁定里的订单再扣一次
- 只看最后一天余额
