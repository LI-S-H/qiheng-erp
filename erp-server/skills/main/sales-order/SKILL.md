# 销售单操作

## 动作一览

| 用户意图 | 调用工具 | 前置条件 |
|---|---|---|
| 生成新销售单 | `prepare_sales_order_draft` | 客户、出库仓库、产品和价格已确定 |
| 修改已有销售单 | `update_sales_order_draft` | 销售单已经存在，且状态为草稿或待审核 |
| 提交审核 | `submit_sales_order` | 用户同意提交，且单据是草稿 |
| 取消 | `cancel_sales_order` | 用户同意取消，且未出库、未部分出库 |

## 动作之间的关系

- **创建 → 编辑**：只有创建成功、拿到销售单号之后才可能进入编辑。用户在创建前说要改什么，那是创建参数，走创建，不要调编辑。
- **创建/编辑 → 提交**：动作完成后主动问一句是否提交，用户同意才调提交。
- **取消**：可以主动建议（例如客户已取消需求、库存无法满足、交付日谈不拢），但必须先说明理由并询问用户，同意后才调。不要直接调，也不要反复劝。
- 状态不允许时不要硬调：已审核及之后不能编辑；已出库、部分出库不能取消；已取消不用再取消。
- 工具返回的是结论文本：第一句说明用户做了什么；修改后确认和系统拒绝会附最终参数或当前单据 JSON，先读结论，需要精确数值时再读参数块。

## 创建

调用 `prepare_sales_order_draft`。

参数要求：

- 客户、仓库、产品一律传数字主键 ID，不能传 C0001、WH000001、P001029 这类业务编码
- 用户只给编码时，先用 `query_sql_data` 按编码查出主键 ID，再生成草稿：
  - 客户：`sales_customer.customer_id`
  - 仓库：`warehouse.warehouse_id`
  - 产品：`product.product_id`
- 编码直接提交会被业务接口拒绝（客户ID格式错误，必须为数字字符串），不能拿编码去创建
- 客户、仓库：真实存在且启用
- 明细产品：启用状态的产品，可以是任意产品
- 数量：按产品精度取整，不是随口估的量
- 单价：必须给出，用产品参考售价或用户明确的价格，不能编造
- 预计发货：用户给了交期就填，没有就留空；提交审核前必须补上
- 备注：可填，只在用户明确要求记录说明时填写

回执处理：

- **用户确认创建**：给出单号，说明是草稿；然后问是否需要提交审核。
- **用户修改参数后创建**：先读用户说明和修改字段，复述调整意图，说明影响（库存占用、交付能力、金额），数据依据调用 `analyzeData`；只改备注时只做一句确认。最后问是否需要提交审核。
- **用户驳回**：回应驳回原因，等用户给出新方向，不要按原参数再生成一次。
- **创建未通过**：判断是参数问题还是业务规则问题。参数问题修正后重新生成并说明改了什么；业务规则问题把规则原文告诉用户，给替代方案。

## 编辑

调用 `update_sales_order_draft`，传 `salesOrderId` 和完整业务参数：`customerId`、`warehouseId`、完整的 `items`，以及要改的日期、备注。确认卡片只用单据详情做展示底稿，不能替你补工具参数。

- 单据必须已经存在；不存在时不要调，先走创建
- 明细要传完整的 items，不要只传改动的那一行
- 如果上下文里没有当前单据的销售参数，先用 `query_sql_data` 查询单据详情或让用户提供；不要猜。确认卡片只做展示底稿，不替工具补必填参数
- 待审核状态编辑时，预计发货必须非空且不得早于今天；已锁定库存的单据不能改出库仓，要换仓先取消重下
- 已锁定库存的待审核单改数量时，提交后会按新数量重新校验库存

回执处理：

- **用户确认修改**：说明已保存和当前状态；原来是草稿时问是否提交。
- **用户修改参数后保存**：同创建的修改处理，说明影响。
- **用户驳回**：销售单保持原样，回应原因即可。
- **修改未保存**：状态不允许就把当前状态告诉用户；参数问题给修复建议。

## 提交

调用 `submit_sales_order`，只传 `salesOrderId`。

- 提交不产生新参数；预计发货为空时用户在卡片上补，不要编造
- 提交会校验并锁定可用库存，锁定后库存对其他销售单不可用；卡片和回复都要说清这一点
- 单据不是草稿时先说明状态，不要调用

回执处理：

- **用户同意提交**：说明当前是待审核、库存已锁定，下一步等主管审核，不要说成已出库。
- **用户暂不提交**：按原因回应，不要反复询问。
- **提交未通过**：看错误原文。
  - 缺预计发货：提醒用户在卡片上补，或走编辑补日期
  - 可用库存不足：给出缺多少、哪个仓库缺，建议改数量、换仓库或等采购到货后重提
  - 客户停用、状态不允许：不能靠改参数绕过，给替代方案

## 取消

调用 `cancel_sales_order`，传 `salesOrderId` 和从用户话里提取的 `reason`。

- 确认前提醒：取消是终态，不可恢复；已锁定库存会释放，未确认的出库单会作废
- 只有草稿、待审核和未出库的已审核单据能取消

回执处理：

- **用户同意取消**：说明已取消和原因，说明库存已释放
- **用户暂不取消**：尊重决定，不再劝
- **取消失败**：按错误原文说明（例如已有出库事实不能取消），给下一步建议

## 查询销售单进度

用户问「我的销售单到哪一步了」「审核了吗」「为什么还没发货」时，用 `query_sql_data` 查状态和出库进度，再按状态机解释。

查询口径：

- 销售单：`sales_order` 的 `status`、`expected_delivery_date`、`submitted_at`、`approved_at`、`locked_at`
- 明细进度：`sales_order_item` 的 `quantity`（订购量）、`locked_qty`（已锁定）、`outbound_qty`（已出库）
- 出库单：`outbound_bill` 中 `source_type = 'SALES_ORDER'` 且 `source_id` 等于销售单 ID，看 `status`
- 库存是否够用：`warehouse_stock` 的 `stock_qty` 减 `locked_qty`

销售单状态：

| 状态 | 含义 | 下一步 |
|---|---|---|
| DRAFT | 草稿，尚未提交 | 需要提交审核，提交时锁库存 |
| SUBMITTED | 已提交，等主管审核 | 审核通过后生成待确认出库单 |
| APPROVED | 已审核，已生成待确认出库单 | 等仓库确认出库 |
| PARTIAL_OUTBOUND | 部分出库 | 剩余数量仍在待出库 |
| OUTBOUND_DONE | 全部出库 | 流程结束，库存已扣减 |
| CANCELLED | 已取消 | 终态，不会再发货 |

出库单状态：

| 状态 | 含义 |
|---|---|
| DRAFT | 草稿，尚未提交确认 |
| PENDING_CONFIRM | 待仓库确认 |
| CONFIRMED | 已确认，库存已扣减 |
| CANCELLED | 已作废（销售单取消时联动） |

回答要求：

- 先说当前处于哪一步，再说卡在谁那里：等审核、等仓库确认、还是等发货
- 部分出库要给出已出库和剩余数量，不要只说「部分出库」
- 预计发货日已过但仍是待出库时，说明可能是仓库未确认或生产不足，并告诉用户可以查什么确认
- 只回答查到的状态，不推测「应该快发了」这类结论
- 单据不存在或查不到时如实说明，不要编造进度

## 失败后的循环

提交或修改失败时：

1. 说明失败原因，给一句可执行的修复建议
2. 等用户确认或给出新参数
3. 同意后调用编辑工具修改
4. 保存成功后，问是否重新提交
5. 不要自动重试同一份参数，也不要在用户没有反馈时连续调用

## 交付要求

- 草稿参数必须能被系统直接校验通过，不提交明显会被拒的内容
- 说清楚草稿和正式销售单的区别：草稿创建后仍需提交审核，提交才锁库存
- 影响结论必须来自实际数据，不能凭变化方向推测幅度
- 用户驳回后先回应原因，再给方案

## 常见误判

- 用客户名称或产品名称代替编号
- 用 C0001、WH000001、P001029 这类业务编码代替数字主键 ID 生成草稿
- 用户没给价格就自己编一个单价，或者单价留空
- 只算账面库存当可用库存，忽略已锁定数量
- 用户修改后只复述数字变化，不解释影响
- 系统拒绝后不改参数就重复提交
- 用户驳回后不看原因，按原方案再生成一次
- 创建成功后没说还需要提交审核
- 用户没同意就调用提交或取消
- 把「已提交」说成「已出库」

## 相关技能

- 交付风险和能否按期发货：`fulfillment`
- 客户退货、换货的单据操作：`return-order`
- 退货原因与趋势分析：`returns`
- 促销与价格口径：`promotion`
