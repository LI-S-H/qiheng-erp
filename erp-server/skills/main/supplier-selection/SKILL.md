# 供应商选择规划

## 什么时候用

- 这次向哪家买、有没有备选
- 某家供应商评分高，靠不靠谱
- 候选都不满足条件怎么办
- 现有供应商要不要换
- 这个品类该单一供应商还是多家

已经确定供应商、只算下单量时，调用 `purchase` 技能。

## 规划流程

### 第一步：确定采购定位

按"利润影响"和"供应风险"两个维度给品类定位，定位决定策略：

| 定位 | 特征 | 推荐策略 |
|---|---|---|
| 战略型 | 采购金额大、供应风险高、替代难 | 长期合作、双源或多源、联合改进 |
| 杠杆型 | 采购金额大、供应风险低、供应商多 | 竞价、集中采购、年度框架协议 |
| 瓶颈型 | 采购金额小、供应风险高、替代难 | 保证供应优先、开发替代供应商、适当备库 |
| 一般型 | 采购金额小、供应风险低 | 简化流程、自动补货、合并下单 |

用户没有明确品类定位时，先根据金额占比和候选供应商数量粗略判断，并说明判断依据。

### 第二步：确认硬条件

硬条件是"不满足就不能选"的约束，比如：

- 必须能供应该产品
- 资质、认证、账期要求
- 最低供货能力或最大供货上限
- 地域或交付区域限制

只有用户明确说"不满足就淘汰"的，才放进硬条件，其余都算偏好。

### 第三步：确认候选范围

- 在册且启用的供应商
- 供应商产品档案里有该产品记录的
- 近期有有效报价或历史成交的

候选为空时如实说明。战略型和瓶颈型品类候选不足时，提示需要开发新供应商，不能勉强从现有候选中选。

### 第四步：确认比较维度和权重

| 维度 | 看什么 | 来源 |
|---|---|---|
| 价格 | 本次报价或最近成交价 | 供应商产品档案 |
| 质量 | 质量评分，按 180 天合格与不合格金额计算 | 系统评分 |
| 交期 | 历史平均交期、当前是否逾期、本次承诺 | 交期字段和采购单 |
| 服务 | 服务评分和原因 | 人工维护 |
| 总成本（可选） | 采购价加运费、质量成本、延误成本 | 只有用户能提供成本参数时才计算 |

系统综合分权重固定为价格 30%、交付 30%、质量 30%、服务 10%，任一项缺失时综合分为未就绪。直接引用系统评分，不重新计算。

默认用系统综合分排序，这是现成的加权评分，不需要自己造。只有用户能提供运费、质量成本、缺货损失时，才额外核算总成本；参数不全时不估算，直接说明缺哪几项。

### 第五步：确认证据来源

- 评分是系统按规则算的，还是人工维护的
- 本次报价是否在有效期内
- 历史交期样本有多少
- 总成本里的运费、质量成本是否有可靠来源

证据不足时标注"未知"，不能当"满足"或"不满足"。

### 第六步：交办分析专家

候选超过一家，或需要算价格指数、交期稳定性、逾期率、质量趋势、供应集中度时，调用 `analyzeData` 交办，不要自己用 `query_sql_data` 取明细。

- goal：一句话写清产品和要回答的问题，例如"比较 P000227 的候选供应商，按价格、交期稳定性、质量趋势、供应集中度排序，给出主候选和替补"
- context：写明候选供应商 ID、硬条件、用户给的权重、采购定位、时间窗口
- 返回：每家准入状态、各维度指标、排序结果、主候选和替补、未知项

只有候选唯一、且不需要上述指标时，才可以直接引用系统评分作答，并在答复里说明未做多候选比较。

候选唯一但仍需判断单源风险时，goal 只要求核验报价有效期、历史交期与逾期率、质检记录、库存覆盖与在途，不要要求排序、双源分配和总成本。

### 第七步：解读

- 先说不满足的，为什么不满足
- 再说未知的，需要补什么证据
- 比较满足条件的候选：系统综合分、交期稳定性、价格指数、质量趋势分别列出来，按用户重视的维度说明排序依据
- 主候选和替补都要给；战略型品类建议给出双源分配比例
- 说明采购定位和对应策略，以及本次选择是否符合该策略
- 交期标准差大或质量趋势下降的供应商，即使综合分高也要提示风险

## 交付要求

- 每家供应商标明：满足硬条件、不满足、还是证据未知
- 说明采购定位和本次选择对应的策略
- 评分要说明来源；算了总成本才列构成，没算就说明缺什么参数
- 推荐必须说明依据的维度和证据
- 系统综合分可以直接引用；用户明确给了权重时按用户权重排序并写明；用户没给权重时不要自己编一套

## 常见误判

- 把"没查到"当成"不满足"
- 用供应商自述或销售话术提高评分
- 只比较单价，不看交期和质量评分
- 只推一个候选，没有替补
- 战略型品类只选一家，没有备份
- 用户没给权重时自己编一套权重

## 相关技能

- 候选确定后算下单量：`purchase`
- 需要先看采购缺口：`replenishment`
- 供应商绩效变化后复核策略：`inventory-policy`
